# v2.8.0 finish-HTTP-boundary lane — codex pre-merge review findings

Adversarial review (codex, read-only) over the branch reviewable diff (goldens +
already-reviewed plan docs excluded). Verdict: **needs-attention, 3 findings**.
Codex found **no `static_arg` whole-argument leak** for the Kotlin/Elixir/PHP/Rust
interpolation traps — the M2 silence core holds. All 3 findings are receiver/verb
*proof* gaps (M2 false-positives / mis-attested joins). Lead confirmed all 3 by
tracing the code.

## F1 (HIGH, conf 0.91) — axum emits routes for locally-known non-Router receivers
`axum.rs` `collect_router_receivers`/`receiver_is_poisoned`. A local var assigned
only from `AssignRoot::Other` (e.g. `let registry = build_registry();`) fails the
`router_ish` gate (line 407 `continue`), so it is never inserted into `states`;
`receiver_is_poisoned` then sees `None` and returns false → `registry.route("/x",
get(h))` emits a false `axum.route.v1`. In-file proof that the receiver is NOT a
Router is ignored; it is treated like an unknown parameter.
**Fix:** track locally-assigned-from-non-router names as a distinct SUPPRESSED
state and suppress `.route`/`.nest` on them. Keep permissive emit ONLY for truly
absent identifiers (function params / fields). Regression: local non-router var
`.route("/x", get(h))` in an axum-import file emits nothing.

## F2 (HIGH, conf 0.88) — reqwest builder facts fire on unproven `.get("/path")` receivers
`http_clients/rust.rs` `client_request_fact` field_expression arm. The builder arm
proves only the method name + that the URL is not `classify_url=="relative"`. A
`/`-rooted path classifies as `"path"`, so `store.delete("/cache/key")` /
`cache.get("/ns/key")` in any file containing `reqwest` emits a false
`http.client_request.v1`.
**Fix:** for the builder (field_expression) arm, require the receiver to be a
same-file-proven reqwest client (inline `reqwest::Client::new()`/`::builder()...`,
or a var assigned from one, or a typed `reqwest::Client` param). Else stay silent.
Keep the scoped `reqwest::get(...)` arm unchanged. Regression: `.get("/x")` on a
non-reqwest receiver in a reqwest file emits nothing; a proven client still emits.

## F3 (MEDIUM, conf 0.84) — actix `web::route().guard(guard::Get())` drops the attested verb
`actix.rs` `actix_method_router_verb`. The chain descends transparently through
`.guard(...)`/`.wrap(...)` to the base; `web::route()` → `VerbClass::Any` → verb
omitted, even when `.guard(guard::Get())` attests the method. A verb-less fact lets
a non-GET client join a GET-only handler.
**Fix:** parse standard method guards in the chain
(`guard::{Get,Post,Put,Patch,Delete,Head,Options,Trace,Connect}` + qualified) and
emit the attested verb; if a `web::route()` chain carries an unparsed method-like
guard, stay SILENT rather than emit any-method. Bare `web::route()` (no method
guard) keeps emitting verb-less (correct). Regression: guarded `web::route()`.

## Disposition
All 3 are release-blocking M2 correctness issues. One fix worker, TDD, then re-run
framework/client tests + registry conformance + golden + strict + branch gate.
