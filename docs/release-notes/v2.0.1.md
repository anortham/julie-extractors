# v2.0.1

This is a patch release for the v2.0.x standalone extraction product line.

## Fixes

- Fixed SQLite artifact writes for large real repositories that could fail with
  `db_write_failed` after generating more requested symbol IDs than SQLite would
  accept as host parameters in one prepared statement.
- Replaced the large dynamic symbol lookup `IN (...)` query with an in-memory
  same-batch lookup plus a temporary-table join for unresolved IDs.
- Fixed spooled scan artifact writes so large scans can write artifacts without
  holding all extracted files in memory.

## Performance And Profiling

- Added optional JSON report profiling with phase timings and per-language
  timing/count data.
- Pruned noisy pending relationship rows for unresolved external member calls in
  JavaScript, TypeScript, and Swift paths.
- Reused batch-scoped cached SQLite prepared statements on hot artifact-writer
  paths.
- Added a writer performance tripwire for repeated child-row writes.

## Contract Changes

- CLI commands, exit codes, SQLite schema version, JSONL schema version, and
  extract contract version are unchanged.
- JSON report schema remains version 1. The `profile` object is additive and
  optional.

## Known Performance Boundary

Cold scans of very large TypeScript-heavy repositories still spend substantial
time in extraction and SQLite row writes. The v2.0.1 release candidate removes
the correctness blocker and avoids obvious major regressions; deeper cold-scan
optimization remains follow-up work.
