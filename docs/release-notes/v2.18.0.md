# v2.18.0

This breaking producer release replaces inferred reference occurrence identity
with canonical producer-attested reference sites. It also adds parser-backed
marker facts for deterministic source audits.

## Canonical reference sites

- SQLite schema v5 adds `reference_sites` as the physical occurrence authority.
- Identifier, relationship, and pending evidence reference the canonical site
  that produced the assertion.
- Exact site IDs derive from `(file_id, start_byte, end_byte)` only when the
  producer attests the target token.
- Broad syntax nodes remain explicitly spanless and non-exact in the artifact.
- Resolved and unresolved assertions preserve distinct site, target, and
  canonical-kind combinations.
- Conflicting physical rows for one site ID fail instead of being merged.

## Typed producer evidence

- `Relationship.reference_site_is_exact` is a serde-defaulted typed field.
- `create_relationship_at_target` is the only direct relationship constructor
  that attests an exact target-token site.
- User metadata cannot forge exactness and no structural attestation marker is
  exported through relationship metadata.
- Canonical golden fixtures assert exactness for all relationship rows. The
  certified corpus contains 14 audited exact relationships and 210 explicit
  non-exact relationships.

## Closed capability gaps

- Capability-gap status is the closed vocabulary `open | exception`.
- The certified reference-resolution snapshot contains exactly 70 open gaps:
  36 tier-3 rows and 34 tier-2 rows.
- Unknown status values are rejected.

## Parser-backed marker facts

- Structural facts now cover parser-recognized marker comments across the
  supported language registry.
- Marker classification and source spans are emitted by `julie-extractors`;
  consumers do not reparse comments or infer marker locations.
- The structural-fact catalog remains the authority for marker pattern IDs and
  metadata.

## Contract versions

- Rust package versions are `2.18.0` for `julie-extract-artifact`,
  `julie-extract-cli`, and `julie-extractors`.
- SQLite schema version is 5.
- Extract contract version is 4.
- JSONL schema version is 4.
- These are breaking contracts. Version 4/3 aliases and version ranges are not
  provided.

## Consumer note

Consumers must rebuild artifacts with a 2.18-or-newer producer before reading
schema v5 reference evidence. Exactness must come from `reference_sites`; do not
reconstruct target-token identity from names, lines, overlap, or nearest-token
heuristics.
