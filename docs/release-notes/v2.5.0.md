# v2.5.0

This minor release hardens extraction against adversarially deep syntax trees,
adds per-file row attribution to JSON reports, and splits two large internal
Rust modules into clearer helper modules. It keeps the durable SQLite and JSONL
artifact contracts at version `3`.

## Features

- Successful `scan --json` reports now include a bounded
  `counts.file_rows` summary of the largest source files by attributed
  artifact rows, plus `counts.file_rows_truncated` when the scan report omits
  smaller files.
- `info --json` now includes the full persisted per-file row breakdown for
  every artifact file. Each entry includes the file path, language, status,
  total attributed rows, and exhaustive row-domain counts.
- `docs/contracts/cli.md` and `docs/contracts/reports.md` document per-file
  attribution as part of the report contract.

## Fixes

- Tree-sitter traversal is now depth-bounded through the shared traversal
  helpers and direct language-specific recursive walkers. Extremely deep source
  trees can no longer trigger Rust stack overflows in the covered extraction,
  identifier, relationship, structural-fact, source-region, and helper passes.
- Deep Rust and JavaScript regressions cover the stack-safety path for nested
  syntax trees.
- The remaining tree-walker audit now reports zero unguarded true child-
  recursive tree-sitter walkers.

## Internal Changes

- `crates/julie-extract-cli/src/commands.rs` was split so capability snapshot
  mapping, report shaping, and read-only artifact access live in focused
  internal modules. Command functions keep command dispatch and high-level
  scan/update/delete orchestration.
- `crates/julie-extract-artifact/src/writer.rs` was split so capability sync
  helpers and row-family insertion helpers live under `writer/`. The public
  `ArtifactWriter` API and transaction orchestration stay unchanged.
- Convention tests now fail if the extracted helper families drift back into
  the large orchestration files.

## Contract Changes

- Rust package versions change from `2.4.0` to `2.5.0`.
- SQLite schema version remains `3`.
- Artifact integer `extract_contract_version` remains `3`.
- JSONL schema version remains `3`.
- JSON report schema version remains `3`.
- `counts.file_rows` and `counts.file_rows_truncated` are additive JSON report
  fields. Existing report fields and row-domain keys remain present.
- Traversal beyond the internal safety depth budget is intentionally skipped to
  preserve process safety on pathological source trees.
- Parser dependency versions are unchanged.
