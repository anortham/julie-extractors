# julie-extract 2.40.3

Reader admission now recovers when an interrupted writer has committed store-log
progress but has not synchronized the coordinator's log watermark. Previously,
this crash window could refuse readers of every view in the family as
`stale_snapshot` until another writer reconciled the store.

Recovery advances an existing watermark monotonically from a validated durable
snapshot, in the same coordinator transaction as reader registration. Store
reads remain query-only. Writer and maintenance exclusions, root/manifest
validation, retention checks, and refusal of missing allocator metadata remain
in place.

No schema, extraction-identity, parser-output, or CLI-report change. Regression
tests cover committed lag, ahead watermarks, uncommitted writer rows, and refused
admission without partial coordinator changes.
