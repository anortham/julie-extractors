# v2.6.0

This minor release adds HTTP boundary structural facts: client-side request
facts and server-side handler/route facts that let downstream consumers (the
Miller bridge) trace `fetch`/axios call sites to the API routes that serve
them. It supersedes `v2.5.10`.

## New Fact Families

- `http.client_request.v1` (`javascript`, `jsx`, `typescript`, `tsx`, `vue`):
  global `fetch()` calls and import-gated axios calls whose first argument is
  a static string URL. Metadata: `client`, `framework`, `target_path`,
  `url_kind` (`path`/`relative`/`absolute`), `verb`, `verb_source`
  (`attested`/`default`), and `import_source` (axios only). Axios call sites
  are matched on the local import binding; generic type arguments
  (`axios.get<T>(...)`) are supported. In Vue SFCs the scan covers
  `<script>`/`<script setup>` sections only, with the axios import gate local
  to the declaring section.
- `nextjs.route_handler.v1` (`javascript`, `typescript`): one fact per
  exported HTTP-verb handler (`GET`/`POST`/`PUT`/`PATCH`/`DELETE`/`HEAD`/
  `OPTIONS`) in an App Router `route.{js,ts}` file, sharing the App Router
  segment walk with `nextjs.file_route.v1`. Auto-implemented `OPTIONS` is not
  emitted (not source-attested).
- `nuxt.server_route.v1` (`javascript`, `typescript`): one fact per Nitro
  server-route file under `server/api/**` (prefixed `/api`) or
  `server/routes/**`, gated on a `defineEventHandler`/`eventHandler`
  identifier or a method-suffix filename. Filename method suffixes attest the
  verb; suffix-less handlers omit `verb`. `server/middleware`, `server/plugins`,
  and `server/utils` are excluded.
- `aspnet.attribute_route.v1` (`csharp`): attribute-routed controller facts
  with `attribute_kind` of `controller_route`, `http_method`, or `route`,
  using tree-sitter attribution. `[controller]`/`[action]` substitutions are
  recorded in `route_tokens`; `effective_route_template` is the server-side
  join key, matching the minimal-API family. Non-literal attribute arguments
  stay silent; conventional (non-attribute) routing is out of scope.

## Improvements

- `htmx.attribute.v1` now also emits from JSX markup in `javascript`, `jsx`,
  and `tsx` sources and from Vue `<template>` sections, with the same fact
  shape as HTML. JSX brace-expression values and Vue dynamic bindings stay
  silent. Plain `typescript` is excluded because the TypeScript grammar cannot
  parse JSX.
- csharp capability matrix now advertises class-level annotations
  (evidence: attribute-routed controller fixtures).

## Contract Changes

- Rust package versions change from `2.5.10` to `2.6.0`.
- `EXTRACTION_CONTRACT_VERSION` gains the `http-boundary-facts-v1` marker
  (the dotted chain now ends `...web-route-facts-v3.http-boundary-facts-v1`).
- Verb policy for the new families: `verb_source="attested"` only when the
  verb is written in source (fetch/axios `method:` or verb method, route
  handler export name, Nitro filename suffix); `verb_source="default"` marks
  spec-default GET on client requests. ASP.NET attribute verbs are inherently
  attested and carry no `verb_source` key, matching the minimal-API family.
- Naming policy: client references carry `target_path`; frontend/file-route
  definitions carry `route_path`; ASP.NET families carry `route_template`/
  `effective_route_template` as the server-side join keys.
- SQLite schema version remains `3`.
- Artifact integer `extract_contract_version` remains `3`.
- JSONL schema version remains `3`.
- JSON report schema version remains `3`.
- Parser dependency versions are unchanged.

## Miller Handoff

A Miller-side companion plan should bridge `http.client_request.v1` call
sites to `nextjs.route_handler.v1`, `nuxt.server_route.v1`,
`aspnet.attribute_route.v1`, and `aspnet.minimal_api.route.v1` handlers via
`target_path` ↔ route-template matching, then bump `scripts/julie-pins.json`
to this release.
