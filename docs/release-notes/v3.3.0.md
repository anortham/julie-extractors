# julie-extract 3.3.0

classification: compatible

This release makes Qt C++ a first-class extraction family. A macro pre-pass
blanks Qt's macros before the parser reads a `.h` or `.cpp` file, so a Qt class
parses for the first time, and its properties, signals, slots, and QML metadata
become rows an agent can query. Four pre-existing C++ defects on the same
headers are fixed at the same time. Every change is declared in
[the extraction-output ledger](../contracts/extraction-output-changes.md) under
`3.3.0`.

## Added

- Every `Q_PROPERTY(...)` in a class or struct body is a `property` symbol row,
  named by the property, parented to its class, visibility public, with the
  whitespace-collapsed macro text as its signature. Its metadata carries
  `property_type`, and `read`, `write`, `notify`, `member`, `reset`, `bindable`,
  `constant`, `final`, and `required` when the macro names them.
- The same site emits one `cpp.qt_property.v1` structural fact, with
  `capture_name` `qt_property`, `node_kind` `macro`, `containing_symbol_id` set
  to the enclosing class, and the same metadata keys.
- A method in a `signals:` or `Q_SIGNALS:` section, or prefixed by `Q_SIGNAL`,
  is an `event` row with public visibility.
- `symbols.metadata_json` gains `qt_slot` for a method in a slots section or
  prefixed by `Q_SLOT`, and `qt_invokable` for a method prefixed by
  `Q_INVOKABLE`.
- A class or struct gains `qt_object`, `qt_gadget`, `qml_element`,
  `qml_singleton`, `qml_anonymous`, `qml_uncreatable`, and `qml_attached` from
  the matching macros.
- A new golden fixture, `fixtures/extraction/cpp/qt_header`, and a new language
  record, [`docs/languages/cpp-qt.md`](../languages/cpp-qt.md).

## Changed

- Qt's C++ macros are blanked to same-length spaces before the parse, on the
  scan path, on the `julie-extract check` path, and in the `.h` header probe.
  Every byte position and every newline is preserved, and the original text
  stays the source of record. A Qt header no longer reports a syntax error for
  its macros: parse diagnostics fall from 981 to 31 on Kirigami and from 4,627
  to 298 on plasma-workspace.
- A row named `Q_PROPERTY`, or after another Qt macro, is gone: 294 such rows on
  Kirigami and 786 on plasma-workspace fall to 0. An empty-name row for a
  section label is gone: 5 and 28 fall to 0.
- A forward declaration such as `class ColumnView;` emits no `class` row,
  because it names no new type: 57 one-line `class X` rows on Kirigami and 653
  on plasma-workspace fall to 0.
- A declared constructor or destructor emits one row instead of two: 43
  duplicate rows on Kirigami and 493 on plasma-workspace fall to 0.
- A constructor or destructor row carries the visibility of its access section.
  Both were hardcoded `public` before. A destructor signature no longer ends
  in `;`.
- A method declared in a class keeps its whole declared return type, with the
  `const` qualifier, one `*`, `&`, or `&&` per pointer or reference wrapper,
  template arguments, and namespace qualifiers. A declaration carried no return
  type at all before.
- `override` and `final` are trailing specifiers, written after the parameters
  and the `const` qualifier, never leading modifiers.
- A modifier no longer leaks from a sibling member. A false leading `override`
  is gone from 412 signatures on Kirigami and 2,365 on plasma-workspace; no
  signature starts with `override ` on either corpus now.
- The `cpp` capability row adds `event` and `property` to its symbol kinds and
  body-span exclusions, and `cpp.qt_property.v1` to its structural facts. The
  `cpp`/`qt_header` fixture row is new.
- `EXTRACTION_CONTRACT_VERSION` gains the suffix `qt-cpp-v1`.

## Compatibility

- SQLite artifact schema remains 7 and report schema remains 3. The extraction
  identity epoch remains 10: the contract version is what consumers observe, and
  no symbol id of an unchanged non-Qt file moves.
- Every column keeps its type, so a reader built for 3.2.0 still parses the
  output. Only the `cpp` row content moves.
- A consumer that already holds an artifact must rebuild it rather than rescan,
  because an unchanged file keeps its stored rows.
- A consumer that renders C++ skeletons or searches C++ symbols must accept
  `event` and `property` as cpp symbol kinds. A Qt signal no longer answers a
  `method` query.
- A consumer that read a Qt property from a symbol named `Q_PROPERTY` must read
  the `property` rows or the `cpp.qt_property.v1` facts.
- A consumer that resolved a type from a forward-declaration `class` row, or
  held a stored id for one of the removed rows, must rebuild.
- A consumer that assumed a C++ member signature starts with its name must match
  a return type at the head of the signature instead.
- The new metadata keys are optional. A row without them keeps its old meaning.
