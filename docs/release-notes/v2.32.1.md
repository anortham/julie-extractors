# julie-extract v2.32.1 candidate

Local patch-release candidate that hardens long family-store writes and removes measured work from imports,
scope selection, and exact resolution publication. It has not been published.

## Store lifecycle reliability

Long from-artifact imports now renew the writer lease while their indivisible import quantum is running. The
coordinator keeps the existing lease and fencing rules; other operation kinds do not gain a renewable long
quantum.

Byte-identical imports with a new idempotency key now reuse the validated current manifest before file-version
materialization. Changed input, incomplete prior requests, and changed current state still take the normal path.

## Resolution work

Resolution scope crossover is decided before expensive execution. When the dependency-closed scoped worklist is
too close to full, the resolver selects the full path directly instead of first paying scoped setup costs.

Exact resolution publication now reuses one prepared identifier insert statement behind the unchanged streaming
writer API. A 100,000-row regression improved from 3.415 seconds to 1.715 seconds. On the faithful Miller replay,
identifier-row publication fell from 14.304 to 7.547 seconds and end-to-end resolution improved from 49.98 to
43.10 seconds.

## Compatibility

The versioned store remains schema v2 and format epoch 1. Manifests, resolution bases, the standalone v3 artifact,
resolver-output epoch, crash boundaries, publication identity, and CLI report contracts are unchanged.

## Verification

The faithful replay preserved canonical digest, 392,526 identifiers, 10,804 pending rows, 1,538 source versions,
integrity, and publication identity. Coordinator/import, scope-selection, exact-writer, crash-recovery, formatting,
strict Clippy, workspace-check, and release-preflight gates cover the integrated candidate.
