# julie-extract v2.39.0

classification: compatible

This release lands both waves of the receiver-type facts contract. Every
general-purpose language now emits the three fact shapes that Miller's
receiver-typed call resolution (policy v6, Tier 3) reads: parameter symbols,
declared-type facts for locals, parameters, and fields, and `receiver_type`
metadata on self-style call sites. It also adds the `RAZORBACK` marker token
and advances the extraction identity epoch to 9. Every claim is backed by
golden fixture evidence in `fixtures/extraction/`, the strict data-quality
gate reports `silent_cells: 0` and `quality_bar_debts: 0`, and the two
evidence scans record the per-language counts.

## Receiver-type facts, wave 1

Languages: csharp, typescript, javascript, python, rust, go, and java.
Contract: `docs/decisions/2026-09-01-receiver-type-facts.md`; evidence:
`docs/findings/2026-09-01-receiver-type-facts-evidence.md`.

- Parameter symbols (kind `variable`, metadata `role: "parameter"`) with
  declared-type facts. C# implicit lambda parameters get names so they emit
  parameter symbols too.
- Declared-type `type_facts` rows for locals, parameters, fields, and C#
  callable return types, reduced to base type names with the shared
  `strip_type_decorations` helper.
- `receiver_type` call-site metadata for `this`, `base`, and `super`
  receivers in csharp, typescript, and javascript.
- Legacy inference values that can never verbatim-match a type symbol
  (whitespace, commas, dangling `<` or `>`) are dropped from the `types`
  map, and the TypeScript `unique symbol` annotation records nothing.
  Sixty-six junk rows leave the goldens across seventeen fixture groups.

## Marker facts

`code.marker.v1` recognizes `RAZORBACK` debt comments alongside `TODO`,
`FIXME`, `HACK`, and `XXX`. `EXTRACTION_CONTRACT_VERSION` gains
`marker-razorback-v1` so stores re-extract marker facts.

## Receiver-type facts, wave 2

Languages: kotlin, swift, dart, gdscript, scala, c, cpp, zig, vbnet,
powershell, fsharp, qml, php, ruby, lua, r, elixir, erlang, bash, and razor.
Wave-1 languages gain the refinements the wave-1 spec deferred: python locals
parent to the enclosing callable, go `:=` results from same-file constructors,
java bindings (try-with-resources, enhanced-for, catch, lambda, `instanceof`,
record components), csharp indexer return types, and `receiver_type` for
python, rust, go, and java.

- Parameter symbols: kind `variable`, metadata `role: "parameter"`,
  `parent_id` = the enclosing callable, span = the parameter node. Bash
  records its positional parameters (`$1`, `$2`) the same way.
- Declared-type facts: `resolved_type` is always the base type name. Generic
  argument lists, nullable suffixes, by-ref, pointer, and borrow sigils, and
  language type-keyword prefixes are stripped. Array suffixes and namespace
  qualifiers stay. When the declared text differs, the full text lands in
  `metadata.declared`. A type with no single base name (tuples, function
  types, unions, multi-word C sized types) records nothing.
- Inferred facts: an initializer records `is_inferred = true` only for a
  constructor-shaped call or literal that names a class-like symbol declared
  in the same file (`Foo(...)`, `Foo.new(...)`, `new Foo()`, `Foo{...}`,
  `#foo{...}`, `[Foo]::new()`, `New Foo(...)`, `Foo$new()`). Unknown,
  imported, and namespace-qualified names record nothing. Elixir `%Foo{}`
  records without the same-file check because the compiler already rejects
  an unknown struct.
- `receiver_type` lands on both the call identifier row and the structured
  pending relationship row when the receiver is the language's self reference
  (`this`, `self`, `super`, `Me`, `MyBase`, `$this`, `self::`, `static::`,
  `parent::`) or the enclosing method's own receiver parameter (go, zig,
  lua, fsharp, r). The value is the enclosing type's base name; `super`-style
  receivers name the declared base type. Razor records it on identifiers
  only. C, elixir, erlang, and bash have no receiver concept and record
  nothing.
- Kind changes: function-local `val`, `let`, `const`, and `final`
  declarations are kind `variable` in kotlin, swift, gdscript, scala, zig,
  dart, and ruby; class-level rows keep their kind. Kotlin and scala primary
  constructor parameters are `property` rows under the class. Ruby `@x` and
  `@@x` are kind `field`. Razor `@code` fields are kind `field`. PowerShell
  class constructors are kind `constructor`.
- Dart callable symbols now span the whole declaration instead of the
  signature, so identifiers inside a method body are contained by the
  method. R6 and RefClass members span their own `name = value` argument
  instead of the whole class call.
- Legacy type inference in every wave-2 language now records only base type
  names or nothing. Function types, slices, tuples, and keyword text such as
  `final`, `var`, `async`, and `inferred` no longer reach the `types` table.
- Lua and R now claim the `types` capability. Their facts come from same-file
  constructor shapes; neither language states declared types.

## Capability claims

Nineteen `open_gaps` entries that named the wave-2 plan are closed and their
anchored kinds are `supported`: c `variable`, cpp `variable`, zig `constant`,
python `variable`, vbnet `variable`, php `constant`, ruby `field`, swift
`variable`, kotlin `variable`, dart `variable`, elixir `variable`, fsharp
`type`, erlang `variable`, lua `variable`, r `class`, bash `constant`,
powershell `constructor`, gdscript `variable`, razor `field`. Scala claims
`variable`, `property`, `function`, and `constructor` on golden evidence.
Every language whose goldens emit parameter rows claims `variable`.

## Compatibility

Artifacts stay schema 7, JSONL stays contract v5, family stores stay store
schema 2, store format epoch stays 1, and the report schema stays 3. The
extraction identity epoch advances from 8 to 9, so family-store import
writes fresh epoch-9 file versions for unchanged files instead of reusing
the epoch-8 rows that predate these facts. Epoch-8 rows stay immutable.

`EXTRACTION_CONTRACT_VERSION` gains the suffixes `marker-razorback-v1`,
`receiver-type-facts-v1`, and `receiver-type-facts-v2`. A consumer that pins
the contract version re-extracts to pick up the new rows. An existing
artifact keeps working unchanged until it is re-extracted.

No table, column, or JSONL field is added, removed, or renamed. Row counts
and some row values change for the affected languages: new `variable`
symbols for parameters and locals, new `type_facts` rows, `receiver_type`
keys in identifier and pending-relationship metadata, and the kind changes
listed above.
