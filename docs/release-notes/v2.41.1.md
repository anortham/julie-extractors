# julie-extract 2.41.1

classification: compatible

This release improves the facts agents use for type navigation, web-route
tracing, template analysis, and exact Java test selection.

## Return-type identifiers

- Named return types emit one exact `type_usage` identifier in all 25 languages
  with native return-type syntax.
- C# and Razor cover bare, nullable, array, generic, and qualified return forms
  without duplicate rows.
- Elixir and Erlang use native type specifications; SQL covers named scalar
  PostgreSQL `RETURNS` types.
- The remaining 15 supported languages have no native return-type position and
  are recorded explicitly as not applicable.

## Web and template facts

- ASP.NET minimal API facts cover `MapHead`, `MapOptions`, and literal
  `MapMethods` verb lists, with route-group and handler metadata.
- htmx facts preserve complete JSX template expressions, consumed component
  attributes, normalized route templates, and explicit uncertainty when a
  value cannot be resolved safely.
- Razor emits the same minimal API route and route-group patterns as C# where
  its embedded C# syntax proves them.

## Java package identity

- Single-segment packages such as `package sample;` now emit the same Namespace
  fact as dotted package declarations, enabling exact native Java test IDs.

## Compatibility and rollout

- Artifact schema remains 7, JSONL export contract remains v5, report schema
  remains 3, and family-store schema remains 2.
- Extraction identity epoch advances from 9 to 10. Existing source files are
  re-extracted so the new facts appear even when their content is unchanged.
- Existing artifacts remain readable; consumers should replace the binary and
  refresh their index. Prior family-store file versions must not be deleted.
- Existing families preserve their stored reader floor. A family created by
  2.41.1 stamps `min_reader_version = 2.41.1`, so consumers must advertise
  2.41.1 reader capability when adopting this binary.
