# julie-extract 2.41.0

classification: compatible

This release introduces an optional in-process Rust syntax API and exports relationship fact types at the crate root. Extraction output, schemas, and CLI contracts remain completely unchanged.

## Rust Syntax API (`syntax-api`)

The optional, default-off `syntax-api` Cargo feature exposes structured syntax parsing for in-process consumers:
- `julie_extractors::syntax::parse_source` and `parse_source_with_options` return `ParsedSource { language, tree, diagnostics }` or typed `SyntaxError`.
- Grammar selection is shared with canonical extraction, covering all 40 supported languages, F# signature files (`.fsi`), extensionless `qmldir`, and case-insensitive extensions.
- C/C++ header detection probes both grammars, reuses the winning tree with zero third parse, and enforces bounded cancellation checks during whitespace and tie-breaking.
- Iterative AST cursor diagnostics (`tree.walk()`) inspect `ERROR` and `MISSING` nodes with depth pruning, avoiding stack exhaustion.
- Cooperative cancellation and deadlines are supported via tree-sitter parse progress callbacks and periodic traversal checks.
- Composite files provide host markup/template trees only; `.jsonl` files are rejected as unsupported containers.
- Zero new dependencies added to the crate.

## Relationship Fact Exports

- `PendingSpan` and `UnresolvedTarget` are exported at the root of `julie_extractors` (`julie_extractors::{PendingSpan, UnresolvedTarget}`) while keeping internal modules private.

## Compatibility and Rollout

- Artifact schema remains 7.
- JSONL export contract remains v5.
- Extraction identity epoch remains 9.
- SQLite/JSONL fact table outputs and CLI behavior remain 100% byte-identical.
- Primary CLI and artifact interfaces remain unchanged.
