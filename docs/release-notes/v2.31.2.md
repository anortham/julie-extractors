# julie-extract v2.31.2

Patch release for family-store physical maintenance, capacity safety, and
cross-version correctness.

## Physical maintenance and retention

Store maintenance now measures physical bytes across the store database, WAL,
resolution bases, and scratch data. Garbage collection drives incremental
vacuum in bounded steps until the freelist is empty or the configured budget is
spent, and reports the before/after byte and page measurements. Retention
pressure now considers physical bytes as well as logical retained rows, records
the physical breach streak, and surfaces when compaction is still required.

## Capacity and rollback safety

Store imports, updates, and artifact imports perform a filesystem-capacity
preflight before creating or mutating the family store. Artifact imports also
validate the source artifact's schema, root, file identity, capability
identity, and resolution completeness before store creation, failing closed
without mutating the store when the source is malformed or incompatible.

## Parity and compatibility

The store equivalence, mixed-version, maintenance, crash, and resolution
contracts now cover the physical-maintenance and rollback paths, including the
full supported 38-language fixture matrix. Existing legacy artifacts and
standalone extraction behavior remain compatible; the changes are confined to
family-store maintenance, admission, and import validation.

## Verification

The Rust 1.95 formatting, default, contract, release preflight, and package
manifest gates are required for this candidate. Contract verification covers
the maintenance, crash, generation, equivalence, mixed-version, resolution,
and all-language parity suites.

This file describes the local v2.31.2 release candidate. The current published
release remains v2.31.1 until the four target packages are published and
verified.
