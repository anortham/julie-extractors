# julie-extract 3.12.1

classification: compatible

Patch release pins a `tree-sitter-razor` fix for Razor comments.

## Fixed

- A `@* … *@` comment first in an `@if`, `else`, or `@foreach` block, first in
  an element, or first in a `@code` block no longer turns the whole Razor file
  into one parse error. With 3.12.0 such a file kept only its component class
  and directives, so downstream code-kb reported every `@code` member as
  removed in an edit check ([julie-extractors #29](https://github.com/anortham/julie-extractors/issues/29)).
- A comment above the directives no longer ends the directive section;
  `@page`, `@inherits`, and `@inject` after it stay directives.

## Unchanged

- A block that holds only a comment, or nothing (`@if (x) { }`), is still one
  parse error, as in 3.12.0.
- A templated Razor delegate inside a C# expression (`… ? @<span>…</span> : …`)
  still parses with a local error around the template.

## Compatibility

- SQLite schema remains 8, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `razor-comment-extras-v1`.
- Refresh a 3.12.0 schema 8 artifact with `julie-extract scan --root <project>
  --db <artifact.db> --force` before incremental use with 3.12.1.
