# julie-extract 3.9.0

classification: breaking for readers of `identifiers.reference_site_id`

Minor release with a `references` extraction level, a smaller artifact at that
level, and new facts for JavaScript properties and C# calls and conditional
code. `docs/contracts/extraction-output-changes.md` lists every rule.

## Added

- `--level references`: `facts` plus every call and variable-reference
  identifier with its call metadata, identical to `full` for those rows. It
  leaves out type-argument usages, source regions, complexity metrics, and
  symbol annotations.
- JavaScript: `obj.name = <value that is not a function>` writes a `property`
  symbol (`className`, `isAssignedProperty`), once per `obj.name` in a file.
- C#: call identifiers get `arg_types`, the type each argument states, at the
  `references` and `full` levels.
- C#: a symbol in the kept branch of an `#if` group gets `preprocessorIf`, the
  condition of that branch.

## Changed

- SQLite schema 8: `identifiers.reference_site_id` may be null. At the
  `references` level, an identifier whose site no relationship or pending
  relationship shares has a null site and no `reference_sites` row. `full` and
  `facts` write the same rows as before.

## Compatibility

- SQLite schema is 8, report schema remains 3, and extraction identity epoch
  remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `javascript-assigned-properties-v1`, `csharp-argument-types-v1`, and
  `csharp-preprocessor-conditions-v1`.
- A write into a schema 7 artifact reports `schema_migration_required`.
  Refresh it with `julie-extract scan --root <dir> --db <path> --force`.
