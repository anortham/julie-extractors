# julie-extract v2.33.5

v2.33.5 is a compatible incremental-resolution patch. Public CLI, report, schema, and store
contract surfaces stay the same.

## One-file resolve stays scoped

A store resolve whose journal records one changed file no longer promotes to a full-corpus
pass when common names collide. The previous crossover rule treated identifier share ≥ 0.7
as a whole-tree resolve. One C# save that mentioned `path`, `name`, or `String` paid that
price every time.

## Private locals are not resolve keys

`touched_names` now omits `kind=import` and private variables (`kind=variable` with
visibility `private` or unset). C# locals such as `path`, `name`, `i`, `ex`, and `root` no
longer select hundreds of files. Public JS and Python module exports still count.

## Crossover compact actually runs

A Full+Crossover decision now carries `rebase_after_exact` into the resolve pipeline. The
planner already set the flag; the session used to hard-code `false`, so the overlay never
compacted after a crossover pass.

## Upgrade note

Existing views may run one full resolve after upgrade. Old journal batches include private
locals in `touched_names`, so re-validation can fail closed once (`JournalInvalid`). The
next incremental save then writes a filtered journal and stays scoped.

## Compatibility

No public CLI, report, schema, or store contract version changes. Existing store files,
resolution publication, fencing, crash-recovery, and package integration points remain
compatible with v2.33.4.

## Verification

The candidate passed the store-delta-scope contract (15 tests), the new Full-arm rebase
telemetry check, the scope-journal name-filter contract, formatting, and whitespace
checks. Live Miller dogfood on this workspace: one C# save stayed scoped at 14 files
(was 459 files / 226 s). After compact, the following save stayed in that 14-file band.
