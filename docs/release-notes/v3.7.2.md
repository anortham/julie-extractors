# julie-extract 3.7.2

classification: compatible

Patch release for Windows path handling and artifact identity checks. Extraction
rules and parser dependencies are unchanged from 3.7.1.

## Fixed

- Canonical Windows paths no longer retain the verbatim `\\?\` prefix in
  artifact metadata and reports. Prefix removal preserves native UTF-16 path
  units, including unpaired surrogates, when accessing files.
- Incremental commands recognize equivalent source roots by file identity.
  Committing scan, update, and delete operations repair an older root spelling
  while preserving the artifact ID. A no-change scan leaves metadata untouched;
  an explicit rebind repairs the spelling and assigns a new artifact ID.
- Writes prepared before a concurrent rebind fail with `artifact_changed`, exit
  code `1`, instead of overwriting the rebound root and artifact ID. Retry the
  command against the artifact's current root.
- Force scans for a different root replace facts and metadata in one SQLite
  transaction, preserving the database file identity. A failed artifact write
  keeps the original artifact.
- Discovery reuses artifact and SQLite sidecar identity handles during each
  walk and closes them before writes. Unix file identity and size checks also
  reuse candidate metadata. This avoids repeated handle and metadata reads
  when source filenames match the artifact name.
- Index-level conflict reports use the documented `requested_index_level`
  detail key.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. Extraction contract markers and fact-table output are
  unchanged.
- Existing readers remain compatible. Incremental commands require the same
  producer version; refresh a 3.7.1 artifact with
  `julie-extract scan --root <dir> --db <path> --force` before incremental use
  with 3.7.2.
- `artifact_changed` also applies to scan, update, and delete when a rebind
  changes the artifact ID while a write is being prepared. These reports carry
  `expected_artifact_id` and `found_artifact_id` and are recoverable.
