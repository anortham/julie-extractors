# julie-extract v2.33.1

- **Audience:** Every Windows user. Unix is unaffected.
- **Release shape:** One repair, and the CI gate that should have caught it.
- **Upgrade urgency:** High for Windows. Scoped store resolution has been broken since `v2.32.0`.

## The defect

On Windows, every scoped (delta) store resolution failed with:

```
store resolution SQLite error: invalid uri authority: %3F
```

A view could never reach `exact`. It stayed at `converging` forever.

### Why

`StoreLayout` canonicalizes every path it hands out (`layout.rs:54`, `:133`). On Windows,
`std::fs::canonicalize` always returns the verbatim spelling `\\?\C:\...`, even for a short path. The
prefix is not a long-path symptom; it is unconditional.

`sqlite_read_only_uri` then replaced backslashes with forward slashes **before** removing that
prefix, so `\\?\` became `//?/`. The leading `//` makes SQLite look for a URI authority, and `?` was
absent from the helper's safe-byte set, so it was percent-encoded. The result:

```
file://%3F/C:/Users/<user>/.miller/stores/<family>/gen-001/store.db?mode=ro
```

SQLite reads the text between `file://` and the next `/` as the authority, finds `%3F`, and refuses.

`materialize_prior_overlay` attaches the prior store and the prior base through that helper, and
`finish_exact_inner` calls it first, so no scoped resolve could reach an exact base.

### Why it looked partial rather than total

Full resolves clear `prior_scope_state` and skip the overlay entirely. So an affected store kept
serving data at `level=full` and never became exact. Reads worked; convergence did not. On one
dogfooding machine, 27 of 48 resolve requests failed while imports, updates, and deletes all
succeeded.

## The fix

`sqlite_read_only_uri` now strips the verbatim prefix — including the `\\?\UNC\` form — before the
separator swap, and emits an explicitly empty authority so a UNC host name cannot become one either.

A drive path yields `file:///C:/...`, and a UNC path yields an empty-authority form. Both attach.

## Why CI stayed green for two days

The tests were never wrong. **7 of the 24 tests in `store_resolution_contract` fail against the
pre-fix code**, and all 24 pass with it. The suite simply never ran on Windows: it is gated behind
the `test-store-resolution-contract` feature, and the Windows CI job ran only `capacity_tests` and a
single import test.

The one unit test that does cover the helper builds its fixture with `tempfile::tempdir().join()`,
which is never canonicalized, so it never saw the prefix that production always has.

Two changes close this:

- A new unit test, `prior_overlay_attach_uris_survive_a_canonicalized_store_path`, canonicalizes its
  fixture first — which is what `StoreLayout` does.
- The Windows CI job now runs the full resolution contract suite. It costs about 70 seconds.

## Verification

Verified against a real wedged store, not only in tests. `store resolve --json` returned
`state=committed`, `resolution.state=exact`, `resolution_mode=scoped`, `failure_class=none`. The
consuming Miller instance then completed a whole-repo scan and swap after five consecutive failures,
and its `inspect`, `trace`, and `impact` tools recovered.

- `cargo test -p julie-extract-cli --lib`: 182 passed. Two failures are pre-existing and unrelated,
  confirmed by re-running them at the parent commit: a path-separator assertion in `reports.rs` and a
  `PermissionDenied` in `spool.rs:678`. Both remain open.
- `cargo test -p julie-extract-cli --features test-store-resolution-contract --test store_resolution_contract`:
  24 passed on Windows.
- `cargo clippy --all-features --no-deps -- -D warnings`: clean.

## If you cannot upgrade immediately

Set `JULIE_STORE_RESOLUTION_DELTA=off` in the consuming process. That forces the full path, which
clears `prior_scope_state` and skips the broken attach. The value must be exactly `off`. The cost is
a full resolution every time.
