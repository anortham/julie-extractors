# julie-extract 3.4.0

classification: compatible

This release closes the gaps that the
[2026-09-22 language gap audit](../findings/2026-09-22-language-gap-audit.md)
found across all 40 languages. Wave 1 closed the 347 high-rated gaps. Wave 2
closed 673 medium and low gaps and 22 recorded `open_gaps` entries, so the
capability ledger's open-gap backlog fell from 43 to 25. Every row change is
declared in [the extraction-output ledger](../contracts/extraction-output-changes.md)
under `3.4.0`, and the per-language detail is in `docs/languages/*.md`.

## Added

- File selection. `.bats` files, shell startup files, and extensionless files
  with a `sh`, `bash`, or `bats` shebang are `bash`. Ruby build files
  (`Gemfile`, `Rakefile`, `.gemspec`, and more), JSON variants (`.ndjson`,
  `.jsonld`, `.geojson`, `.webmanifest`, `.code-workspace`), XML project and
  markup files (`.vcxproj`, `.proj`, `.xaml`, `.xslt`, `.xliff`, and more),
  `.sbt`, `.escript`, `.regexp`, `Pipfile`, an R `NAMESPACE`, and Erlang
  `rebar.config`, `sys.config`, and `*.app.src` files now extract. A `.config`
  file whose first non-blank text is `<` is `xml`.
- Embedded blocks. HTML `<script>` and `<style>` elements and Vue script and
  style sections run the native JavaScript, TypeScript, TSX, JSX, or CSS
  pipeline, with every row family remapped to host coordinates.
- Capability flags. `razor`, `css`, `toml`, `yaml`, `xml`, and `markdown`
  publish `pending_relationships`, and `xml` publishes `relationships`.
- Structural facts. 113 new pattern ids, among them routes for Angular,
  ASP.NET conventional routing, chi, Fiber, gorilla/mux, Koa, hapi, JAX-RS,
  http4s, Akka HTTP, Rocket, Vapor, Giraffe, Cowboy, httpz, DRF, and Plumber;
  EF Core, Spring XML, MyBatis, Android manifest, Docker Compose, Kubernetes,
  Ansible, SwiftPM, Zig build, Godot, Neovim, Shiny, and Tailwind facts.
  `docs/contracts/structural-fact-patterns.json` lists every id.
- Symbols, relationships, identifiers, type facts, doc comments, and test
  roles that the audit found missing, in every language family.

## Changed

- Many spans change, and a changed span changes the location-derived symbol
  id. False and duplicate rows are gone, for example duplicate JavaScript
  function values, PowerShell phantom functions, Lua call-argument table
  fields, and JavaScript data object literal properties.
- TypeScript and JavaScript emit one export row per exported name, and export
  rows no longer parent declarations.
- HTML drops the synthetic `url:`, `resource:`, `endpoint:`, and `script:`
  relationships. Links, scripts, anchors, embeds, and form actions are
  structured pending rows.
- C# blanks preprocessor directive lines and every `#elif`/`#else` branch
  before the parse. Only the first branch of an `#if` group yields rows, and
  the parse errors that directives inside a statement caused are gone
  (Newtonsoft.Json: 857 diagnostics fall to 5).
- Receivers. A `.` on the previous line never names a receiver, a leading `@`
  is part of a receiver only in Ruby and C#, and `->` is a member separator
  only in C, C++, and PHP.
- Scan time. On the 13 comparison repositories, zod and radzen-blazor scan
  faster than 3.3.1 and Newtonsoft.Json takes the same time. Repositories that
  gain many rows take longer: Alamofire writes about 194,000 more rows and
  takes about 15% longer.
- `EXTRACTION_CONTRACT_VERSION` gains the suffix `language-gap-closure-v1`.

## Compatibility

- SQLite artifact schema remains 7, report schema remains 3, and the
  extraction identity epoch remains 10. No column is added, removed, or
  retyped.
- Replace the binary and rebuild every artifact. An unchanged file keeps its
  stored rows on a rescan, so a rescan alone does not apply the new output.
- Do not carry symbol ids across the rebuild.
- A consumer that pinned the previous `EXTRACTION_CONTRACT_VERSION` must
  accept the new suffix.
- A consumer that read HTML links from the synthetic relationships must read
  the structured pending rows.
- A consumer that relied on export rows as the parent of exported
  TypeScript or JavaScript declarations must use the declaration rows.

## Open gaps

25 `open_gaps` entries stay recorded in `fixtures/extraction/capabilities.json`,
each with a reason, a required closure, and a planned closure task. Among them:
a test role for SpecFlow and Behat step definitions, a `go.mod`/`go.sum`
language entry, JSON5 files, and regex conditionals, which the pinned
tree-sitter-regex grammar cannot parse.

## Evidence

- Linux: `cargo fmt --check`, workspace Clippy with `-D warnings`,
  `scripts/check-agent-doc-sync.sh`, `cargo test -p xtask`, and the golden,
  capability, default, and contract tiers pass, as does the
  `reference_site_identity` heavy contract test.
- Strict language report: `silent_cells=0`, `quality_bar_debts=0`,
  `open_gap_backlog=25`.
- Windows: the default tier passes (5,064 extractor tests, 7 ignored).
- `cargo xtask compat-check` against the published 3.3.1 binary accepts the
  `3.4.0` compatible ledger entry.
- A two-pass external review (general and security) of the whole branch found
  two defects, both fixed before release: a C# minimal-API route that panicked
  on non-ASCII text, and embedded structural facts that could share an id.
- Real-repository scans of 13 repositories with 3.3.1 and 3.4.0 exit 0 with no
  failed files. See
  [wave 1](../evidence/2026-09-22-language-gap-wave1-real-world.md) and
  [wave 2](../evidence/2026-09-23-language-gap-wave2-real-world.md).
