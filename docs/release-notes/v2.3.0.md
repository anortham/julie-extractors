# v2.3.0

This minor release is a broad language data-quality release. It raises
`julie-extractors` from coarse "supported" language claims to fixture-backed,
per-domain extraction evidence across the full supported language matrix while
keeping the v3 artifact contract shape unchanged.

## Features

- Adds an applicability-aware language quality scorecard with strict gating for
  silent capability cells and quality-bar debt.
- Extends `kind_coverage` to cover annotations, doc comments, literals, and
  source regions alongside symbols, relationships, identifiers, body spans,
  structural facts, and complexity metrics.
- Deepens structural fact extraction across code, data, markup, query, and
  domain-specific languages, including high-value semantic facts for JSON,
  YAML, TOML, Markdown, CSS, SQL, Regex, Vue, Razor, Bash, PowerShell, Ruby,
  Elixir, Lua, QML, R, GDScript, Swift, Scala, Kotlin, Dart, Java, and Zig.
- Broadens complexity metric coverage for supported code languages and embedded
  web regions.
- Expands fixture-backed evidence for annotations, doc comments, literals,
  source regions, body spans, relationships, pending relationships, types, and
  type argument usages.
- Adds language-focused tests and golden fixture coverage so agents can improve
  one language at a time without weakening the global quality bar.

## Fixes

- Fixes language-specific extraction defects found while closing applicability
  gaps, including stronger Ruby relationships and QML type evidence.
- Normalizes Vue single-file component spans to end on real source lines while
  preserving fixture attachment behavior.
- Deduplicates shared span helper logic used by base, SQL, and Regex complexity
  metrics.
- Consolidates duplicate CLI `kind_coverage` JSON serialization so
  `languages --json` and artifact capability snapshots stay aligned.

## Contract Changes

- Rust package versions change from `2.2.1` to `2.3.0`.
- SQLite schema version remains `3`.
- Artifact integer `extract_contract_version` remains `3`.
- JSONL schema version remains `3`.
- JSON report schema version remains `3`.
- The `kind_coverage` JSON object remains the capability-depth contract and now
  carries ten explicit domains.
- Parser dependency versions are unchanged.
