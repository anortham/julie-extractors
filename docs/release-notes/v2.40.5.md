# julie-extract 2.40.5

Consumer cursor advance and release no longer load historical manifests or compute a
whole-store garbage-collection plan before updating one coordinator row. This fixes
repeated cursor timeouts in Miller on long-lived family stores.

On a local one-million-entry fixture, alternating release binaries reduced measured
warm cursor operations from roughly 2.4 seconds to 5 milliseconds. The deterministic
regression test proves that neither command reads unrelated manifest rows.

Cursor reports retain schema version 1 and add `measurement_scope: "cursor_only"`.
GC counts, capacity, and retention fields are explicitly unmeasured defaults in these
reports; use `store maintain inspect` for GC measurements. Other maintenance output
is unchanged.

Reader-compatible clients can maintain their cursors even when the store's fact-writer
version is newer. Reader floors, supported schemas, serving-generation checks,
maintenance exclusion, monotonic cursor bounds, and reader retention remain enforced.
Plan mode writes no database changes.

No schema, extraction-identity, parser-output, or upstream dependency changes.
