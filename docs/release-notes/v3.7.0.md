# julie-extract 3.7.0

classification: compatible

This release fixes false reference targets, keeps separate reference
occurrences apart, moves receiver facts into the language extractors, and
closes ten extraction gaps plus regex branch-reset groups. Every change is
declared in [the extraction-output ledger](../contracts/extraction-output-changes.md)
under `3.7.0`.

## Upgrade

- Run `julie-extract scan --root <dir> --db <path> --force` once on every
  existing artifact. Incremental `scan`, `update`, `delete` and `rebind` now
  refuse an artifact built by a different binary version with
  `fingerprint_mismatch` (exit code `3`) and change nothing.

## Fixed

- A call could bind to a local function that a parameter or local variable
  shadowed, to a function in an unrelated scope, or to an Elixir function with
  a different arity. These calls are now pending relationships with their
  source span, receiver and caller.
- A call that needs inheritance lookup no longer picks a method only because
  its name is unique in the file. It stays pending for the consumer.
- An ECMAScript ordinary function nested in a class no longer treats `this` as
  the class.
- Two calls to the same target on one line collapsed into one relationship
  row. Each occurrence now has its own row.
- HTML, regex and C# identifier spans covered a wider node than the name. They
  now select the name token.
- A failed `--force` scan could leave a partly written generation. Facts and
  producer metadata now commit together, and a source or discovery error
  keeps the previous generation.

## Added

- Receiver facts come from the syntax tree in the extractor. For
  `a.b.run()`, `receiver` is `b` and `receiver_qualifier` is `a`. SQL routine
  calls and Rust macro calls gain qualified receivers.
- Actix: typed `ServiceConfig` routes, local scope bindings, resource paths
  and method guards.
- Local typed `reqwest` fields, and local Tesla clients with `BaseUrl`
  middleware.
- Rust benchmark harness facts, without test-case roles.
- Cucumber step methods in Java use the step-definition role.
- Swift Testing named traits with raw arguments.
- Kotest table checks and property checks inside their owning test.
- Phoenix socket and channel facts.
- Regex conditionals `(?(1)...)` and branch-reset groups `(?|...)`, with
  PCRE2 capture numbering. The regex parser is a vendored, licensed patch of
  `tree-sitter-regex` 0.25.0 (`0.25.0-julie.1`).

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `reference-occurrence-identity-v2`, `canonical-receiver-facts-v1`,
  `reference-integrity-v1` and `regex-branch-reset-v1`.
- Expect more `relationships` rows where one line repeats a call, and fewer
  resolved rows where a target was false. The pending rows keep the call
  sites.
- Regex `capture_index` and `captureIndex` values can repeat inside one
  pattern that uses a branch-reset group.

## Known gaps

Eleven capability gaps stay open. Four need a consumer join of existing
mount facts to route facts: Actix scopes, Axum nests, Laravel provider
prefixes and Phoenix forwards. Seven need explicit project context: unknown
Rust and Kotlin client receiver types, ambiguous Axum colon parameters, and
Next.js Pages Router files without framework signals in TypeScript, TSX,
JavaScript and JSX.
