# julie-extract 2.40.4

Completion checkpoints now skip missing, empty, and header-only WALs separately
for each database. Reader acquire, renew, and release can checkpoint coordinator
changes without issuing an empty TRUNCATE against an unchanged store.

Empty TRUNCATE operations can advance another SQLite connection's `data_version`
without changing stored rows. Repeated reader operations could therefore make
maintenance inspection continually refuse with `maintenance_inspection_raced`.
The fix removes that unnecessary invalidation.

Real WAL frames still receive the existing bounded checkpoint attempt, including
debt from an earlier interrupted command. Unknown WAL metadata is not treated as
empty. Busy-reader deferral, replay retries, retention, and the maintenance
concurrent-mutation guards remain unchanged.

The reader-lifecycle regression passed on Linux and Windows. No schema,
extraction-identity, parser-output, or CLI-report change.
