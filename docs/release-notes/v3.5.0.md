# julie-extract 3.5.0

classification: compatible

This release closes the gaps that the 3.4.0 language gap closure left for an
owner decision or a grammar change. Every row change is declared in [the
extraction-output ledger](../contracts/extraction-output-changes.md) under
`3.5.0`. The plan is [gap follow-ups](../plans/2026-09-23-gap-followups.md).

## Added

- Step definitions. `test_role` gains `step_definition`. SpecFlow and Reqnroll
  methods of a `[Binding]` class with `[Given]`, `[When]`, `[Then]`, or
  `[StepDefinition]`, and Behat methods with a `Given`, `When`, or `Then`
  attribute or docblock tag, carry it. A Behat context class is a
  `test_container`, and its `Before*` and `After*` hooks are fixture hooks. See
  the [decision](../decisions/2026-09-23-step-definition-test-role.md).
- `gomod`. A `go.mod` file is a new language. It publishes the module path, the
  `go`, `toolchain`, and `godebug` settings, and every `require` and `tool`
  entry as symbols, `imports` edges from the module, pending rows for local
  `replace` targets, and facts for every directive. Each `require` line is a
  `manifest.dependency.v1` fact with ecosystem `go` and `indirect`.
- `gosum`. A `go.sum` file is a new language. Each checksum line is a
  `gosum.checksum.v1` fact with the module path, version, hash, whether the hash
  covers only `go.mod`, and pseudo-version details. It publishes no symbols.
- Grammar forks. `anortham/tree-sitter-go-mod` adds the `godebug` directive,
  absolute and one-character paths, and a last line without a newline.
  `anortham/tree-sitter-go-sum` accepts empty files and any semantic-version
  pre-release. `julie-extract languages --json` lists 42 languages.

## Changed

- JSON5 is out of scope, and its open gap is retired. See the
  [decision](../decisions/2026-09-23-json5-out-of-scope.md).
- Regex conditionals stay an open gap: tree-sitter-regex 0.25.0, the latest
  release, has no conditional rule.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `step-definition-role-v1`, `go-module-manifest-v1`, and
  `go-sum-checksums-v1`.
- A step definition sets none of `is_test`, `test_container`, or
  `test_lifecycle`. Read `test_role` in `metadata_json` to find it.
- A reader must accept the new `step_definition` value and the `gomod` and
  `gosum` languages.
- Rust callers: the public `TestRole` enum gains `StepDefinition`, so an
  exhaustive `match` on it needs a new arm.
- Replace the binary and rebuild every artifact. No schema migration is
  required.

## Evidence

- Linux: `cargo fmt --check`, workspace Clippy with `-D warnings` on Rust 1.97
  and 1.98, `scripts/check-agent-doc-sync.sh`, `cargo test -p xtask`, and the
  golden, capability, certification, default (5,474 passed), and contract (187
  passed) tiers pass.
- Strict language report: `silent_cells=0`, `quality_bar_debts=0`,
  `open_gap_backlog=21`.
- Windows: the default tier passes (5,465 passed, 7 ignored).
- `cargo xtask compat-check` against the published 3.4.0 binary accepts the
  `3.5.0` compatible ledger entry.
- Real files: 128 local `go.mod` files and 70 local `go.sum` files scan with no
  failed file and no parse diagnostic. Nine comparison repositories scan with
  no failed file; their rows match 3.4.0 except the new `go.mod` and `go.sum`
  rows, and scan times stay within run-to-run noise.
- A two-pass external review (general and security) found four medium defects,
  all fixed before release: Behat step roles that a PHPUnit name rule could
  overwrite, a generic `Context` base type taken as Behat, undecoded Go string
  escapes, and a go.mod comment check whose cost grew with the square of a
  comment block. A retract comment is now also read once per block and kept to
  500 bytes.
