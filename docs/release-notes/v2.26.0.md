# julie-extract v2.26.0

Delta resolution release: whole-repo scans now honour the delta scope they
already compute, the delta path reaches every resolution tier it was silently
skipping, and no scoped pass pays the workspace-wide report aggregate. On a
1,397-file repo a one-changed-file whole-repo scan drops from ~12.2 s to
~2.9 s (4.2×); the single-file delta resolution gate runs at 51 ms release
against its 100 ms design target — down from 172 ms on v2.25.0, where the
O(workspace) report aggregate was most of the number.

## Delta soundness (correctness, not speed)

The scoped path previously produced answers a full pass would not. Three
classes fixed, each reproduced against v2.25.0 first:

- **Tier-2/3 reachability:** a delta over files whose edits changed
  import-resolution or receiver-type facts re-ran only tier-4 keys; imports
  filled by a delta and receiver-typed members now resolve identically to a
  full pass.
- **Module-specifier rebinding:** adding or deleting a file that re-points a
  module specifier (shadowing, unshadowing, and shadow files with disjoint
  exports) now widens the delta scope by module-candidate **path**, not just
  touched names — the shadow-with-unrelated-exports case previously kept the
  old target alive.
- **Receiver-type uniqueness restoration:** deleting the file that made a
  receiver type ambiguous re-resolves the survivors.

The acceptance gate is new `resolution_scope_equivalence.rs`: an artifact
converged by N incremental steps must carry a resolution overlay identical to
a full re-derivation over the same rows — nine scenarios including multi-step
edit sequences and both shadowing directions. It fails 3/4 arms on unmodified
v2.25.0 and passes 9/9 here.

## Whole-repo scans scope resolution

Both whole-repo write sites passed `is_full_scan: true` while already
computing `changed_file_ids`. The resolution hook now takes the scoped branch
for whole-repo scans when no path moved, with a measured crossover promotion:
past `DELTA_SCOPE_CROSSOVER` (0.7 — scoped passes cross Full cost at 70–80 %
of the corpus on the 92k-identifier perf fixture) the pass promotes itself to
Full, so a mass edit never pays scoped bookkeeping on top of Full work.
Worklist `IN` binds are chunked, so a widened scope past SQLite's 32,766
variable limit resolves instead of erroring (probed to 80,000 touched names).

## Scoped passes skip the workspace-wide report aggregate

`run_resolution` previously ended **every** pass — including a single-file
`update` — with the workspace-wide `resolution_report` aggregation, inside
the write transaction. That query was 69 ms of the original 81 ms delta-gate
figure and grew to 130 ms; at a 10M-identifier scale it extrapolates to
seconds per file save. Scoped passes no longer compute it; passes that
re-derive the whole workspace (full scan, v3 backfill, crossover-promoted
delta) still do. Root-cause attribution:
`docs/findings/2026-08-05-single-file-delta-172ms-attribution.md`.

## Contract changes

- Scan/update report `reference_resolution` section: `totals`,
  `origin_totals`, and `by_language` are **JSON null on scoped passes**
  ("not recomputed by this pass", never "zero rows") and present on
  whole-workspace passes. `status`, `version`, `last_full_revision`,
  `counts`, `gated_languages`, and `failed` are pass-derived and always
  present. Documented in `docs/contracts/reports.md`.
- Durable `reference_resolution_*` artifact metadata is unchanged and remains
  correct on every pass kind.
- No schema/catalog changes, no new flags, argv byte-identical to v2.25.0.

## Evidence

Branch gates at the released tree on rustc 1.97.1: `cargo fmt --check`,
clippy `-D warnings` (workspace, all targets, `test-perf` on),
`cargo test -p xtask`, `cargo xtask test default`, `cargo xtask test
contract`, `cargo xtask test capability`, and the feature-gated
`resolution_perf` suite 5/5 in release: FULL 805 ms (2 s budget), single-file
delta 51 ms (150 ms ceiling, 100 ms design target), savepoint-seam full
1,660 ms (5 s ceiling), variable-limit chunking to 80k names, and the
crossover sweep validating the shipped 0.7 threshold one-sided against the
measured 70–80 % crossing. Delta-vs-full equivalence 9/9. Cross-model review
(Codex) of the report-skip commit found no correctness issues. Whole-repo
scan timings measured on a 1,397-file repo: leaf-file change 12.20 s → 2.88 s;
hot-shared-import change 12.36 s → 13.26 s (correctly promotes to Full past
the crossover).
