# julie-extract v2.38.0

classification: compatible

This release adds F# as the 40th extraction language, and closes three
extractor gaps in Go, Rust, and C#. Every claim below is backed by golden
fixture evidence in `fixtures/extraction/`, and the strict data-quality gate
still reports `silent_cells: 0` and `quality_bar_debts: 0`.

## F# extraction

`julie-extract` registers `fsharp` for `.fs`, `.fsx`, and `.fsi`. Source and
script files parse with `tree_sitter_fsharp::LANGUAGE_FSHARP`; signature files
parse with `tree_sitter_fsharp::LANGUAGE_SIGNATURE`. All three publish the
stable artifact language `fsharp`, so a consumer never sees a second language
name for a signature file.

- Full capability tier: symbols, relationships, pending relationships,
  identifiers, types, body spans, doc comments, annotations, literals, source
  regions, complexity metrics, test detection, structural facts, and type
  argument usages.
- Symbols cover modules, namespaces, classes, records, unions, structs,
  members, properties, fields, enum members, functions, and values.
- New structural fact pattern `fsharp.attribute.v1` records an attribute
  applied to a declaration. The fact attaches only to an annotated symbol in
  the attribute's own scope. An attribute with no in-scope target, such as an
  `[<assembly: ...>]` attribute, keeps its lexical container instead of
  claiming an unrelated later symbol.
- Test detection recognizes xUnit `Fact` and `Theory` attributes, including a
  qualified spelling.
- Parser dependency: `tree-sitter-fsharp` pinned at `=0.3.0`.
- Five fixture families prove the claims: `basic`, `script`, `signature`,
  `negative`, and `test_roles`.

One gap stays open and is recorded in `fixtures/extraction/capabilities.json`:
a top-level `open` in a `.fsx` script has no enclosing symbol, so no import
relationship is attached rather than inventing a caller row.

## Go literal subtests

A literal `t.Run("name", func(t *testing.T) { … })` inside a test function now
produces its own test-case symbol, parented to the enclosing test. Nested
`t.Run` calls keep their parent identity, so a subtest tree survives into the
artifact.

The receiver must really be the test's `*testing.T`. A `t` rebound by any of
the following is not treated as a test handle, and emits nothing:

- a `var` declaration or a short declaration earlier in the same block,
- an `if`, `for`, expression-switch, or type-switch initializer,
- a `range` clause binding,
- a type-switch alias,
- a named result,
- a `select` receive binding.

A dynamic subtest name, a callback with the wrong parameter list, and a
non-`Run` member all stay silent rather than emit a guessed row.

## Rust doc-test facts

A new `rust.doc_test.v1` structural fact records each executable fenced code
block in a rustdoc comment: outer `///` and inner `//!` line comments, and
`/** ... */` and `/*! ... */` block doc comments. For a block comment the
collector applies rustdoc's horizontal trim, so a `*` gutter shared by every
line after the first is stripped before fence scanning while spans keep the
original source bytes. The `mode` metadata key carries the rustdoc execution
mode: `run`, `ignore`, `no_run`, or `compile_fail`.

Fence recognition follows rustdoc's own rule for the info string. The
recognized attributes are `rust`, `ignore`, `ignore-<reason>`, `should_panic`,
`no_run`, `compile_fail`, `test_harness`, `standalone_crate`, and
`edition<year>`. A fence carrying an unrecognized token stays a doc test only
when a recognized attribute appears too. A `should_panic` or `edition2021`
fence is therefore extracted, while a `text` or `python` fence emits nothing.

## C# internal visibility

A C# declaration marked `internal` now reports visibility `internal`. It used
to report `private`, with the real value kept only in metadata. Consumers that
group or filter C# symbols by visibility see the corrected value after a
re-extract.

## Compatibility

Artifacts stay schema 7, JSONL stays contract v5, family stores stay store
schema 2, store format epoch stays 1, the report schema stays 3, and the
extraction identity epoch stays 7. No consumer read path changes shape.

`EXTRACTION_CONTRACT_VERSION` gains the suffixes `csharp-visibility-v2`,
`go-subtests-v1`, `rust-doc-test-facts-v1`, and `fsharp-v1`. A consumer that
pins the contract version re-extracts to pick up the new rows and the corrected
C# visibility values. An existing artifact keeps working unchanged until it is
re-extracted.

Two additions widen `language_capabilities.kind_coverage_json`:
`rust.doc_test.v1` and `fsharp.attribute.v1`. Readers that enumerate structural
fact pattern ids see the two new entries.
