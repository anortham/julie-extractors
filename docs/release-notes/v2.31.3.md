# julie-extract v2.31.3

Patch release that hardens the family store for concurrent multi-worktree
writers and maintenance freezes.

## Concurrent fencing

Ordinary store-writer lease acquire now refuses while a foreign live
maintenance intent exists, even when the lease row is absent during a long
generation build. Maintenance ownership uses an explicit owner fence
(`run_id`, owner id/pid, and fencing token). Enqueue, resolve claim, and
consumer cursor advance/release recheck that intent inside their IMMEDIATE
coordinator transactions.

## Temporary writer floor and destination normalization

Maintenance raises the frozen source `min_writer_version` and mirrors intent
into reserved `maintenance_tmp_*` metadata before releasing the writer lease
for generation construction. Promotion forces the destination floor back to
the pre-maintenance value and strips temporary mirrors. Finish, abort, and
Drop cleanup restore a still-serving source floor before clearing coordinator
authority so compatible writers are not permanently blocked.

## Resolve and import durability

Exact resolve publication requires a pre-`BEGIN IMMEDIATE` heartbeat and
validates writer leases against wall clock. Resolve terminal log rows use
fenced writers. Resolve pins are released on failure paths when ownership
allows, and expired pins no longer protect resolution bases. Import
resolution bases follow building→ready discipline, refuse to steal live
builders, and clean orphan base files on failure where possible.

## Capacity

Maintenance re-probes live free bytes before scratch purge, GC demotion
cohorts, and generation staging so plan-time free space cannot authorize
destructive work after free space drops.

## Verification

Formatting, Clippy, default, and contract gates are required for this
candidate, including store coordinator, connection, generation, maintenance,
crash, resolution, import, and adapter contracts.

This candidate is not yet the published release until tag `v2.31.3` is
published with the four-target packages.
