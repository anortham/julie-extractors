# v2.21.0

This release adds two new supported languages — **Erlang** at the full
capability tier and **XML** (`.xml`/`.xsd`/`.wsdl`) at the data-only tier —
bringing the language count from 36 to 38. It also changes the oversized-file
transition policy in `julie-extract` (consumer-facing) and adds bounded
parse-error recovery for Erlang with an explicit recovery-budget diagnostic.

## Erlang (language 37, FULL tier)

- Symbols: modules, functions (multi-clause functions span every clause; body
  hashes move when any clause changes), records and fields, types, macros,
  callbacks, with export-driven visibility.
- Identifiers: calls (local/remote/imported with `-import` arity lookup),
  member access, type usage, variable refs; walks are restricted to executable
  forms so `-spec`/`-type` type names never emit false calls.
- Relationships: same-file call edges plus structured pending edges for remote
  calls and `-behaviour` declarations.
- Types, test roles (EUnit modules and Common Test suites with lifecycle
  hooks), doc comments (`-moduledoc`/`-doc`), complexity metrics (in-expression
  branch forms plus guards; comprehensions as loops), string call-argument
  literals, and five structural-fact patterns:
  `erlang.module_attribute.v1`, `erlang.behaviour_declaration.v1`,
  `erlang.callback_declaration.v1`, `erlang.export_attribute.v1`,
  `erlang.include_directive.v1`.
- **Bounded parse-error recovery**: a file whose root parse fails is
  re-parsed from column-0 form boundaries (≤32 passes) so declarations after a
  broken form are still extracted. Literal ranges come from a tree-independent
  lexical scan (strings, triple-quoted strings, quoted atoms, `$` chars,
  comments), so form-shaped text inside unclosed strings cannot mint phantom
  symbols. Exhausting the recovery budget now emits an explicit parse
  diagnostic naming the give-up offset.
- Real-world corpus gate: telemetry 1.3.0, certifi 2.15.0,
  unicode_util_compat 0.7.1 vendored under `fixtures/real-world/erlang/` with
  an exact committed baseline.

## XML (language 38, DATA_ONLY tier)

- Symbols: name-promoted elements for schema/config documents; anonymous
  repeated elements collapse (a 4,000-row catalog produces 3 symbols).
- Identifiers: `type`/`ref`/`base`/`element` attributes become type-usage
  references **only when the owning element or attribute resolves to a declared
  XML Schema, XML Schema-instance, or WSDL namespace** — generic XML
  (`<button type="button">`, `.csproj`, logging configs) emits none.
- Attribute-value literals under the shared `tag.attribute` carrier.
- Ten structural-fact patterns covering document/namespace shapes, XSD
  types/elements/imports, and WSDL services/ports/operations/messages/bindings.
- Files over the 1MB source cap remain unsupported by design; machine-generated
  multi-megabyte schemas are codegen inputs whose generated code is already
  indexed.

## Oversized-file transition policy (consumer-facing)

A tracked file that grows past `MAX_SOURCE_FILE_BYTES` (1MB) now has its rows
**removed** from the artifact instead of silently keeping stale data:

- `update` returns `status: unsupported` for that file (previously
  `no_change`). Consumers that branch on update status should treat
  `unsupported` as "rows gone", not "nothing happened".
- `scan` no longer preserves rows for files skipped as oversized.
- A file shrinking back under the cap re-extracts normally.

## Parse-diagnostic messages

`ParseDiagnostic` now carries an optional `message` (SQLite column and JSONL
field already existed in the artifact contract; extractors now populate it).
The pipeline appends extractor-supplied diagnostics to tree-derived ones
instead of overwriting them. Diagnostic identity is unchanged when no message
is present.

## Contracts and dependencies

- Extraction contract version: unchanged (new languages land inside existing
  row domains; structural facts stay on `structural-facts-v1`).
- New parser dependencies: `tree-sitter-erlang = 0.20.0`,
  `tree-sitter-xml = 0.7.0` (both crates.io, pinned exact). Parser
  certification gate green for the full 38-language inventory.
- Strict data-quality scorecard: 38 languages, 728 cells, 0 silent cells,
  0 quality-bar debts.

## Review evidence

Two independent adversarial reviews ran pre-release with all findings either
fixed or dispositioned: multi-clause span/body-hash coverage, schema-namespace
gating for XML references, quoted-atom and unclosed-string recovery hardening,
and the recovery-budget diagnostic all landed as fixes from those reviews.
