# julie-extract v2.38.2

classification: compatible

v2.38.0 already maps a C# declaration marked `internal` to visibility
`internal`. It left the extraction identity epoch at 7. Family-store import
reuses a completed `(path, content_hash, extraction_epoch)` identity, so an
unchanged C# file kept its epoch-7 rows and never rewrote L1.

This release advances `EXTRACTION_IDENTITY_EPOCH` from 7 to 8. An unchanged
C# file therefore gets a new `file_versions` row on the next import. The new
row carries `visibility=internal` for explicit `internal` types and members.
Epoch 7 rows stay immutable.

The capability snapshot is keyed to epoch 8. That avoids the epoch-7
collision that fired after F# was added (39 languages vs 40;
`INSERT OR IGNORE` plus exact match).

Extraction fact tables stay byte-identical to v2.38.1. Artifacts stay schema
7, JSONL stays contract v5, family stores stay store schema 2, and store
format epoch stays 1. `EXTRACTION_CONTRACT_VERSION` is unchanged.

Consumer action: replace the binary and let epoch-8 family-store file
versions populate on the next import or update. Do not delete live
`file_versions` to force a rewrite.

Miller 1.26.0 stays on julie-extract 2.38.1 / epoch 7 until it pins this
release.
