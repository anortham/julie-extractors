# julie-extract 3.1.1

classification: compatible

This release fixes how every language extractor records a qualified call chain
in `pending_relationships`. The change is declared in
[the extraction-output ledger](../contracts/extraction-output-changes.md) under
`3.1.1`.

## Changed

- A qualified call chain `Q1.Q2 ... Qn.t(...)` now records `terminal_name = t`,
  `receiver = Qn`, and `namespace_path = [Q1 .. Qn-1]`, with `display_name`
  joined by `.`. Before this release each language chose its own split: some
  kept the whole chain in `receiver`, some dropped the qualifiers, some kept a
  language-native separator such as `::` or `->`, and C# recorded the receiver
  as the terminal name (`client` instead of `client.GetFromJsonAsync`).
- Languages changed: C#, Java, Kotlin, Go, PowerShell, C++, Zig, JavaScript,
  TypeScript, Python, Swift, Dart, Lua, GDScript, C, PHP, Ruby, and R.
- Scala and VB.NET already produced the target shape and are unchanged.
- Rust, Elixir, F#, and Erlang are unchanged: they record a path-style call
  with every qualifier in `namespace_path` and no `receiver`.
- Golden fixtures regenerated: `csharp/http_client`, `java/basic`,
  `powershell/basic`, `powershell/return_types`, `cpp/basic`, `cpp/cross_file`,
  `ruby/basic`, `ruby/backend_http_boundaries`, and `zig/test_roles`. Every
  changed row is a receiver split into `receiver` and `namespace_path`, a
  newly emitted pending row for a chain that emitted nothing before, a
  `display_name` or `callee_name` whose separator became `.`, or the corrected
  C# terminal name.

## Compatibility

- SQLite artifact schema remains 7 and report schema remains 3.
- Extraction contract and identity epoch remain unchanged. No column, table, or
  JSON shape changes, so a reader built for 3.1.0 reads the new output
  correctly.
- A consumer that already holds an artifact must rebuild it rather than rescan,
  because an unchanged file keeps its stored rows.
- A consumer that matched `receiver` against a whole chain such as `Net::HTTP`
  must now match `receiver` against the last qualifier and read the earlier
  qualifiers from `namespace_path`.

## Contract changes

- [The extracted-data contract](../contracts/extracted-data-v3.md) states at
  the `pending_relationships` row that the receiver is the last qualifier
  before the terminal name and the namespace path holds the qualifiers before
  it.

## Evidence

- `cargo xtask test golden`: passes after regeneration.
- `cargo xtask test capability`: passes.
- `cargo xtask release preflight --version 3.1.1`: exit 0.
