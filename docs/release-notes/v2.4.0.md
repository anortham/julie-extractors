# v2.4.0

This minor release makes file selection a precise, git-exact contract. It
fixes a family of ignore-rule precedence and scoping defects found in a
pre-release review, gives caller-supplied `--ignore-file` rules the final
word over in-tree ignore files, and documents the full layering in the CLI
contract. Extraction output for a given selected file is unchanged.

## Features

- `.julieignore` files are honored in nested subdirectories at any depth
  (previously capped), including hidden directories, with the same semantics
  as nested `.gitignore`.
- `--ignore-file` rules now take precedence over in-tree `.gitignore` and
  `.julieignore` rules in both directions: a caller exclusion cannot be
  re-included by a committed whitelist, and a caller whitelist can re-include
  a file in-tree rules ignore. This makes consumer-side vendor routing via
  `--ignore-file` reliable (see
  `docs/decisions/2026-06-11-ignore-rule-precedence.md`).
- In-tree ignore files that cannot be read are reported as non-fatal entries
  in the report `errors` array instead of being silently skipped.
- New "File Selection and Ignore Rules" section in `docs/contracts/cli.md`
  documents the layering as a stable contract for consumers that mirror scan
  selection, and all CLI flags now carry `--help` descriptions.

## Fixes

- Nested ignore-file patterns previously leaked root-relative matches because
  all files fed one root-anchored matcher; every ignore file is now anchored
  at its own directory, exactly as git.
- A whitelist (`!pattern`) can no longer re-include a file underneath an
  excluded parent directory. `scan` and `update` share one selection path, so
  `update` can no longer insert rows for files a fresh `scan` would drop.
- Ancestor `.gitignore` files (between the scan root and the git root) are
  now anchored at their own directories, so anchored patterns such as `/docs`
  behave as git does.
- Ignore files inside hidden directories (for example `.devcontainer/`) are
  now honored; previously they were collected from no dot-directory while the
  scan still traversed them.
- Ignore files inside excluded directories are no longer read, and symlinked
  directories are never traversed while collecting ignore files.
- `.julieignore`-over-`.gitignore` precedence in one directory is now an
  explicit load order instead of a filename-sort coincidence.

## Contract Changes

- Rust package versions change from `2.3.0` to `2.4.0`.
- SQLite schema version remains `3`.
- Artifact integer `extract_contract_version` remains `3`.
- JSONL schema version remains `3`.
- JSON report schema version remains `3`.
- File selection precedence is now: hard safety exclusions, then
  `--ignore-file` rules (decisive), then in-tree ignore files with git
  semantics (deepest directory wins, `.julieignore` beats `.gitignore` in the
  same directory, no re-inclusion under an excluded parent). The previous
  in-tree-outranks-caller wording shipped in no release.
- Report `errors` entries may now describe unreadable in-tree ignore files;
  they are non-fatal.
- Parser dependency versions are unchanged.
