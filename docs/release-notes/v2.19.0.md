# v2.19.0

This release adds a static-type receiver resolution tier and fixes a C#
extractor gap that left file-scoped namespaces unrecorded. Both change artifact
content for existing C# sources; schema and contract versions are unchanged.

## Static-type receiver resolution

- Resolution contract version is 3. Artifacts written by an older producer are
  re-resolved on the next scan.
- New tier 3b binds a reference whose receiver names a type directly:
  `Fixture.Create()`, `Color.Red`, `Limits.Max`. No `type_facts` row
  participates, so it carries its own method string `tier3_static_type` at
  confidence `0.70` — below a concrete type fact, above global uniqueness.
- Both tier-3 methods stamp `tier = 3`. Consumers keying on the method string
  must accept `tier3_static_type` alongside `tier3_receiver`.
- Identifier `member_access` now targets `Constant` and `EnumMember` in addition
  to Property/Field/Method.

The tier refuses everything it cannot corroborate, because a wrong edge is worse
than a missing one:

- a receiver type nested inside another type
- a non-public type referenced outside its declaring file
- a member whose signature carries no standalone `static` modifier, scanning
  only the modifier prefix so an expression body or field initializer containing
  the word cannot pass for one
- a receiver whose written qualification is not a suffix of the candidate's
  declared namespace, so `External.Fixture.Create()` never answers for a
  workspace `App.Core.Fixture`
- a receiver shadowed by a parameter of an enclosing callable

## C# file-scoped namespaces

- `namespace App.Core;` now produces a `namespace` symbol and parents the types
  it governs, matching what block syntax already produced. Previously only
  `namespace App.Core { ... }` was recognized, so file-scoped sources emitted no
  namespace symbol and left every type unparented.
- A 1,447-file C# corpus went from 0 to 655 namespace symbols. Consumers will
  see new namespace rows and changed `parent_symbol_id` values on C# types.

## Identifier resolution reporting

- Identifiers are no longer skipped merely for sharing a span with a pending or
  relationship edge; only identifiers a currently resolved edge owns are.
  Previously 63,840 C# identifiers in the measured corpus carried no
  `identifier_resolutions` row at all. That count is now 0.
- Delta invalidation keys on the receiver name as well as the terminal name, so
  editing only a receiver type rechecks the resolutions that depend on it.
- Delta ownership is read over the full resolution scope rather than only
  changed files, so an identifier in an unchanged file cannot have a correct
  propagated target overwritten by the generic chain.

## Measured effect

On a 310k-identifier C# corpus, comparing 2.18.0 to this release:

| identifier kind | 2.18.0 | 2.19.0 |
|---|---|---|
| `call` | 16,659 (19.4%) | 21,995 (25.7%) |
| `member_access` | 96 (0.2%) | 5,399 (12.0%) |
| `type_usage` | 10,132 (37.2%) | 10,631 (39.0%) |
| overall | 34,371 (11.1%) | 45,511 (14.7%) |

External receivers stay unresolved: `Assert.Equal` (7,091 sites),
`Assert.Contains` (2,859), `Path.Combine` (1,691), `File.WriteAllText` (416),
`Directory.CreateDirectory` (390) all resolve to zero.

## Capability gaps

- The certified reference-resolution snapshot now contains 105 open gaps: 36
  tier-3 receiver rows, 34 tier-2 import rows, and 35 tier-3 static-type rows.
- `reference_resolution.tier3_static_type` is recorded for every language
  outside `TIER3_STATIC_TYPE_LANGUAGES`, which is C# only. The tier runs
  everywhere, but only yields edges where the extractor emits type `visibility`
  and a standalone `static` member modifier.

## Contract versions

- Rust package versions are `2.19.0` for `julie-extract-artifact`,
  `julie-extract-cli`, and `julie-extractors`.
- SQLite schema version is 5. Unchanged.
- Extract contract version is 4. Unchanged.
- JSONL schema version is 4. Unchanged.
- Resolution contract version is 3, raised from 2.

## Consumer note

No schema migration is required. Rescan to pick up the new namespace symbols and
resolution rows; a stale resolution version forces a full re-resolution pass
automatically. Consumers that classify overlay targets should note that
`tier3_static_type` at `0.70` is corroborated by the receiver but not by a
recorded type fact, and rank it accordingly rather than treating every overlay
target as equally exact.
