# julie-extract v2.28.0

Resolution crossover release: the delta-scope crossover guard now measures what
the pass actually pays for. Two changes, both in the resolution pass, no schema
or artifact-contract change.

## The crossover is denominated in identifier rows, with a save-shape exemption

`DELTA_SCOPE_CROSSOVER` decides when a widened delta resolution scope should
promote to one Full pass. It compared the scope's **file count** against 70% of
the workspace's files, while the pass's cost is the **identifier rows** it
loads and resolves — and the widening unions preferentially select large files,
so file share systematically understates cost on dense corpora.

Measured on a real 1,420-file C#-dense workspace (381k identifiers):

- A 737-changed-file scan delta covered **52% of files** — under the old guard
  it stayed scoped — while holding **99.7% of identifiers**, and paid 26.0 s of
  scoped resolution where Full paid 22.6 s in a same-minute paired A/B
  (25,972 ms vs 22,569 ms; wall 57.4 s vs 53.3 s). The guard now promotes this
  shape.
- A **single-changed-file** save whose scope widened to 90–93% of identifiers
  paid the **same or less** on the scoped path as on Full across repeated
  paired runs. Promotion sheds per-changed-file worklist overhead, and a
  one-file worklist has none worth shedding — so a single-changed-file scope
  is now **exempt from promotion entirely**. Single-file `update` behavior,
  cost, and resolved-row counts are unchanged from v2.27.0.

The shipped threshold stays 0.7. The `resolution_perf` crossover sweep now
reports its x-axis in identifier share (on its uniform fixture the measured
crossing is ~80%, so the shipped 0.7 keeps erring on the side that costs time,
never correctness).

## A promoted delta no longer claims whole-corpus coverage

`reference_resolution_last_full_revision` and `complete` status now advance
only when the write hash-checked the whole corpus (`whole_corpus` scans), never
because a scoped delta happened to promote to Full resolution. A promoted
single-file update re-derives every resolution row from artifact state but
verified one file on disk; claiming corpus currency from that conflated
resolution coverage with corpus freshness. Whole-repo scans are unaffected —
every production scan path carries `whole_corpus`.

## Compatibility

- No schema change, no artifact-contract change, no new flags.
- `RESOLUTION_VERSION` is unchanged: resolution output for any given scope is
  byte-identical to v2.27.0; only the scoped-vs-Full path choice and the
  metadata claims above changed. Delta and Full are contracted to agree
  (`resolution_scope_equivalence`), so promoted scopes produce the same rows.
- Single-file `update` / `delete` behavior is byte-identical to v2.27.0.

## Evidence

Committed in the Miller repo alongside this release: the paired A/B
