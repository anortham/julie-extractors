# julie-extract v2.36.0

classification: compatible

## Test-role contract for ten languages

- Symbols now carry a `test_role` metadata string — `test_case`,
  `parameterized_test`, `fixture_setup`, `fixture_teardown`, or
  `test_container` — that always agrees with the `is_test`, `test_container`,
  and `test_lifecycle` booleans. A single writer (`apply_test_role`) sets both
  forms, and a golden universality gate holds the agreement.
- Golden-backed coverage for Rust, Python, C#, JavaScript/TypeScript (all four
  dialects), Go, Java, Ruby, PHP, Kotlin, and Swift, including framework
  containers, parameterized cases, and setup/teardown lifecycle direction.
- A shared JavaScript-family classifier gates the bare test DSL on a test path
  or a named framework import, resolves namespaced chains
  (`test.describe`, `QUnit.module`, `t.test`), drops run modifiers, and keeps
  `.each` tables in the leading word's own category: `test.each`/`it.each`
  report `parameterized_test`, `describe.each` reports `test_container`.
- Python decorator handling no longer leaks a decorator onto nested functions
  or onto the methods of a decorated class.
- Test-path detection covers Ruby/Python/PHP/Swift file conventions, Gradle
  test source sets, and Cypress layouts, with `/` and `\` treated alike.

## Unsupported files in the artifact

- Files the discovery walk reaches but no extractor claims now get journal and
  `files` rows with `language = "unsupported"`, so a downstream consumer can
  see the whole tree. Files over the source-size cap are skipped before
  hashing, whatever their extension.

## Adversarial review hardening

An external adversarial review (grok-4.6) of the complete change set produced
six confirmed findings; all six are fixed and test-locked in this release:
the unsupported-file size cap above, path-gated Python lifecycle names,
container-role `describe.each`, removal of the bare `integration/` test-path
segment, Windows-separator handling in the JavaScript file probe, and a
contract-marker lock in the public API surface test.

## Compatibility

Artifacts stay schema 7, JSONL stays contract v5, family stores stay store
schema 2, and store format epoch stays 1. Extraction identity epoch advances
from 5 to 6, and `EXTRACTION_CONTRACT_VERSION` gains the
`test-role-strings-v2` marker. Existing v2.35.1 readers can read the unchanged
artifact tables; replace the binary and re-extract source trees, or let
epoch-6 family-store file versions populate on the next import or update, to
receive `test_role` metadata.
