# julie-extract 2.43.0

classification: compatible

This release adds the `facts` extraction level: the symbol core plus
`structural_facts`, with no identifiers, literals, type-argument usages, or
source regions. It exists for consumers such as `code-kb` that query framework
facts but never read the reference tables.

## Compatibility

- SQLite artifact schema remains 7, JSONL export contract remains v5, report
  schema remains 3, and family-store schema remains 2.
- Extraction contract and identity epoch remain unchanged; existing artifacts
  and unchanged files do not require migration or re-extraction.
- `symbols` and `full` levels are unchanged. `facts` is a new
  `index_level` value; older binaries report an artifact at that level as an
  unknown index level, as the CLI contract already specifies.
- Emitted facts, identifiers, JSON shapes, parser inventory, fixtures, and
  external dependency graph are unchanged at existing levels.

## Contract changes

- `scan --level <symbols|facts|full>` in [the CLI contract](../contracts/cli.md).
- `ExtractionLevel::Facts` and `ExtractionLevel::includes_structural_facts` in
  the Rust crate. `ExtractionResults::strip_to_symbols_level` is replaced by
  `strip_to_level(level)`.
