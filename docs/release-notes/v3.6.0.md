# julie-extract 3.6.0

classification: compatible

This release records the type of a binding whose value is a call to a
same-file callee with a declared return type. Before, a local such as
`let workspace = resolve_root(..)?` had no type fact, so code-kb could not
resolve `workspace.nested_project_root()` and missed real callers. Every row
change is declared in [the extraction-output
ledger](../contracts/extraction-output-changes.md) under `3.6.0`. The decision
is [call-initializer type facts](../decisions/2026-09-24-call-initializer-type-facts.md).

## Added

- Inferred `type_facts` rows (`is_inferred = 1`) for bindings whose value is a
  same-file call, in every general-purpose language. Each
  `docs/languages/<lang>.md` page states the call forms, the declarations that
  get a row, and the cases that record nothing.
- The rules for every language:
  - The callee must be in the same file.
  - Every same-named candidate must agree on one return type.
  - A generic return records nothing.
  - A call that a local, parameter, import, or inherited member may bind
    instead records nothing.
  - A chain that ends in an unknown method records nothing.
  - Only the language's own unwrap layers are removed, for example `?`,
    `.unwrap()`, `await`, `try`, and `!!`.
  - A written type always wins.
- Languages with no general return-type syntax read only declarations they can
  trust: R `setGeneric(valueClass =)`, Ruby Sorbet and RBS signatures, Lua
  `---@return`, and Elixir and Erlang same-module specs. The remaining Lua gaps
  are planned in [Lua call-initializer
  gaps](../plans/2026-09-24-lua-call-initializer-gaps.md).

## Changed

- Rows that were wrong are removed or corrected in several languages. Examples:
  - C `auto w = make();` was a function `make` and is now a variable `w`.
  - A C++ macro before a return type is no longer read as the type.
  - Python `Union[int, str]` no longer records `Union`.
  - Swift tuple and subscript constructor rows are removed.
  - Rust `Self::new()` records the impl type, not `Self`.
- Scoping is stricter in several languages:
  - An Elixir `alias` applies only after it appears.
  - An Erlang or Elixir arity no longer counts comments.
  - A Ruby pattern variable is a local, not a call.
  - A QML bare call links only through the nearest object and the component
    root.
- The ledger lists every change by language.
- Windows: tree-sitter-swift 0.7.3 computes a scanner flag with `1UL << 32`.
  `unsigned long` is 32 bits on Windows, so `try!` parses as `try` followed by
  a `!` prefix there. The Swift extractor now reads both parses the same way.
  [swift.md](../languages/swift.md) records the defect. The planned fix is a
  grammar fork that uses `1ULL`.
- The index walks that the new inference uses in C++, C#, Go, Lua, Ruby, and
  JavaScript now carry their context down the tree. They no longer climb from
  every node, because tree-sitter `parent()` rescans siblings from the root.
  Output does not change.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `call-initializer-type-facts-v1`.
- A reader built for 3.5.0 reads the new output. Inferred rows use the existing
  `is_inferred` column. Some rows keep the full written return type in
  `metadata.declared`.
- Rust callers: no public API changes.
- Replace the binary and rebuild every artifact. No schema migration is
  required.

  `open_gap_backlog=21`.
- Specialist tiers: real-world smoke, real-world release, certification, perf,
  and dogfood pass.
- `cargo xtask compat-check` against the published 3.5.0 binary accepts the
  `3.6.0` compatible ledger entry. The fixture adds one TypeScript inferred row
  and two capability rows.
- The original report: a rescan of code-kb gives the `server.rs` line-259 local
  `workspace` the inferred type `Workspace`. `code-kb refs nested_project_root`
  lists `resolve_project_root` at `server.rs:275`.
- Comparison repositories, 3.5.0 to 3.6.0, inferred rows:
  - code-kb Rust: 373 to 889
  - radzen-blazor C#: 3,818 to 5,003
  - miller C#: 8,871 to 10,697
  - miller Python: 70 to 852
  - zod TypeScript: 874 to 1,115
  - moshi Kotlin: 542 to 598
  - Alamofire Swift: 231 to 260
  - nlohmann-json C++: 18 to 71
- Unresolved receiver calls in code-kb Rust fell from 183 to 132. The three
  jq C rows that were removed were wrong (`un`, `unsigned`).
- Scan time, against 3.5.0 code built with the same compiler:
  - radzen-blazor +1.8%, miller +0.3%, nlohmann-json −3%.
  - Twelve other repositories are within 4%.
  - Long single files are within 6% in every language.
- An external review (Codex) of the whole branch found eight issues:
  - Rust `async` results, Rust shadowing bindings, `ok_or` giving `Result`, and
    associated types on generic parameters: all fixed.
  - Java supertypes the file cannot see: fixed. They now count as possible
    overload sources.
  - JavaScript callees reassigned to another value: fixed.
  - QML local bindings indexed too late: fixed.
  - A Dart inherited-member claim: disproved. Dart 3.13 calls the top-level
    function, and pinning tests now cover this.
