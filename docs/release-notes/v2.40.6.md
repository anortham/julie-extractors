# julie-extract 2.40.6

This patch removes an unnecessary SQLite configuration write when opening an already-configured shared-store writer.

- Reader acquire and release no longer rewrite the existing incremental auto-vacuum setting during connection setup.
- Reader protection, FULL durability, checkpoint behavior, initialization, and setting validation remain intact.
- In a paired Miller CLI measurement, inspect median improved from 347 to 313 ms, about 10%. Latency spikes remain; this does not eliminate all reader-registration overhead.
- No parser, schema, extraction-identity epoch, or CLI contract changed.

The regression test proves that opening an initialized coordinator does not commit a database change. Linux default tests and Windows connection, coordinator, and reader-registration verification passed on the behavioral source.

Details and raw samples: [reader setup write regression](../evidence/2026-09-06-reader-pragma-cost.md).
