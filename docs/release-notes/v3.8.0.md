# julie-extract 3.8.0

classification: compatible

Minor release with two extraction changes: the argument count of each call,
and Rust type facts that no longer hold cut signature text. The SQLite schema,
the report schema, and the extraction identity epoch are unchanged. The full
rules are in the 3.8.0 section of `docs/contracts/extraction-output-changes.md`.

## Added

- Every `call` identifier in Python, JavaScript, TypeScript, TSX, Java, C#, Go,
  Rust, Kotlin, C, and C++ whose call node has an argument list gets
  `metadata_json.arg_count` at the `full` extraction level: the number of
  arguments written in that call's own list. A keyword or named argument
  counts as one.
- `metadata_json.arg_spread` is `true` when one argument is a spread or splat
  (`*x`, `**x`, `...x`, `x...`, Kotlin `*x`). The count then counts the spread
  as one argument, so the real count is unknown.
- A key is right or absent. These calls get no key: a call whose node holds a
  syntax error, a TypeScript, TSX, C#, Kotlin, C, or C++ call whose comma an
  angle-bracket reading can move (`f(g<A, B>(1), 2)`), a C# call with a
  preprocessor directive line inside it, and a call with an empty argument
  slot. A C or C++ macro that expands to several arguments counts as written.

## Fixed

- The Rust extractor no longer writes `type_facts` rows cut out of signature
  text. A type with no base name (a slice, array, closure, `impl Trait`,
  function pointer, or a reference to one) gave rows such as `&[Box<dyn`,
  `&mut`, `impl`, or `[u8;`. These symbols now have no row, as the AST
  recorders already decided. Only rows are removed; no Rust row is added or
  changed. The corrupt-type count of a code-kb scan goes from 60 to 0.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `rust-type-fact-base-names-v1` and `call-argument-counts-v1`.
- Existing readers remain compatible: the new keys are optional and merge into
  the same `metadata_json` object as `receiver` and `receiver_qualifier`.
- Incremental commands require the same producer version. Refresh a 3.7.2
  artifact with `julie-extract scan --root <dir> --db <path> --force` before
  incremental use with 3.8.0.
