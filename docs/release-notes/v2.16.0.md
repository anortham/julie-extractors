# v2.16.0

This feature release completes the deferred HTTP client-request lane
(plan 2026-07-03 section 2b): Kotlin, PHP, Elixir, and Rust now emit
`http.client_request.v1` facts for their major client libraries, hardened
through three independent review rounds (two multi-agent workflow reviews and
a Codex cross-model pass) with every confirmed finding fixed and
regression-tested.

## New client-request coverage

- **Kotlin**: OkHttp (`Request.Builder()` chains), Retrofit (verb
  annotations, including fully-qualified `@retrofit2.http.GET`), Spring
  `WebClient` and `RestTemplate` (typed-param, primary-constructor,
  exact ctor-chain, and same-file local-assignment receiver proofs), plus the
  existing Ktor client now behind a full `HttpClient` receiver proof.
- **PHP**: Symfony HttpClient (`request(verb, url)` with parameter-type
  receiver proof and `HttpClient::create()` chains), cURL (`curl_init` /
  `curl_setopt` handles, including top-level script code and handle reuse),
  and Guzzle two-argument `request()`/`requestAsync()` with receiver proof.
- **Elixir**: Tesla, HTTPoison, Finch, and OTP `:httpc` (exact atom receiver).
- **Rust**: hyper `Request::builder()` chains (parser-backed `use hyper`
  gating, including `pub use` re-exports) and ureq free functions; reqwest
  proofs tightened to the `reqwest` crate qualifier and `use reqwest::Client`
  imports.

## Precision hardening (M2)

All collectors follow the "false positive is worse than a miss" rule with
parser-backed import gates and proven receivers. Notable fixes over the
in-flight lane: uppercase DSL calls no longer read as ktor verbs, unanchored
type-name matches (`WebClientFactory`, `AcmeHttpClient`, `\Aws\Client`) no
longer prove receivers, PHP receiver proofs are ordered and closure-scoped,
and a stale `ktor_routes` golden that encoded `map.get(...)` as a client
request was corrected.

## Contract

- `capabilities.json` records the residual silences as narrowed `open_gaps`
  entries: instance/field receivers (kotlin, php, rust), Tesla middleware
  base URLs, and Elixir alias resolution.
- ADR 0007 settles cURL emission as configuration-based (consistent with the
  OkHttp/hyper constructed-request semantics).
- Shared HTTP verb tables (`verb_for_lower_method` / `verb_for_token`)
  replace five per-collector copies; the sqlite-contract frontend-pattern
  guard now derives from the registry SPECS instead of a hardcoded list.

## Known limitations (recorded as open_gaps)

- Struct-field / DI-provided / cross-file client receivers stay silent in all
  four languages (M2).
- Elixir module receivers match literal alias names; `alias ... , as:` is not
  resolved.
- Kotlin file gates remain content-needle based; emission is receiver-proof
  gated, so a comment-opened gate alone cannot emit.
