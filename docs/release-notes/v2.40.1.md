# julie-extract v2.40.1

classification: compatible

This patch fixes first-reader activation on an existing family store when an
expired request was left claimed by a dead process. In 2.40.0 that abandoned claim
could make every activation attempt return `busy`, even after its deadline passed.

## Upgrade recovery

Reader-floor activation now uses the same transactional dead-requester cleanup as
normal maintenance. Cleanup still requires an expired request deadline and a
definitively dead requester. A claimed request also requires a dead claimant.
Live owners, unknown identities, and unexpired or absent deadlines retain their
requests. A live writer blocks activation and rolls back the attempted cleanup.

This is request-queue recovery, not reader-pin expiration. Reader registrations
remain protected under the existing liveness and ownership rules. No schema,
extraction identity, report contract, or permanent writer-floor version changes.
The reader-capable writer floor remains 2.40.0.

Miller's accompanying bootstrap correction retries unambiguous reader-admission
`busy` responses through its existing retry mechanism. Consumers must still treat
incompatible/corrupt stores and uncertain acquire results conservatively. Upgrade
both producer and consumer for automatic recovery through temporary contention.

## Verification

The new expired-dead-request regression failed with `MaintenanceBusy` before the
fix and passed afterward. Preservation coverage includes live claimants and
requesters, unknown requester identity, unexpired/absent deadlines, and rollback
when a live writer blocks activation. The four activation tests passed on Linux
and Windows. Linux registration and maintenance scopes passed 74 tests, with two
existing opt-in/helper skips. Full release gates are required before publication.

The failure was found during Miller's first live 2.39-to-2.40 restart. A normal
supervised import recovered that store without manual SQLite edits or reader
termination. This patch makes subsequent eligible activation attempts recover the
abandoned request directly.
