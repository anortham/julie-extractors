# julie-extract v2.35.0

v2.35.0 is the compatible minor candidate until the release workflow succeeds.

classification: compatible

## Store view retirement

- New verb: `store maintain retire-view --view <id>` removes one named dead
  view from a family store. With `--apply` it deletes the view's manifest
  entries, its manifests, and its `views` row in one store transaction; without
  `--apply` it returns a pure plan and modifies nothing.
- Retirement is caller-named, never inferred from a missing root. The verb
  keeps every family allocator mark, store-log row, request receipt, and
  consumer cursor, so a later view can never reuse a retired identity.
- The versions the view released are not deleted by the verb; they become
  ordinary GC candidates for a later `gc --apply` run.
- Refusals: an absent view is `invalid_arguments` with code `view_not_found`;
  a queued or claimed coordinator request that names the view is `busy`. The
  verb takes the same maintenance fence and stale-plan validation as `gc`,
  `repair`, and `promote`.
- Contract text: [cli.md](../contracts/cli.md) and
  [store-v1.md](../contracts/store-v1.md).
