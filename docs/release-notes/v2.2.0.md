# v2.2.0

This minor release adds the v3 extraction artifact contract for downstream
tools that need structural facts, cross-language complexity metrics, and a
documented normalized body hash contract.

## Features

- Adds `structural_facts` as a versioned SQLite row domain and
  `structural_fact` JSONL record kind for parser-backed structural query facts.
- Adds `complexity_metrics` as a versioned SQLite row domain and
  `complexity_metric` JSONL record kind for conservative file and symbol
  complexity metrics.
- Publishes structural fact and complexity metric capability evidence through
  persisted capability rows and `julie-extract languages --json`.
- Documents `body_hash` as `julie-normalized-body-md5-v1`, including whitespace
  and comment normalization rules.
- Adds `cargo xtask performance writer-current-schema` as non-default release
  evidence tooling for current-schema SQLite writer performance.

## Fixes

- Rejects old extraction contract versions consistently instead of reading v2
  artifacts as if they were v3 artifacts.
- Preserves JSON report compatibility by bumping `report_schema_version` to `3`
  after adding v3-only row count domains.
- Normalizes VB.NET `REM` comments case-insensitively for `body_hash`, including
  bare `REM` lines and inline `: REM` comments.

## Contract Changes

- Rust package versions change from `2.1.3` to `2.2.0`.
- SQLite schema version changes from `2` to `3`.
- Artifact integer `extract_contract_version` changes from `2` to `3`.
- JSONL schema version changes from `2` to `3`.
- JSON report schema version changes from `2` to `3`.
- Rust crate `EXTRACTION_CONTRACT_VERSION` changes to
  `2026-06-03.ecmascript-swift-shape-v3.source-regions-v1.structural-facts-v1.complexity-metrics-v1`.
- Parser dependency versions are unchanged.
