# julie-extract 3.6.1

classification: compatible

This patch fixes the signature of a Python instance attribute. The change is
declared in [the extraction-output
ledger](../contracts/extraction-output-changes.md) under `3.6.1`.

## Fixed

- A `self.x = ...` assignment in a method is a `property` row of its class.
  Its signature dropped the receiver, so `self.cli = cli.AppGroup()` in
  `Flask.__init__` read as the class attribute `cli = cli.AppGroup()`. The
  signature now keeps `self.`, also for annotated targets
  (`self.debug: bool = False`) and tuple targets (`self.a, self.b = pair`).
  JavaScript (`this.x`), Lua (`self.x`), and Ruby (`@x`) already keep the
  receiver.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `python-instance-attribute-signature-v1` because canonical rows change.
- Only the `signature` column of these Python rows changes. Names, kinds,
  parents, spans, and ids stay the same.
- Replace the binary and rebuild affected artifacts. No schema migration is
  required.
