# v2.23.0

This release makes large real-world repositories indexable. julie-extract 2.21.0 could not index
dotnet/runtime (58,366 files) at all: it aborted with a stack overflow at default thread stacks,
leaked a 15.4 GB scan spool, and — at larger thread stacks — failed the entire artifact import
non-recoverably on a reference-site identity conflict, writing zero rows and reporting the single
word `failed`. All of those are fixed, and the artifact write path that remained after the fixes
was rebuilt so the same repo now imports in roughly an hour of write time instead of multiple
hours. The work is independent of v2.22.0's process-lifecycle flags; both ship here together.

Full measurement record:
[`2026-08-02-scale-fixes-validation.md`](../findings/2026-08-02-scale-fixes-validation.md).

## Recursion guards (stack-overflow abort)

Every CST walker is now bounded by the shared traversal budget, including the Blazor navigation
walkers that run on every C# file and the complexity-metrics walker. Hitting the cap records a
`depth_truncated` row in `parse_diagnostics` (additive kind value) instead of capping silently. The
rayon extraction pool takes an explicit 16 MiB worker stack so behavior no longer depends on the
caller's `RUST_MIN_STACK`. A convention test fails the build on any new production walker that
recurses over children without the guard.

## Reference-site identity (import abort)

Two extraction passes could disagree about a reference site's `containing_symbol_id` and trip a
BEFORE INSERT guard that aborted the whole single-transaction import. Two root fixes: PowerShell's
identifier pass no longer filters containment to multi-line symbols, so a one-line
`function F { G }` resolves the same way in every pass; and the shared containment helper now
applies a deterministic total order (start_byte, then symbol_id) so input iteration order cannot
change the winner. The guard itself is demoted from a fatal abort to **first write wins**: the
import commits and the scan report carries a recoverable `reference_site_payload_conflict` warning
per affected file, with the language, conflict count and a bounded sample of the diverging columns.
Per-row attribution is unaffected — `identifiers` and `pending_relationships` carry their own
containing/caller columns.

Known residual: on dotnet/runtime, 4,237 conflicts across 28 files — all C — still take the
first-write-wins path. They are recoverable warnings, not failures; routing the containment
helper's own-scope decision is the named follow-up.

## Scan spool (disk amplification)

Per-identifier `code_context` is no longer emitted: it was write-only weight that no consumer ever
read. The spool is re-framed from one JSON object per line to length-prefixed binary frames with a
spool-local intern table for repeated hash ids, and the import streams rows instead of re-parsing
the whole spool three times. Measured 6.97x smaller on a dense subtree and 7.3x smaller on a full
dotnet/runtime scan (3.2 GiB peak, against a ~25 GB projection for 2.21.0). **JSONL export emits
`null` for `identifier.code_context`** — the field remains in the schema.

## Artifact write

`artifact_write` is split into additive `artifact_write_*` JSON profile keys (`plan`,
`file_symbol_insert`, `child_rows`, `resolution`, `index_build`, `foreign_key_check`, `commit`,
`wal_checkpoint`) that partition the phase. A fresh-artifact bulk-load mode defers secondary-index
creation and relaxes journal pragmas for the initial build only, restoring WAL and checkpointing
before finishing; it is gated on an empty artifact and never activates on `update`, `delete`, or an
incremental scan.

Bulk load originally collapsed at the tens-of-millions-of-rows scale: with
`defer_foreign_keys=ON`, SQLite searches every child table referencing a parent on each parent
INSERT, and the dropped secondary indexes were exactly the indexes backing those 16 foreign-key
columns — a full scan per insert, quadratic overall. The fresh bulk load now runs with
`foreign_keys=OFF` and replaces deferred per-row enforcement with something stronger: a whole-DB
`PRAGMA foreign_key_check` after the index rebuild, inside the transaction, before COMMIT. Any
violation rolls the entire import back to an empty artifact. This is safe on the fresh path only
because it never deletes rows, so no CASCADE work is ever owed.

Measured on dotnet/runtime: `file_symbol_insert` down 99.6%, process CPU time down 71%, peak RSS
20.97 GiB (from 30.6), and a complete 22.84 GiB artifact whose 24 tables carry row-for-row
identical content (53,479,352 rows, including 15,515,252 `reference_sites`) versus the pre-fix
branch baseline. On an ordinary repo (Miller, ~1,700 files) the cold scan drops from 44.2 s to
22.1 s, with `artifact_write` down 2.23x.

## Costs at the top end

Honest numbers for the largest tier, so nobody is surprised: a 58k-file, 2.58M-symbol repo still
costs roughly 65–70 minutes of write time on an M2 Ultra (measured 1 h 55 m under heavy external
CPU contention), ~21 GiB peak RSS, and a `foreign_key_check` pass of ~5.5 minutes at 22.84 GiB
(scales with artifact size). Resolution throughput also decays monotonically as the artifact grows
(45 → 6 MB/min across the run, present before and after these fixes); the savepoint sub-journal
under `temp_store=MEMORY` is the named suspect and resolver optimization is tracked as follow-up
work. Typical repos are far below all of these numbers.

## Diagnostics

The non-JSON report path now prints one `code: message (path)` line per error and warning plus a
`files: scanned=N changed=N unchanged=N failed=N` counts line, instead of a bare status word. Exit
codes and the `--json` payload are byte-identical to before.

## Contracts

- SQLite schema version unchanged (5); only the catalog fingerprint moves, for the trigger DDL.
- `extract_contract_version` unchanged (4); JSONL schema unchanged (4) — `identifier.code_context`
  is now always `null`.
- New additive values consumers should tolerate: `parse_diagnostics.kind = 'depth_truncated'`,
  report warning code `reference_site_payload_conflict`, and the `artifact_write_*` profile keys
  above.
- Parser dependency pins unchanged. No new language; the 38-language inventory is untouched.
