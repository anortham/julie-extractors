# v2.0.0

Status: release target selected before publication. No v2.0.0 release assets have
been published from this repository yet.

## Version Rationale

This standalone product starts at v2.0.0 because the old in-tree Julie extractor
crate had already reached v1.22.0. Starting below that line would make the
standalone product look like a downgrade even though it owns the future
`source tree -> versioned extraction artifact` contract.

## Shipped Product Surfaces

- CLI: `julie-extract scan`, `update`, `delete`, `info`, `export`, and
  `languages`.
- SQLite artifact contract: v1, primary durable output.
- SQLite artifacts persist parser inventory and language capability snapshot
  rows.
- JSONL export contract: v1, secondary export and streaming format.
- JSON report contract: v1 reports for CLI automation.
- Rust crate: secondary in-process extraction API.

## Package Contents And Staging

The release package manifest is generated by:

```bash
cargo xtask release package-list
```

Packages contain:

- `dist/{target}/julie-extract{exe_suffix}`
- `dist/{target}/julie-extract{exe_suffix}.sha256`
- CLI, SQLite, JSONL, and report contracts
- product-boundary and schema-principles docs
- testing and release docs
- this release note

Package staging command:

```bash
cargo xtask release package --version 2.0.0 --target <target> --out-dir <path> --binary <path>
```

The `Release Binaries` workflow publishes GitHub Release assets for:

- Linux x86_64: `x86_64-unknown-linux-gnu`
- macOS Apple Silicon: `aarch64-apple-darwin`
- macOS Intel: `x86_64-apple-darwin`
- Windows x86_64: `x86_64-pc-windows-msvc`

Linux and macOS assets are `.tar.gz` archives. Windows assets are `.zip`
archives.

## Known Boundaries

- This repo does not ship Julie MCP/server/daemon/search/embedding/watcher,
  dashboard, or editing behavior.
- JSONL is secondary to SQLite.
- The CLI is the primary integration surface; Rust APIs are secondary.
- Artifacts do not include complete source file contents; consumers should read
  the matching source tree when full file text is needed.
- The GitHub workflow publishes GitHub Release assets. Package registry
  publication is not part of these notes.
