# julie-extract v2.25.0

Two-level extraction release: `scan --level symbols|full`. A `symbols`-level
scan builds the servable symbol core — files, symbols, annotations,
diagnostics, relationships, pending arms, relationship/pending reference
sites, type facts, complexity metrics — and skips the identifier walk plus the
region/facts collectors entirely. On the dotnet/runtime yardstick (41,406
indexed files) a symbols first build completes in **3.9 minutes against 23.7
for full** (6.1×) at a 73% smaller artifact, with symbol/file/relationship
counts identical to the full build. Consumers converge to full later with an
ordinary force rebuild.

## The level contract

- `scan --level symbols|full` sets the extraction level **for a NEW artifact
  only**. `full` is the default and emits no flag from consumers — full-level
  argv is byte-identical to v2.24.0 and works against older binaries.
- The level is recorded as `artifact_metadata.index_level` and is **immutable
  per artifact**: a scan or update against an existing artifact inherits the
  recorded level; passing a conflicting `--level` is a usage error (exit 2)
  telling the caller to rebuild into a fresh artifact. `--force` does not
  license an in-place level change.
- Absent key reads as `full`: pre-levels artifacts ARE full-level artifacts,
  and older binaries reading a `symbols` artifact see a valid v5 schema with
  empty reference tables.
- At `symbols` level the gated domains — identifiers, identifier resolutions,
  literals, type-argument usages, type arguments, source regions, structural
  facts — are empty by construction; every kept domain is row-identical to a
  full build of the same tree. The gate lives in the shared registry dispatch
  with `ExtractionResults::strip_to_symbols_level` as the single parity
  authority, so the level is uniform across all supported languages.
- The resolution hook still runs at symbols level (pending relationships
  resolve; `reference_resolution_status` reaches `complete`).

## Level identity is race- and forward-proof

Two hardening changes from the adversarial review of the levels branch:

- The level is established exactly once, **inside the write transaction**. A
  scan decides its level before its transaction begins — possibly before the
  artifact exists — so a concurrent scan can commit a different level first.
  The writer now verifies the recorded level at write time and aborts the
  whole write with the new `ArtifactWriteError::IndexLevelConflict` (CLI:
  `usage_error`, exit 2) instead of restamping the artifact around rows
  planned under another level. The non-spooled `write_scan` family stamps the
  staged level through the same guard.
- An artifact recording an `index_level` this binary does not recognize fails
  **closed**: scan and update return `schema_incompatible` (exit 3, details
  carry `artifact_index_level`) instead of silently treating the artifact as
  full and extracting full-level rows into it — the forward-compatibility
  trap when a newer julie-extract built the artifact.

## Contract changes

- New `scan` flag: `--level <symbols|full>` (clap-validated; conflicts with an
  existing artifact's recorded level are `usage_error` exit 2).
- New `artifact_metadata` key: `index_level` (`symbols` | `full`; absent =
  full). Scan/update reports carry `artifact.index_level`.
- New `ArtifactWriteError::IndexLevelConflict { recorded, staged }`, surfaced
  as `usage_error` exit 2 with both levels in details.
- Unknown recorded `index_level` on scan/update: `schema_incompatible`,
  exit 3.
- Schema/catalog untouched: no table or index changes, no schema-version bump;
  a symbols artifact is a valid v5 artifact with empty gated tables.

## Evidence

Branch gates at the released tree on rustc 1.97.1: `cargo fmt --check`, clippy
`-D warnings` (workspace, all targets), `cargo test -p xtask`,
`cargo xtask test default` (3,238 extractor tests), `cargo xtask test
contract` (93, including six level contract tests: symbols core build,
kept-domain parity vs full, inherit + conflict semantics, default-full,
update-at-level, unknown-level fail-closed) and the writer race-guard contract
test. End-to-end validation on dotnet/runtime with production argv: symbols
first build 234 s / 5.47 GiB vs full 1,422 s / 20.41 GiB with identical
symbol/file counts; a subsequent full-level force rebuild converged to a
baseline-identical full artifact (12,856,606 identifiers) in 21.7 minutes
while the symbols artifact stayed the served file; a SIGKILL mid-upgrade left
the served artifact intact (integrity check clean, level and counts
unchanged). Recorded in Miller's
`docs/findings/2026-08-03-progressive-levels-p3-validation.md`.
