# julie-extract 3.11.0

classification: compatible

Annotations now survive extraction at the `references` level. Variable and
member identifiers gain optional access facts for consumers that distinguish
written assignments from reads.

## Added

- `identifiers.metadata_json.access` records `write`, `read_write`, or `read`
  when syntax classifies the site. A missing key means unclassified.
- Assignment targets and pattern bindings have reference rows when no
  declaration symbol already represents that site. Symbol declarations do
  not gain duplicate identifiers.
- The capability snapshot records `identifiers.access` support with golden
  fixture evidence in `kind_coverage.identifier_metadata`.

## Changed

- `symbol_annotations` rows are available at `references` and `full`.
  `symbols` and `facts` still omit them; complexity metrics remain `full` only.

## Compatibility

SQLite schema remains 8, report schema remains 3, extracted-data contract
remains v4, and extraction identity epoch remains 10. The contract markers are
`annotations-at-references-v1` and `variable-write-sites-v1`. Existing readers
can ignore the optional access key and read annotations with their existing
shape.

Refresh an artifact from 3.10.0 with `julie-extract scan --root <project> --db
<artifact.db> --force` before incremental use. See
[the extraction-output ledger](../contracts/extraction-output-changes.md#3110)
and [variable access facts](../contracts/extracted-data-v4.md#variable-access-facts)
for the contract.
