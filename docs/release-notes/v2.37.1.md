# julie-extract v2.37.1

v2.37.1 is the current published release.

classification: compatible

This release makes MSBuild and .NET project XML files first-class extraction
inputs. Repositories built on the .NET toolchain carry their build graph,
package references, and resource declarations in these files, and until now
`scan` dropped every one of them as an unsupported extension.

## MSBuild and .NET project XML extensions

The xml language spec now claims eight more extensions: `csproj`, `props`,
`targets`, `vbproj`, `fsproj`, `slnx`, `nuspec`, and `resx`. Files with these
extensions route through the existing tree-sitter XML extractor and publish
the same data-language facts as `.xml` files: symbols, structural facts,
source regions, and the other schema 7 tables. `sln` stays unclaimed because
the classic solution format is not XML. The capability snapshot mirrors the
extension list, and focused tests cover detection and extractor routing.

## Compatibility

Artifacts stay schema 7, JSONL stays contract v5, family stores stay store
schema 2, and store format epoch stays 1. Extraction identity epoch advances
to 7 so paths recorded as `unsupported` by earlier scans re-enter extraction.
No table, column, or JSONL field is added, removed, or renamed; a reader
built for v2.37.0 reads the new output unchanged. Replace the binary and
re-extract source trees, or let epoch-7 family-store file versions populate
on the next import or update.
