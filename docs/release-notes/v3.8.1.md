# julie-extract 3.8.1

classification: compatible

Patch release that skips unnecessary call-argument processing in reduced
extraction levels and clarifies the 3.8.0 compatibility notes.

## Fixed

- `symbols` and `facts` scans no longer compute call-argument metadata that
  those levels discard. `full` scans continue to publish `arg_count` and
  `arg_spread` with the same rules as 3.8.0.
- The 3.8.0 extraction-output notes now distinguish Rust `type_facts` removals
  from call-identifier metadata additions and label the Rust comparison with
  the published version.

## Compatibility

- Extraction output and parser dependencies are unchanged from 3.8.0.
- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` is unchanged.
- Incremental commands require the same producer version. Refresh a 3.8.0
  artifact with `julie-extract scan --root <dir> --db <path> --force` before
  incremental use with 3.8.1.
