# julie-extract 2.42.3

classification: compatible

This maintenance release avoids retaining scan-only source snapshots, skips an
unneeded data-loss-guard query for successful files, and adds an opt-in writer
performance-floor command with a manual workflow.

## Compatibility

- SQLite artifact schema remains 7, JSONL export contract remains v5, report
  schema remains 3, and family-store schema remains 2.
- Extraction contract and identity epoch remain unchanged; existing artifacts
  and unchanged files do not require migration or re-extraction.
- Emitted facts, identifiers, JSON shapes, parser inventory, fixtures, and
  external dependency graph are unchanged.

## Performance evidence

- An isolated release-binary scan workload improved from 17.86 s to 17.02 s
  median wall time after scan-only snapshot-cache retention was removed. The
  result is workload-specific; RSS was inconclusive.
- A cargo-test-profile forced-refresh writer workload improved from 6,382 ms to
  5,964 ms median. Its overlapping samples are not a release-CLI claim.
- `cargo xtask test perf` exposes existing generous writer and JSONL throughput
  floors for manual use; it stays outside the default and contract tiers.

Full methods and limitations are recorded in
[the 2026-09-14 project review](https://github.com/anortham/julie-extractors/blob/main/docs/findings/2026-09-14-project-review.md).
