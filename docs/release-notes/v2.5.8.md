# v2.5.8

This patch release supersedes `v2.5.7`. It includes all framework route fact
work from today, preserves the release evidence and implementation plans, and
fixes review findings found during release preparation.

## Features

- Retains `aspnet.minimal_api.route_group.v1` facts for literal ASP.NET minimal
  API `MapGroup` route prefixes.
- Retains `effective_route_template` metadata on grouped ASP.NET minimal API
  route calls when a route call is made through a captured group variable.
- Retains `htmx.attribute.v1` facts for static htmx attributes in HTML and
  Razor markup.
- Retains `vue.route_reference.v1` facts for static Vue Router references.
- Retains `vue.route_definition.v1` facts for static Vue Router route objects
  with literal `path` values and optional route/component metadata.
- Retains `react.route_reference.v1` and `react.route_definition.v1` facts for
  static React Router `Link`/`NavLink`, `<Route>`, route object, and index-route
  patterns.
- Retains `nextjs.route_reference.v1` and `nextjs.file_route.v1` facts for
  static `next/link` targets and Next.js App Router / Pages Router page routes.
- Adds `nuxt.route_reference.v1` and `nuxt.file_route.v1` facts for static
  `NuxtLink` targets and Nuxt `app/pages/**` / `pages/**` page routes.

## Fixes

- Restricts React Router route-object extraction to objects supplied through
  recognized route API calls such as `createBrowserRouter(...)` and
  `useRoutes(...)`, preventing unrelated local objects with `path` fields from
  emitting route-definition facts.
- Preserves simple local route-array support such as
  `const routes = [...]` passed to `createBrowserRouter(routes)`.
- Correctly handles later `index: true` route objects even when earlier
  unrelated objects contain `index: false`.
- Excludes `pages/api/**` files from `nextjs.file_route.v1` page-route facts.

## Release Process

- Adds a source-control closeout checklist requiring the primary checkout,
  `origin/main`, and the release tag to be reconciled before a release is
  declared complete.
- Restores implementation plans and checkpoints that were present in the
  working tree during today's release-prep work.
