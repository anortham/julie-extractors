# julie-extract v2.33.3

v2.33.3 is the current published release. This is a compatible performance and reliability patch for
versioned store resolution. It keeps the existing CLI, report, schema, and store contract surfaces intact.

## Bounded incremental resolution

Eligible scoped resolutions now finalize directly from the validated predecessor and base state. The
work is bounded around changed files, touched symbols, and dependency-closed relationships instead of
rebuilding unchanged resolution rows. Batched coverage reads, fixed statement reuse, request-local
validated-base proof reuse, and the existing crossover decision remove repeated work without disabling
relationship extraction or the forced-full escape hatch.

The guarded production-volume replay improved from 148.431 seconds to 54.814 seconds. The official
three-run release performance gate reported medians of 29,522 ms for full resolution and 11,002 ms for
scoped resolution, with zero semantic, applied-row, and row-level differences between the incremental
and full oracles.

Those measurements cover the incremental path. A cold full index remains expensive; this release does
not make a claim that first-time whole-repository extraction is fast.

## Unchanged imports stay unchanged

No-change imports avoid creating unnecessary store work, and byte-identical imports reuse the validated
current manifest before file-version materialization. Idempotency, unchanged output, and import report
behavior remain the same; this patch does not add a new import mode or public report field.

## Recovery and fencing remain authoritative

The direct scoped path writes the existing base-relative resolution format and keeps the established
integrity, count, completeness, crash-cleanup, claim-heartbeat, writer-lease, fencing-token, and CAS
publication checks. The validated proof is private to the request, so strict standalone validation and
recovery fallbacks remain available. Existing full resolution and rebase paths continue to serve as the
exact oracle when scope is missing, unsafe, or too close to full.

## Cross-platform acceptance

Windows root identity now treats drive, UNC, and verbatim spellings as the same identity when they refer
to the same path, while preserving strict mismatch detection. Import and resolution paths retain their
platform-specific handle and supervision behavior; Linux-only test helpers remain gated to their target.

The producer acceptance evidence covers native Windows manifest, import, and resolution contracts,
Linux formatting and strict all-target/all-feature Clippy, and the rebuilt producer's Miller Scale run
(138 passed, 10 skipped).

## Compatibility

No public CLI, report, schema, or store contract version changes. Existing store files, release package
manifest entries, and consumer integration points remain compatible with v2.33.2.
