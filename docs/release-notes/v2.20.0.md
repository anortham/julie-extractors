# v2.20.0

This release extends reference resolution for C#, TypeScript, and JavaScript:
static-type receivers for TS/JS, C# locals and parameters as typed symbols, and
a precision pass that prefers a missing edge over a wrong one. Resolution
contract version moves from 3 (at v2.19.0 ship) to 6.

## TypeScript / JavaScript static-type receivers

- `TIER3_STATIC_TYPE_LANGUAGES` is now `csharp`, `typescript`, and `javascript`.
- Same-file static receivers (`Fixture.create()`) are fixture-proven for TS/JS.
- Cross-file static edges require import corroboration: the receiver must bind
  an import whose resolved module is the type's defining file.
- Type-only imports (`import type` and `import { type X }`) never authorize
  runtime static members.
- Interfaces and type aliases are not static receivers in module languages
  (runtime value types only: class and enum).
- Export-aware TypeScript visibility: exported declarations are `public` so
  cross-file static reachability can bind; non-exported helpers stay unreachable
  across files.
- Members carry `isStatic` metadata (C#/TS/JS) with signature fallback for the
  static-type tier.

## C# locals and parameters

- Local variables and formal parameters emit as `SymbolKind::Variable` with
  `role` metadata (`local` / `parameter`) and type facts for receiver resolution.
- Covers ordinary locals, `out`/`ref`/`in` declaration expressions, `foreach`
  loop variables (including tuple deconstruction), and parameters including
  `params`.
- Identifier calls with a typed receiver use the tier-3 receiver path.
- Multiplication and other tree-sitter misparses no longer become false locals
  (e.g. `requested * Scale`).

## Precision and fail-closed module policy

Wrong edges are treated as worse than misses:

- Receiver-qualified calls no longer fall through to import Branch B or global
  uniqueness without the receiver.
- Module-wide import Branch B is removed: a named import does not authorize every
  export in that module.
- For ES-module languages (`javascript`, `jsx`, `typescript`, `tsx`), tier 4 is
  same-file only; unique unimported cross-file exports stay unresolved.
- Default imports fail closed until default-export provenance exists (no binding
  a same-named named export as the default).
- JavaScript aliased imports record `importedName` for tier-2 / static
  corroboration.
- JavaScript export visibility only considers a direct parent export statement.

## Capability gaps

- Open reference-resolution gaps: **103** (was 105 at v2.19.0): 36 tier-3
  receiver, 34 tier-2 import, and 33 tier-3 static-type rows after certifying
  TypeScript and JavaScript static-type receivers.
- `jsx` / `tsx` share ES-module fail-closed policies with JS/TS; tier-2 import
  certification remains `typescript` and `javascript` until dialect fixtures land.

## Contract versions

- Rust package versions are `2.20.0` for `julie-extract-artifact`,
  `julie-extract-cli`, and `julie-extractors`.
- SQLite schema version is 5. Unchanged.
- Extract contract version is 4. Unchanged.
- JSONL schema version is 4. Unchanged.
- Resolution contract version is **6**, raised from 3 at v2.19.0 ship (intermediate
  producer builds used 4 and 5 during this development).

## Consumer note

No schema migration is required. Rescan to pick up C# local/parameter symbols,
TS/JS static-type edges, and import metadata. A stale
`reference_resolution_version` forces a full re-resolution pass automatically.
Consumers should expect fewer wrong cross-file edges on TS/JS and more C#
`variable_ref` / receiver-typed rows after rescan.
