# v2.17.0

This feature release closes the reference-resolution gaps required by Miller's
deterministic code-navigation workflows. Resolution metadata is now version 2;
SQLite schema v4, extract contract v3, and JSON report schema v3 remain
the same version numbers.

## Safer reference resolution

- `variable_ref` resolves through its lexical scope chain or a unique compatible
  same-file value symbol and never falls through to workspace-global name
  matching.
- Receiver-qualified `member_access` uses receiver evidence only and never
  falls through to the global tier.
- Identifier metadata preserves receiver context for `.`, `?.`, `->`, and `::`
  member separators.
- Confidence remains bounded by the source evidence confidence, and direct
  relationships retain their producer confidence.
- Structured pending evidence is matched by compatible kind and the narrowest
  containing occurrence; conflicting receiver evidence is discarded instead of
  guessed.

## Exact occurrence evidence

- Relationships carry normalized source spans when the producer can identify an
  exact occurrence.
- Relationship identity includes every span coordinate, preserving repeated
  same-line occurrences as separate evidence.
- A language-agnostic fallback supplies a missing relationship span only when
  exactly one compatible target identifier occurs on that line.
- Golden fixtures now serialize direct and pending relationship spans.

## Coverage and reporting

- The new
  `fixtures/extraction/reference-resolution-coverage.json` artifact covers all
  36 supported languages and 689 exact cells across language, origin, raw and
  canonical kind, outcome, tier, method, span state, and applicability.
- Coverage reports distinguish `identifier`, `relationship`, and
  `pending_relationship` origins and record canonical kind, outcome, tier,
  method, span state, and count.
- The strict coverage gate fails on language-registry drift, stale fixture
  digests, canonical-kind vocabulary drift, unmapped canonical kinds, missing
  summaries, silent cells, invalid per-cell counts, invalid pending-kind
  outcomes, or resolved identifiers outside the live method vocabulary.
- The release gate records zero silent cells and zero quality-bar debts.

## Precision fixes

- CSS animation references retain parsed segment offsets, including
  prefix-colliding names.
- Razor and GDScript fallback relationships point to exact namespace or
  base-class occurrences.
- Vue template references retain their regex occurrence offsets.
- Multi-record normalization offsets structured-pending spans together with
  every other source-coordinate domain.

## Consumer note

A normal whole-workspace scan detects a missing or stale resolution version and
automatically re-extracts every supported file before stamping version 2.
`update` and `delete` fail with `schema_migration_required` until that scan has
completed. A new database path or explicit `julie-extract scan --force` remains
a valid upgrade path. A successful automatic migration emits the
`resolution_upgraded` warning. If any preserved source row cannot be
re-extracted or the resolution pass fails, the scan fails visibly and
single-file mutations remain blocked until a complete scan succeeds.
This fail-closed rule also applies after migration: a resolver-hook failure
during a routine `update` or `delete` records
`reference_resolution_status = failed`, and all later single-file mutations
return `schema_migration_required` until `julie-extract scan` succeeds.

- Consumers that gate reference metadata must accept
  `reference_resolution_version = 2`. The stamp is written by the resolution
  pass, so consumers must still use a 2.17-or-newer binary's completed
  whole-workspace scan as the upgrade boundary rather than rewriting metadata
  themselves.
- JSON report schema v3 now adds `totals` and `origin_totals`; its
  `languages.reference_resolution.by_language` rows include all three evidence
  origins plus `unattempted` and `unresolved_pending` outcomes. Resolution rates
  must use the attempted totals within one `origin_totals` entry rather than the
  full evidence-row count. Totals overlap because one source occurrence can
  produce both identifier and pending evidence.
- JSONL schema v3 and SQLite schema v4 remain unchanged, but both expose the
  resolution version 2 metadata.
- Span-bearing relationship IDs change because their stable identity now
  includes all six span coordinates. Structured pending IDs can also change
  when multi-record normalization offsets their spans. Consumers must not
  retain version 1 relationship or pending IDs across the upgrade scan.

## Known limitations

- All 2,212 identifier rows and 224 direct relationship rows in the certified
  fixture corpus carry spans. Pending relationships carry 394 spans across 832
  rows; the remaining 438 are explicitly span-missing rather than inferred.
- The coverage corpus contains 794 unresolved pending rows. Pending
  `imports` and `references` are intentionally reported as unattempted because
  the resolver does not assign those origins a target.
- The conservative variable and receiver-qualified member policies prefer a
  miss over a workspace-global name guess.

## Certification and package contract

- Rust package versions are `2.17.0` for `julie-extract-artifact`,
  `julie-extract-cli`, and `julie-extractors`.
- Parser dependencies and the certified grammar inventory are unchanged from
  2.16.0.
- The strict reference-resolution coverage artifact contains 36 languages, 689
  exact cells, 3,268 evidence rows, zero silent cells, and zero quality-bar
  debts.
- Default, contract, golden, strict data-quality, Clippy, release build,
  package-list, and four-target release-preflight gates pass.
- Release packages retain the existing manifest and SHA-256 checksum contract;
  published archive digests are verified from the live release assets after
  the four-platform workflow completes.
