# julie-extract 3.6.3

classification: compatible

This patch fixes five JavaScript, TypeScript, and C++ parity gaps and adds the
endpoint name to Flask route facts. All six are declared in [the
extraction-output ledger](../contracts/extraction-output-changes.md) under
`3.6.3`.

## Fixed

- `x instanceof MyClass` recorded `MyClass` as a plain value read in JavaScript
  and TypeScript. It is now a type usage, as the class argument of a Python
  `isinstance` call is.
- A decorated TypeScript class, method, or property kept only the decorator
  names: `@Controller class UsersController`. Each decorator now keeps its
  arguments, on one line: `@Controller('users') class UsersController`.
- C++ anonymous unions were named `<anonymous_union_602>` from the zero-based
  row. They are now `anonymous_union_603`, like anonymous structs.
- A JavaScript constructor assignment `this.x = value` was dropped when the
  class also had a getter or setter named `x`. It now has its own row.
- TypeScript constructor assignments `this.x = value` had no rows. They are now
  property rows with visibility and doc comments, as in JavaScript.

## Added

- A Flask route fact records a literal endpoint name in the optional
  `endpoint` metadata key. `app.add_url_rule("/", endpoint="index")` now says
  which endpoint the rule names, so a reader can tell it from a view route.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `ecmascript-instanceof-type-usage-v1`,
  `typescript-decorator-signature-arguments-v1`,
  `cpp-anonymous-union-naming-v1`, `javascript-property-init-coexistence-v1`,
  `typescript-constructor-assigned-properties-v1`, and
  `flask-route-endpoint-v1` because canonical rows change.
- A reader that matched a TypeScript signature by the bare decorator name must
  accept the decorator arguments.
- Replace the binary and rebuild affected artifacts. No schema migration is
  required.
