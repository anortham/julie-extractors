# julie-extract 3.12.0

classification: compatible

This release corrects extraction facts across the audited language set. The
validation matrix closes 47 local defects across 42 languages and 630
language/domain cells.

## Changed

- Declaration bodies, parameter spans, and body hashes now follow the syntax
  that owns them. Hash normalization follows syntax, so comments and formatting
  do not change hashes while literal text and delimiters remain significant.
- Access, type, and annotation facts now retain their correct source sites and
  owners. Full-level XML/XSLT extraction emits callable complexity metrics.
- PowerShell, Erlang, VB.NET, and T-SQL grammar fixes preserve source-backed
  argument, binding, annotation, routine, and DDL facts.

## Coverage

The audit records 465 passing goldens and 47 fixed defects. The 630-cell matrix
contains 545 supported claims, 82 not-applicable cells, and 3 convention-only
cells. The strict quality report has zero silent cells and zero quality-bar
debts; 11 consumer/context boundaries remain recorded. Large corpus,
certification, and timed comparison gates stay outside the default test tier.

## Compatibility

SQLite schema remains 8, extracted-data contract remains v4, report schema
remains 3, and extraction identity epoch remains 10. The extraction contract
adds `html-external-script-body-v1`, `declaration-body-ownership-v1`,
`programming-parameter-body-v1`, `language-coverage-corrections-v1`, and
`syntax-aware-body-hash-v1`. No schema migration is required. Replace the
binary and refresh existing artifacts before incremental use:

```sh
julie-extract scan --root <project> --db <artifact.db> --force
```
