# julie-extract 3.0.0

classification: breaking
artifact output: compatible

This release removes the versioned family store (the `store` command and
every nested verb) and the JSONL export (the `export` command). `code-kb` is
the sole consumer of `julie-extract`. It uses `scan`, `update`, `delete`,
`info`, `languages`, and `rebind` with the SQLite artifact and never used the
store or the export. The decision is recorded in
[the store and JSONL retirement decision](../decisions/2026-09-15-store-and-jsonl-retirement.md).

## Compatibility

- SQLite artifact schema remains 7 and report schema remains 3. The removed
  report fields were only ever populated by the removed `export` command.
- Extraction contract and identity epoch remain unchanged; existing artifacts
  and unchanged files do not require migration or re-extraction.
- `scan --level <symbols|facts|full>` values are unchanged.
- The Rust crate API of `julie-extractors` and its `syntax-api` feature are
  unchanged.
- The scan spool and progress-file formats are unchanged.
- Removed CLI commands: `store` with every nested verb (`import`, `update`,
  `delete`, `export`, `maintain inspect`, `maintain gc`, `maintain repair`,
  `maintain promote`, `maintain retire-view`, `maintain cursor advance`,
  `maintain cursor release`, `reader acquire`, `reader renew`,
  `reader release`) and `export`. The binary now rejects both as
  unrecognized subcommands.
- Removed environment variables: `MILLER_STORE_CHUNK_VERSIONS`,
  `MILLER_ALLOW_EXTRACTOR_DOWNGRADE`, and the store test hooks
  `JULIE_EXTRACT_STORE_TEST_RECORD_READS` and
  `JULIE_EXTRACT_STORE_TEST_CRASH_AT`.
- Removed report surfaces: `ReportOperation::Export`, `ReportMode::Jsonl`,
  the `artifact.jsonl_schema_version` field, the `input.format` and
  `input.output_path` fields, the `unsupported_format` and `export_failed`
  error codes, and the rule that a failed stdout export writes its report to
  stderr. No remaining command populated these fields.
- Removed contract docs: `store-v1.md`, `sqlite-store-schema-v1.md`,
  `sqlite-store-schema-v2.md`, `jsonl-v1.md` through `jsonl-v5.md`, and
  `architecture/versioned-index-store.md`. All are recoverable from git
  history at tag `v2.43.0`.
- Emitted facts, identifiers, JSON shapes, parser inventory, fixtures, and
  external dependency graph are unchanged.

## Contract changes

- The `store` and `export` commands and the "JSONL is a secondary export"
  invariant are gone from [the CLI contract](../contracts/cli.md). SQLite is
  the only durable artifact.
- The `export` operation, the `jsonl` mode, the `input.format`,
  `input.output_path`, and `artifact.jsonl_schema_version` fields, the
  `unsupported_format` and `export_failed` codes, and the stderr rule are
  gone from [the report contract](../contracts/reports.md).

## Build

- Removed cargo features: `test-store-contract` and
  `test-store-maintenance-contract` from `julie-extract-cli`;
  `test-store-crash`, `test-store-maintenance-contract`,
  `test-store-contract`, and `test-takeover` from `julie-extract-artifact`.
- Dropped dependencies: `fs4` from `julie-extract-cli`; `getrandom`,
  `rustix`, `winsafe`, and `machine-uid` from `julie-extract-artifact`.

## Default gate

Warm Linux wall clock for `cargo xtask test default`: 66 s at v2.43.0
(d75b9f8f), 14 s after the removal (f3760ade). `cargo xtask test contract`
runs in 86 s after the removal.
