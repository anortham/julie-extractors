# julie-extract 3.7.1

classification: compatible

Patch release with four extraction corrections merged after 3.7.0. The output
remains readable by 3.7.0 consumers; extraction identity and artifact schemas
do not change.

## Fixed

- C# `@$` and `$@` interpolated-verbatim strings with doubled quotes around
  interpolation expressions now parse without diagnostics. Methods and
  interpolation-variable reference facts are emitted for this valid syntax.
- Python `flask.route.v1` facts from decorators now use the route decorator's
  source span and `decorator` node kind, while remaining bound to the decorated
  view symbol. `add_url_rule` facts remain anchored at their registration call.
  Decorator-anchored facts receive new structural-fact IDs.
- Python member reads through `super().member` and
  `super(Type, self).member` now include `receiver: "super"` in identifier
  metadata. Ordinary receivers and values named `super` are not treated as
  implicit super receivers.
- An unannotated synchronous Python function gains optional
  `inferredReturnType` metadata when all returns name the same local and its
  sole dominating assignment constructs a same-file class or an explicitly
  imported class-style name. The existing `returnType` remains the explicit
  annotation, or the empty string. Ambiguous assignments, fallthrough,
  async/generator functions, and unsupported control flow omit the inferred key;
  an imported factory with a class-style name can still be classified as a
  class.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10.
- `EXTRACTION_CONTRACT_VERSION` retains
  `reference-occurrence-identity-v2`, `canonical-receiver-facts-v1`,
  `reference-integrity-v1`, and `regex-branch-reset-v1`. This release adds
  `flask-route-decorator-span-v1`, `csharp-interpolated-verbatim-v1`, and
  `python-inferred-return-type-v1`. The additional Python `super` receiver
  recognition is covered by the existing `canonical-receiver-facts-v1` marker.
- Existing artifact readers remain compatible. Re-extract existing artifacts
  with `julie-extract scan --root <dir> --db <path> --force` to obtain the new
  facts. Incremental commands against an artifact from another binary version
  report `fingerprint_mismatch` (exit code `3`) without changing rows.
- See the [versioned extraction-output ledger](https://github.com/anortham/julie-extractors/blob/v3.7.1/docs/contracts/extraction-output-changes.md)
  for the detailed output changes and consumer actions. The downloadable package
  does not bundle this ledger.
