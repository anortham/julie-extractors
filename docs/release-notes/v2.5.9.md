# v2.5.9

This patch release supersedes `v2.5.8`. It keeps the framework route fact
families from `v2.5.8` and hardens their extraction against duplicate
framework file-route facts, non-code route-like text, ASI-style imports, and
Vue Router route-array indirection.

## Fixes

- Prevents Next.js Pages Router files from emitting competing Nuxt file-route
  facts, and prevents Nuxt page files from emitting competing Next.js file-route
  facts.
- Treats `app/pages/**/page.tsx` as a Next.js App Router route segment unless
  the file has a Nuxt-specific signal, avoiding duplicate contradictory
  Next/Nuxt file-route facts.
- Makes Nuxt file-route disambiguation syntax-aware: Nuxt signals in comments
  or strings no longer suppress Next.js page routes, and generic
  `defineComponent` is no longer treated as a Nuxt-only signal.
- Fixes JSX route-attribute scanning so earlier attributes such as
  `title="Go to settings"` do not hide the real `to="/settings"` route target.
- Fixes ASI-style JavaScript/TypeScript import scanning so imports without
  semicolons do not swallow following imports and route API registrations.
- Skips React/Next route references and definitions that appear only inside
  comments or string literals.
- Excludes external React Router targets such as `https://...` from static
  route-reference facts.
- Restricts Vue route definitions to router contexts and follows
  `createRouter({ routes: appRoutes })` to the referenced route array.
- Preserves optional Next.js catch-all segment semantics as `:slug*?`.
- Adds effective ASP.NET minimal API route metadata for chained
  `app.MapGroup(...).MapGet(...)` calls.

## Release Process

- Adds `.worktrees/` to `.gitignore` so local agent worktrees can be kept under
