# v2.0.2

This is a patch release for the v2.0.x standalone extraction product line.

## Fixes

- Fixed spooled SQLite writes so foreign-key enforcement stays enabled while
  validation is deferred until transaction commit. This preserves SQLite
  `ON DELETE` cascade/null actions and still allows child symbols to reference
  parent symbols inserted later in the same scan transaction.
- Fixed `export --out - --json` failure reporting so JSONL stays on stdout and
  the failed JSON report goes to stderr.
- Fixed scan profile byte accounting for supported files that fail during
  source reads.
- Serialized the panic-hook unit test that verifies extractor panic handling.

## Performance

- Parallelized scan extraction while keeping deterministic spool ordering.
- Reduced spooled SQLite write time by resolving identifier and symbol parent
  foreign keys inline, reusing existing-file lookups, and sharing cached
  statement sets across the batch.

Current fixed release-candidate medians from three local cold
`scan --force --json` runs:

| Repo | Total | Extraction/spool | Artifact write |
| --- | ---: | ---: | ---: |
| `hermes-agent` | 10.86s | 2.89s | 7.91s |
| `openclaw` | 28.89s | 6.04s | 22.66s |

Compared with the pre-enhancement v2.0.1 profiling evidence, these medians are:

- `hermes-agent`: 65.5% faster end to end; artifact write 38.5% faster.
- `openclaw`: 68.1% faster end to end; artifact write 40.3% faster.

Immediate no-change rescans in the same validation pass were 1.31s for
`hermes-agent` and 1.21s for `openclaw`.

## Contract Changes

- CLI commands, exit codes, SQLite schema version, JSONL schema version, and
  extract contract version are unchanged.
- JSON report schema remains version 1.
- Release package contents are unchanged.
