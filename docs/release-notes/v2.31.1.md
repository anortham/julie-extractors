# julie-extract v2.31.1

Patch release for family-store migration identity.

## Imported resolution base identity

`store import --from-artifact` now derives the imported exact-resolution base ID through the same
canonical identity function used by ordinary store resolution. A later `store resolve` request therefore
recognizes and reuses the imported base instead of deriving a second identity for byte-equivalent rows.

The bug did not change extracted rows, SQLite schemas, or standalone artifact behavior. It affected the
identity bridge between a migrated v3 artifact and subsequent family-store resolution, which is required by
Miller's Ph3 migration/restart path.

## Compatibility

- Legacy extraction contract 4, standalone SQLite schema 6, JSONL schema 4, and report schema 3 are
  unchanged.
- Store contract 1, SQLite store schema 2, format epoch 1, and request/maintenance report schema 1 are
  unchanged.
- Existing v2.31.0 family stores remain readable and writable. The fix changes only the canonical ID chosen
  when importing a resolved standalone artifact.

## Verification

The resolution-adapter contract now proves that import and ordinary resolution produce the same canonical
base identity. Default, contract, formatting, strict Clippy, release preflight, and package gates remain
release requirements.
