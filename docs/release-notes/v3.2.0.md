# julie-extract 3.2.0

classification: compatible

This release makes Qt a first-class extraction family. QML files publish an
object model instead of a flat property list, qmldir type rows change kind, and
Qt's JavaScript directives no longer break a `.js` parse. Every change is
declared in
[the extraction-output ledger](../contracts/extraction-output-changes.md) under
`3.2.0`.

## Added

- A nested QML object is a `field` symbol row. Its name is the object's `id`
  when it has one, else its type name. Its signature is `id: Type`, the bare
  type, or `Type on property` for a `Behavior on color` value source. Its
  metadata carries `object_type`, `binding_kind: "object"`, and
  `value_source_property`.
- An inline component is a `class` row with the signature
  `component Name: Base`. Its members parent to it.
- A QML signal carries the signature `signal name(type arg, ...)` and a
  `parameters` metadata list.
- A bare `required property` row carries `required: true`. A file that opens
  with `pragma Singleton` marks its root symbol `singleton: true`.
- A QML root object emits an `extends` relationship to its base type. The row
  is a concrete relationship when the base type is a symbol in the same file,
  and a structured pending row otherwise.
- `identifiers.metadata_json` gains three keys: `role` (`base_type`,
  `attached_type`, or `signal_handler`), `receiver`, and `change_handler`
  (true for an `onXChanged` handler).
- Two structural-fact pattern ids: `qml.pragma.v1` (metadata `name`, `value`)
  and `javascript.qml_directive.v1` (metadata `directive`, `name`) for a
  `.pragma` line at the head of a JavaScript file. An `.import ... as Alias`
  line at the head of the same file becomes an `import` symbol.

## Changed

- A plain QML property binding such as `width: 100` is no longer a symbol. The
  same evidence stays in `structural_facts` as `qml.binding.v1`.
- A grouped property block such as `anchors { fill: parent }` emits no symbol,
  no relationship, and no type usage. Its inner bindings stay `qml.binding.v1`
  facts.
- An inline component's body extends its base instead of instantiating it. The
  `extends` row comes from the inline `class` row, not from the enclosing
  component.
- An attached signal handler names the attached type as its receiver, so
  `Keys.onPressed` carries `Keys` rather than the enclosing object's type.
- A qmldir type row's kind changes from `class` to `export`, because a qmldir
  line exports a type rather than declaring one.
- A qualified QML type usage such as `QQC2.Button` is recorded by its terminal
  name (`Button`), with the qualifier in the `receiver` metadata key. Before
  this release the whole dotted text was the identifier name.
- Qt's QML JavaScript directives (`.pragma`, `.import`) at the head of a `.js`
  file are blanked to same-length spaces before the parse, on the scan path and
  on the `julie-extract check` path. Such a file no longer reports a syntax
  error. The original text stays the source of record.
- A directive line tolerates a trailing `//` comment, so
  `.pragma library // shared` is recognised and the file still parses. A `//`
  inside the quoted source of an `.import` stays part of the source.
- A `.qmltypes` root is a module descriptor, so it records no `base_type`
  identifier.
- `EXTRACTION_CONTRACT_VERSION` gains the suffix `qt-qml-v1`.

## Compatibility

- SQLite artifact schema remains 7 and report schema remains 3. The extraction
  identity epoch remains 10.
- Every column keeps its type, so a reader built for 3.1.3 still parses the
  output. Only the QML, qmldir, and JavaScript row content moves.
- A consumer that already holds an artifact must rebuild it rather than rescan,
  because an unchanged file keeps its stored rows.
- A consumer that read QML property bindings from the symbol table must read
  them from `structural_facts` as `qml.binding.v1`.
- A consumer that read qmldir types by kind `class` must query kind `export`.
- A consumer that matched a dotted QML type name must match the terminal name
  and read the qualifier from the identifier metadata.
- A consumer that renders QML skeletons or searches QML symbols must accept
  `field` and `export` as QML symbol kinds.
- The three new identifier metadata keys are optional. A row without them keeps
  its old meaning.
- Public extractor API: `Identifier` gains an optional `metadata` field. A crate
  that builds an `Identifier` literal must add the field. A crate that reads one
  is unaffected.

## Evidence

- `cargo xtask test golden`: passes. The golden identifier record now stores
  `Identifier.metadata`, so the `role`, `receiver`, and `change_handler` keys
  are locked by `fixtures/extraction/qml/qt_symbols/expected.json`.
- `cargo xtask test contract`, `cargo xtask test capability`, and
  `cargo xtask test default`: pass.
- `cargo xtask compat-check` against the published 3.1.3 binary: every output
  difference is declared in the `3.2.0` ledger entry.
- `cargo xtask release preflight --version 3.2.0`: exit 0, 6 targets.
- Real-world corpus numbers for `plasma-framework` are in
  [the QML language document](../languages/qml.md) under `Real-world evidence`.
