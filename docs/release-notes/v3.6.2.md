# julie-extract 3.6.2

classification: compatible

This patch fixes six Python extraction defects that code-kb dogfood sessions
found on the flask repository. All six are declared in [the extraction-output
ledger](../contracts/extraction-output-changes.md) under `3.6.2`.

## Fixed

- A Python signature wrote its return annotation after a colon:
  `def wsgi_app(self, environ, start_response): cabc.Iterable[bytes]`. That is
  not valid Python. The signature now uses `->`, and the `returnType` metadata
  holds the annotation alone, as it does in PHP and Kotlin.
- A Flask route read `methods=` only from a list. A tuple or a set, as in the
  Flask tutorial's `@bp.route("/<int:id>/delete", methods=("POST",))`, gave
  one route fact with the default verb `GET`. Tuples and sets now give one
  fact for each listed method.
- `cls(...)` was always read as a call to the enclosing class. In flask's
  `Flask.test_client`, `cls` is a local variable that holds the test client
  class, so the call was recorded as `Flask(...)`. `cls` now names the class
  only when the nearest function that binds it takes it as a parameter.
- A decorated signature kept only the decorator names:
  `@bp.route @login_required def create()` lost the route and its methods. Each
  decorator now keeps its arguments, on one line:
  `@bp.route("/create", methods=("GET", "POST")) @login_required def create()`.
- An annotation with no value, such as `default_config: dict[str, t.Any]` in a
  class body, had the signature `default_config: dict[str, t.Any] = `. It no
  longer ends with ` = `.
- `isinstance(app, Flask)` recorded `Flask` as a plain value read, so a tool that
  lists the type uses of `Flask` missed it. The class argument of `isinstance`
  and `issubclass` is now a type usage.
- A lambda on line 312 was named `lambda_311`. Lambda names now use the
  one-based line that every other location uses.
- A `self.cli = ...` row in `__init__` lost the `#:` comment above it, which a
  class attribute keeps. It now keeps it as its documentation.
- `self.static_folder = static_folder` in `__init__` had no row, because the
  class also has a `static_folder` property. It now has one, so a skeleton shows
  where the attribute is first set.

## Compatibility

- SQLite schema remains 7, report schema remains 3, and extraction identity
  epoch remains 10. `EXTRACTION_CONTRACT_VERSION` adds
  `python-return-arrow-v1`, `flask-methods-tuple-v1`,
  `python-cls-binding-v1`, `python-decorator-args-v1`,
  `python-annotation-only-v1`, `python-isinstance-type-v1`,
  `python-lambda-line-v1`, `python-attribute-docs-v1`, and
  `python-property-init-v1` because canonical rows change.
- A reader that parsed the colon form of a Python return type from the
  signature must accept `->`. A reader of `returnType` no longer needs to strip
  a leading `: `.
- Replace the binary and rebuild affected artifacts. No schema migration is
  required.
