# julie-extract 2.40.2

This patch reserves the SQLite writer at the start of store-writer transactions,
before their first read. A competing writer can no longer invalidate that
transaction's snapshot between its reads and writes. This addresses a source of
`database is locked` failures during store import's ensure-view operation.

Store writer connections explicitly use a five-second busy timeout. A coordinator
regression exercises a competing connection between a quantum's read and write;
the competing writer is refused while the quantum completes successfully.

Reader registration, maintenance fencing, view identity validation, parser output,
schema versions and CLI reports remain unchanged. The reader-registration writer
floor remains 2.40.0.
