# v2.15.0

This feature release expands structural-fact coverage across SQL, PHP/Symfony,
Kotlin/Ktor, and web languages, completes the test-role detection rework for
Kotlin, fixes a destructive oversized-file path in the CLI, and hardens the
structural-fact contract surface. The registry now declares 194 patterns, all
serialized into the machine-readable contract JSON.

## Structural facts

- SQL procedure and function definition facts now report real
  `parameter_count` values. The vendored T-SQL grammar surfaces parenless
  procedure parameters as error nodes, so counting uses sigil detection
  bounded to the routine header (immune to `@@` system variables, string
  literals, local declarations, and `RETURNS` table variables).
- New `symfony.route.v1` pattern extracts PHP `#[Route]` attribute routes with
  verb, template, and class-prefix joins.
- Ktor `ktor.route.v1` now follows the family contract: `route_template`
  carries the raw verb-call literal and enclosing static `route("/prefix")`
  scopes join into `effective_route_template`. `verb` and `verb_source` are
  declared required. Detection is gated on server-side imports
  (`io.ktor.server.*`, plus Ktor 1.x `io.ktor.routing`/`io.ktor.application`);
  client-only files no longer emit routes.
- HTML `data-*` attribute facts carry distinct, deterministic ids per
  attribute (previously multiple attributes on one element collided on a
  single id and all but one row was silently dropped, nondeterministically).
- Landmark facts (`html.landmark.v1`) now emit for landmark roles on every
  element, including tags with dedicated handling (`<form role="search">`,
  media elements, form controls).
- HTML `<style>` blocks emit embedded CSS structural facts (all ten `css.*`
  patterns, language `html`), matching the existing Vue single-file-component
  behavior.
- Statement-form at-rule preludes no longer retain trailing semicolons
  (`@layer reset;` emits `layer_name = "reset"`).

## Test-role detection

- Kotlin joins the lifecycle/container rework: JUnit-annotated Kotlin code now
  emits `test_lifecycle` (`@BeforeEach`/`@AfterEach`/`@BeforeAll`/`@AfterAll`)
  and `test_container` metadata, backed by a new JUnit golden fixture. The
  capability claim is now fixture-evidenced.
- Java and Kotlin container marking propagates to ancestor classes: an outer
  class whose only test content is a `@Nested` class is itself marked. C# and
  Python markers are deliberately unchanged — their frameworks do not execute
  enclosing classes on behalf of nested test classes.

## CLI

- `update` on a supported source file that exceeds the extraction size limit
  no longer deletes the file's existing artifact rows and misreports
  `unsupported_file`; it reports the typed `slow_file_skipped` warning with
  status `no_change` and preserves rows. `scan` had the same destructive
  behavior through a different path (oversized files were treated as deleted
  files) and now preserves rows identically.
- The size limit is single-sourced as `limits::MAX_SOURCE_FILE_BYTES`,
  exported so integration tests and consumers derive from the real value.

## Contracts and registry

- The structural-fact registry moved from one 3,700-line module to family
  modules (`framework/`, `web/`, `builtins/`, `data`, `sql`, `http_client`)
  with LOC tripwires that genuinely constrain regrowth (700 per family file,
  400 for module files).
- `docs/contracts/structural-fact-patterns.json` is regenerated for the full
  194-pattern registry.
- The markdown pattern tables in `jsonl-v3.md` and `sqlite-schema-v4.md` are
  reconciled with the registry (all ten `css.*` rows list `css`, `vue`,
  `html`) and are now guarded by a registry-derived tripwire that asserts row
  presence and exact language sets for every web-markup pattern against the
  live contract docs.

## Hardening

Two adversarial review rounds ran against this release: a multi-agent review
(31 agents, 27 candidate findings independently verified) and a Codex
cross-model review. Sixteen confirmed findings were fixed with RED-first
tests; both reviewers independently cleared the HTML identity/landmark/style
and CLI oversized paths in their final state.

## Known limitations

- Parenless multi-parameter T-SQL procedures are mis-parsed by the vendored
  grammar at the routine-name level (parameters leak into the object
  reference). Single-parameter parenless and all parenthesized forms extract
  correctly.
- The markdown pattern tables document a curated subset (~79 rows) of the 194
  registry patterns; code-builtin, data, and SQL families rely on the
  machine-readable contract JSON. `razor.route_reference.v1` and
  `blazor.component_reference.v1` are declared in the registry but have no
  markdown rows yet.
- `docs/contracts/reports.md` and the frozen `sqlite-schema-v3.md` still
  reference the pre-split registry path.
