## Task 1: Nightly Schedule for Specialist Gates

**Files:**
- Modify: `.github/workflows/specialist-gates.yml`

**Interfaces:**
- Consumes: existing jobs `certification`, `real-world-smoke`, `real-world-release`, `dogfood`, `release-package` (`.github/workflows/specialist-gates.yml:16–105`).
- Produces: an automatic nightly run of the parser-certification and real-world gates.

**What to build:** Add a `schedule:` trigger (nightly cron, e.g. `0 9 * * *` UTC) alongside `workflow_dispatch`. The `release-package` job consumes `inputs.version`/`inputs.target` (`:83–105`), which are empty on schedule events — gate it with `if: github.event_name == 'workflow_dispatch'`. The `certification`, `real-world-smoke`, `real-world-release`, and `dogfood` jobs take no inputs and run on both triggers.

**Approach:** Keep dispatch behavior byte-identical for the release path. Real-world tiers clone external corpora — check the xtask real-world commands for network/corpus assumptions that could flake nightly; if `real-world-release` requires release-only preconditions, keep it dispatch-only too and say so in a workflow comment. Verify the YAML with `gh workflow view` or a dry parse; trigger one manual dispatch after merge to confirm nothing regressed.

**Acceptance criteria:**
- [ ] Nightly schedule present; `release-package` (and any release-preconditioned job) skips on schedule events.
- [ ] Manual dispatch still runs all jobs with inputs.
- [ ] First scheduled or manually-triggered run is green (or failures are real regressions, reported).
- [ ] Worker-scope verification passes, committed.

## Task 2: Collapse `registry.rs` Extractor Wrappers into a Macro

**Files:**
- Modify: `crates/julie-extractors/src/registry.rs` (the ~20 near-identical `extract_<lang>` functions: `extract_java` :198, `extract_csharp` :232, `extract_kotlin` :266, `extract_swift` :300, `extract_php` :334, `extract_scala` :368, `extract_typescript` :402, `extract_tsx` :436, `extract_javascript` :470, `extract_jsx` :504, `extract_bash` :538, `extract_powershell` :572, `extract_lua` :606, `extract_qml` :639, `extract_r` :673, and peers)

**Interfaces:**
- Consumes: each language's extractor constructor + the standard `extract_symbols`/`extract_relationships`/`extract_identifiers`/`infer_types`/`take_*` sequence (see `extract_java` :198–231 for the canonical shape).
- Produces: identical `fn extract_<lang>` items generated by a `macro_rules!` (e.g. `standard_extractor!(extract_java, crate::java::JavaExtractor, "java");`), so call sites in the dispatch table are untouched.

**What to build:** One macro generating the wrapper functions that follow the exact standard shape. Wrappers that deviate (e.g. `extract_html` :723, `extract_sql` :767, `extract_vue` :883 have extra passes) stay hand-written — do not force them into the macro.

**Approach:** Inventory first: diff all wrappers against the canonical shape; only byte-shape-identical ones (modulo extractor type and language string) go through the macro. This is where a new `ExtractionResults` field currently requires ~20 synchronized edits — after this task it requires one.

**Acceptance criteria:**
- [ ] All standard-shape wrappers macro-generated; deviating wrappers unchanged and listed in the commit message.
- [ ] `cargo xtask test default` and golden fixtures pass with zero diffs.
- [ ] Worker-scope verification passes, committed.

## Task 3: Unwrap Audit — SQL Schemas and Vue Helpers

**Files:**
- Modify: `crates/julie-extractors/src/sql/schemas.rs` (18 production `unwrap()` calls — verified 2026-07-01, no `#[cfg(test)]` module in the file)
- Modify: `crates/julie-extractors/src/vue/helpers.rs` (10 production `unwrap()` calls — verified 2026-07-01)
- Test: `cargo xtask test language sql`; `cargo xtask test language vue`

**Interfaces:**
- Consumes: existing extractor error posture — per-file panic isolation exists at the pipeline level, but an extractor panic still kills that file's extraction and surfaces as a failed file.
- Produces: the same emitted rows for well-formed input; malformed constructs skip their row instead of panicking.

**What to build:** Audit each `unwrap()`/`expect()` in the two files. Prefer skip-the-row/`Option` fallbacks consistent with how other extractors handle malformed nodes: extraction of one bad construct must not fail the whole file. (Explicitly out of scope: `julie-extract-artifact/src/writer.rs` — the codex verification found zero production unwraps there; do not "fix" the test-module unwraps or the documented `expect` at `writer.rs:947`.)

**Approach:** Not every unwrap is wrong — an unwrap on an infallible invariant may stay, converted to `expect("<invariant>")` with the invariant stated. The deliverable is zero *unjustified* panics: each remaining `expect` documents why it cannot fire. Add a regression test per file exercising a previously-panicking path (a malformed/truncated SQL DDL fixture for `schemas.rs`; a malformed SFC construct for `vue/helpers.rs`) now skipping gracefully with the rest of the file's rows intact.

**Acceptance criteria:**
- [ ] Zero bare `unwrap()` outside `#[cfg(test)]` in both files; remaining `expect`s state their invariant.
- [ ] At least one new regression test per file exercising a previously-panicking path now skipping gracefully.
- [ ] `cargo xtask test language sql` and `cargo xtask test language vue` pass; golden fixtures byte-identical.
- [ ] Worker-scope verification passes, committed.
