## Commands

The measurement script verified both input states, binary versions, artifact
reports, and database invariants, then ran the two scans concurrently:

```sh
python3 target/annotation-size/measure_release_size_post_claude_review.py
```


`sqlite_autoindex_symbol_annotations_1`, and `idx_symbol_annotations_symbol`.

The artifact-size changes include access metadata and additional write-site
identifiers as well as annotations. The `dbstat` allocation isolates storage
for the annotation table and indexes; it is not the total feature cost.

| Input | Variable read | Variable write | Variable read/write | Member read | Member write | Member read/write | All access rows |

| hermes-agent | 1,278,967 | 73,337 | 3,346 | 240,953 | 43,870 | 724 | 1,641,197 |

Both 3.11.0 artifacts had zero access values outside `read`, `write`, and
`read_write`; no `call` or `type_usage` identifier carried access metadata.
Complexity metrics remained at zero in both 3.10.0 and 3.11.0 references
artifacts.

The final golden audit covered 274 existing fixtures whose changes were limited
to access and new-reference rows, plus 14 new fixtures, with no duplicate write
references. It verified 3,750 access rows: 3,380 reads, 309 writes, and 61
read/write rows. `node scripts/language-data-quality-report.mjs --strict`
passed with zero silent cells and zero quality-bar debts.

## Report checks and limits

All four old and new reports had `status=ok`, no errors, the requested root, and
`index_level=references`. Julie scanned 3,039 files and wrote 3,038 in both
versions with no warnings. Hermes scanned 12,798 files and wrote 12,788 in both
versions. Its 40 warnings matched the 3.10.0 baseline: 33
`reference_site_payload_conflict` and 7 `slow_file_skipped`.

The comparison covers these two fixed source snapshots and the references
level. Artifact totals reflect all rows and SQLite allocation for each input;
they should not be read as a universal per-project overhead estimate.
