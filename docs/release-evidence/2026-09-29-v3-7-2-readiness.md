## Defects fixed

- Native Windows verbatim-prefix removal preserves UTF-16 units rather than
  replacing unpaired surrogates. An isolated native regression failed with the
  previous implementation and passed with the fix; the final native suite also
  covers the production helper.
- Root-spelling repair is exercised on Windows for scan, update, delete, and
  rebind. Committing incremental operations preserve artifact identity;
  no-change scans preserve metadata; rebind assigns a new identity.
- Every artifact mutation checks its staged artifact ID inside the transaction.
  A writer prepared before rebind cannot overwrite the rebound metadata, even
  when producer versions match. CLI reports use recoverable `artifact_changed`.
- Different-root force scans reset facts, capabilities, history, and metadata
  transactionally, without unlinking the database. Tests cover rollback and
  retry, stale identity, hard-link identity, empty rebuilds, writer reuse,
  parent exit, and source errors during producer refresh.
- Discovery reuses Unix metadata for identity and size checks. The regression
  recorded two metadata reads before the fix and one afterward. Ignored and
  generated files still skip unnecessary reads.

## Performance

Published 3.7.1 and final 3.7.2 release binaries scanned the same frozen source
checkout at `f5fe0291`. Three full scans per binary had identical table row totals:
2,968 files, 788,959 symbols, and 593,519 identifiers. Median SQLite size was
2,362,728,448 bytes for both. Final Linux measurements were repeated after the
Windows guest was confirmed off.

| Frozen-repository median | 3.7.1 | 3.7.2 |
| --- | ---: | ---: |
| Full scan | 33.656 s | 33.333 s |
| No-change rescan | 0.972 s | 0.989 s |
| Info | 0.748 s | 0.744 s |

Full-scan performance is effectively unchanged. The small median changes are
within the observed run variation; they are not evidence of a general speedup.

The discovery test used 4,000 directories containing `index.rs`, two warmups,
and ten alternating unchanged scans per binary. Each artifact was checked for
4,000 files and 4,000 symbols. The matching-name case places a database named
`index.rs` outside the source root; the control uses `artifact.sqlite`.

| Platform and database name | 3.7.1 median / p95 | 3.7.2 median / p95 |
| --- | ---: | ---: |
| Linux, `index.rs` | 120.28 / 132.77 ms | 123.24 / 143.08 ms |
| Linux, `artifact.sqlite` | 122.01 / 129.29 ms | 123.26 / 131.31 ms |
| Windows, `index.rs` | 553.55 / 581.52 ms | 573.06 / 594.70 ms |
| Windows, `artifact.sqlite` | 552.38 / 569.63 ms | 532.02 / 547.19 ms |

The initial Linux matching-name result was 8.5% slower; removing the duplicate
metadata read reduced the measured difference to 2.5%. Windows matching-name
checks retain a roughly 3.5% wall-time cost because artifact alias detection now
probes native file identity. An earlier 30-sample confirmation measured 4.8%.
These checks preserve correctness that 3.7.1 lacked; cached artifact handles
avoid reopening the artifact for every candidate. Differently named hard links
remain the deliberately unprobed limitation covered by the existing test.

The current-schema writer benchmark wrote 10,000 files and 80,000 symbols in
one transaction: 11.788 seconds, reported 103,492 rows/second, 378,384,384 bytes.
The final source checkout also passed repository dogfood: 2,968 files and
788,976 symbols, followed by a no-change rescan. Its extra symbols reflect the
metadata-reuse code and regression tests. SQLite quick-check returned `ok` and
foreign-key checking returned no violations.
