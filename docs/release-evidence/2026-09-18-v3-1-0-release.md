# julie-extract 3.1.0 release verification

Published v3.1.0 release verification.

## Scope

- Fenced code blocks in standalone markdown files no longer carry a test role.
  3.0.0 applied the rustdoc rule to every `.md` file, so each bare or `rust`
  block was a test case; `code-kb` listed them as related tests.
- `complexity_metrics` and `symbol_annotations` are written only at
  `--level full`. `code-kb` scans at `facts` and reads neither table.
- Both changes are declared under `## 3.1.0` (`classification: compatible`) in
  `docs/contracts/extraction-output-changes.md`. A consumer that holds a 3.0.0
  artifact must rebuild it, because an unchanged file keeps its stored rows.

SQLite schema v7, report schema v3, extraction contract, identity epoch,
parser inventory, and external dependency graph are unchanged. The markdown
fixtures and the capability snapshot (`test_case` moves to `not_applicable`
for markdown) were reblessed.
