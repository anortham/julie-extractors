## Pre-tag gates and limits

- Native NTFS Windows guest: `cargo xtask test default` and `contract` both exited 0 after clearing rebuildable cache that had filled the guest C: disk. The guest was shut off after testing.
- Local candidate checks included formatting, default/contract/certification, strict quality (zero silent cells and quality-bar debts), real-world smoke/release, repository dogfood, preflight (six targets, 27 inputs), Linux package staging, and a declared-compatible comparison with published 3.7.0. The latter emitted a C# fixture/parser NOTICE rather than a breaking verdict.
- Required pre-tag code-kb dogfood used a hash-pinned 3.7.1 candidate. It found one wrong `lookup_symbol` disambiguation message; reviewed code-kb [PR #23](https://github.com/anortham/code-kb/pull/23) fixed it at merged commit `256f1963c80e8cba71fca9591d4961ab50b03acc`. Both exact reported Flask lookups were replayed against the same candidate after the fix. The report records six nonblocking gaps at `code-kb/.worktrees/julie-3.7.1-dogfood/target/release-dogfood/report.md`. The harness shell timed out before its exit code could be captured; Claude finished and the same Codex session was resumed to completion. No second dogfood round was run.
- The candidate binary used for code-kb dogfood was locally built (`9e17cee5413841564eeef84e219c9910971339ea39ae769182479e950746aeec`); it is **not** the public Linux binary. Public archive and embedded checksums were verified separately above. No native execution of the ARM or macOS public binaries was claimed by this verification.

This pointer/evidence change is a post-publication documentation-only follow-up. It does not alter the released source commit or `v3.7.1` tag.
