# julie-extract 2.42.0 release verification

Published [v2.42.0](https://github.com/anortham/julie-extractors/releases/tag/v2.42.0)

This documentation-only publication record is release closeout under the
user's approval. It is not part of the tagged binary release. The immutable
tag is preserved; main and origin/main advance together with the
evidence-only follow-up.

## Scope

Store throughput and reporting work since v2.41.1: SQLite 3.53.2, busy-lock
classes, quick checks in maintenance, the committed-report race fix, writer
connection and pool reuse, core-scaled workers and deep chunks, the deep-wave
prefetch with its Codex review follow-up, and the clippy repairs that stable
Rust 1.98.1 required. Parser behavior, schemas, and the extraction identity
epoch are unchanged. Notes: `docs/release-notes/v2.42.0.md`; measurements:
`docs/findings/2026-09-08-performance-audit.md`.

Preparation advances the three shipped crate versions and their lockfile
entries to 2.42.0 and moves the mixed-version newer-factory fixture to 2.43.0.
No external dependencies change. The xtask crate stays at 2.0.0.

The first Windows contract-tier attempt failed before any test ran: the guest
`C:` volume was full (`os error 112`), which also produced an `LNK1318` PDB
error while linking the extractors golden test binary. The guest disk was
grown from 80 GiB to 200 GiB, the stale build output was removed, and the
store harnesses above ran on the clean guest. The full contract tier was not
repeated on Windows; the extractor-only harnesses it adds are unchanged since
v2.41.1.

## Public binary proof

The downloaded public Linux binary imported a five-file root at two versions
per quantum. Its deep chunk progress events report `(completed_files,
prefetched_files)` of `(2, 0)` then `(4, 2)`, proving the second deep chunk
was served from the prefetch. The new family stamps `binary_version`,
`min_reader_version`, and `min_writer_version` 2.42.0 and
`extraction_identity_epoch` 10, and the report shows L1, L2, and L3 complete.
