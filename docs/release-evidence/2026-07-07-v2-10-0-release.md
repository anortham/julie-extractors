## What Shipped

- A `variable_ref` emission arm added to every general-purpose language's
  `src/<lang>/identifiers.rs` (the read/receiver complement of the existing
  `call` / `member_access` / `type_usage` arms), plus CSS `var(--x)` and bash
  `$var` / `${var}` reads (Batch F). C# is the reference implementation that locks
  the 6-rule contract; yaml alias `variable_ref` and r/qml `variable_ref` are
  pre-existing and unchanged.
- `variable_ref` is **non-resolvable**: it is not wired into the resolver tier
  chain; the rows are consumed by name-match only.
- `fixtures/extraction/capabilities.json`: `variable_ref` recorded in
  `kind_coverage.identifiers.supported` for all 30 emitting languages, and in
  `kind_coverage.identifiers.not_applicable` for `html`, `json`, `markdown`,
  `regex`, `sql`, `toml`.
- Version bump `2.9.0` → `2.10.0` across all three release crates + `Cargo.lock`.

## Adversarial Review Fix Round (2026-07-07, pre-publish)

A Codex adversarial review of the full source diff (fixtures excluded) returned
two material predicate findings; BOTH were lead-verified with live extraction
probes before any fix, and both fixes shipped the same day:

1. **java (high):** the `field_access` arm early-returned under
   `method_invocation`, so the terminal class receiver of a fully-qualified
   static call (`com.acme.GraphTraversal.reach()`) emitted NO identifier row —
   a class referenced only via FQ static calls looked dead. Fixed by removing
   the guard (the Call arm never emits receivers, so no double-emission);
   FQ terminal receivers now emit `member_access`, matching FQ static-field
   behavior. `java/basic` fixture extended to pin the case. Commit `4ddcb63`.
2. **python (medium):** match-statement pattern bindings leaked as
   `variable_ref` reads (`case [*items]:`, `case _ as handler:`, plus a third
   shape the review missed: `case Point(x=px):` keyword-pattern names). Leaked
   bindings mask genuinely dead same-named symbols. Fixed with
   `splat_pattern`/`keyword_pattern` exclusions and a case-context-only
   `as_pattern` exclusion (with/except handling untouched); zero golden drift
   (no fixture contains a match statement). Commit `61bb384`.

Refreshed evidence at the post-fix tip:

- Full lib suite 2,819 passed / 0 failed; golden clean run passes; clippy 0.
- Dogfood coverage (same query): all 30 emitting languages non-zero;
  java 28 → 31 rows (the receiver fix), others unchanged or noise-level.
- Performance baseline re-run (Miller repo, 3 runs): scan_duration_ms
  min 7,103 / median 7,183 / max 8,358 — unchanged from the pre-fix runs.

## Fix Round 2: Dead-Code-Gate Closure (2026-07-07, pre-publish)

The Miller dead-code gate residual drove two more extraction fixes, both included
in this release:

1. **razor:** the vendored tree-sitter-razor grammar dropped attribute VALUES for
   Blazor component attributes and `@bind-Value` — identifiers in them never
   reached the parse tree. Fixed in a maintained fork
   (https://github.com/anortham/tree-sitter-razor, rev `cf7b0e5`, minimal grammar
   change, full corpus green) with an upstream PR open
   (https://github.com/tris203/tree-sitter-razor/pull/27); the Cargo pin points at
   the fork until the PR merges. No extractor change needed — the existing
   value-read arm covers the new nodes. Commit `f28da33`.
2. **csharp:** tree-sitter-c-sharp parses `A * B` in argument position as a
   pointer-type declaration (a real C# ambiguity), hiding both operands from
   liveness. New language-fact heuristic: pointer types are legal only in
   `unsafe` contexts, so the shape outside one emits both operands as
   `variable_ref`; genuine unsafe declarations unchanged. Commit `c08f1e6`.

Gates at final tip: lib 2,822 / 0; golden clean; clippy 0; preflight 2.10.0 ok.

**Downstream validation (the release's reason to exist):** Miller full-repo
dead-code gate on this binary: **392 candidates (v2.9.0) → 5**, all five
hand-verified true finds, zero confirmed-live false positives — the design's
hard gate passes literally. (Two Miller-side evaluator rules — override_member,
live_member_container — landed on Miller's feature branch as part of the same
effort.)
