# julie-extract 3.1.1 release verification

Published v3.1.1 release verification.

## Scope

- Every language extractor records a qualified call chain
  `Q1.Q2 ... Qn.t(...)` in `pending_relationships` as `terminal_name = t`,
  `receiver = Qn`, `namespace_path = [Q1 .. Qn-1]`, with the display name
  joined by `.`. Eighteen languages change (C#, Java, Kotlin, Go, PowerShell,
  C++, Zig, JavaScript, TypeScript, Python, Swift, Dart, Lua, GDScript, C, PHP,
  Ruby, R). Scala and VB.NET already matched; Rust, Elixir, F#, and Erlang keep
  the whole chain in the namespace path with no receiver.
- Java traverses call sites once, removing duplicate pending rows. Python,
  Ruby, and Swift no longer resolve a namespaced chain to a same-named local
  symbol.
- Declared under `## 3.1.1` (`classification: compatible`) in
  `docs/contracts/extraction-output-changes.md`. A consumer that holds a 3.1.0
  artifact must rebuild it, because an unchanged file keeps its stored rows.

SQLite schema v7, report schema v3, extraction contract, identity epoch, and
parser inventory are unchanged. Nine golden fixtures (later thirteen after the
external review) were reblessed for the receiver split.
