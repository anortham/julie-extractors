## WHAT

Fixed Java single-segment package extraction. `extract_package` now accepts both tree-sitter `identifier` nodes (`package sample;`) and `scoped_identifier` nodes (`package com.example;`). Added a focused regression and regenerated the two existing Java golden fixtures that use single-segment packages.

## WHY

Miller CT's real Java native test could extract the test class and method but could not construct the native `sample.SelectedTest` identity because julie-extract 2.40.6 omitted the `sample` Namespace symbol. The extractor handled only dotted package syntax even though both forms are valid Java and share the same existing Namespace contract.

## HOW

Kept the existing symbol shape, visibility, signature, and parent behavior. Only the accepted tree-sitter child kinds changed. The regression proves `package sample` emits a public Namespace symbol, canonical golden regeneration added `fixture` Namespace rows to Java basic and cross-file fixtures, and a fresh 2.41 debug CLI drove Miller's real Java provider test.

## IMPACT

Miller can resolve native Java test IDs for single-segment packages without a consumer-side guess or declaring Java unsupported. Dotted packages remain covered. Miller's checked-in pin stays at julie-extract 2.40.6 pending the normal release/adoption boundary.
