## Reuse the store writer connection and rayon pool across import quanta

### WHAT
- `StoreCoordinator::drain_acquired` keeps one `StoreWriterConnection` across quanta and hands it to `execute_request_quantum`; the connection is reused when `fenced_for` matches the new generation fence (root, generation, run id, owner, pid, token), and `advance_binary_version` still revalidates the generation fence and writer lease every quantum. A fresh connection with bulk pragmas is opened otherwise. The connection is only cached on the success path.
- `StoreRequestExecutor` caches its rayon pool keyed by `jobs` (`map_with_pool`) and skips the pool for empty work; `map_with_jobs` is test-only now.
- New contract test `projection_staging_is_reusable_across_matching_and_mismatching_files`.

### NUMBERS (paired alternating runs, this repo, load 5-9)
- import 40.0/42.4/43.3 s (before) vs 38.3/40.6/40.0 s (after); under load 23: 59.2 vs 48.0 s.
- bytes read per import 10.2 GB -> 4.35 GB.

- artifact default tier, store crash tier (test-store-crash), takeover tier, CLI store contracts and store_equivalence tier all pass; clippy clean.
