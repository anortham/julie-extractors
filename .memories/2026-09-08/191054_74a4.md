## Codex review of the prefetch commit: five P2 findings fixed

**WHAT:** Follow-up to 29bc16f0 in `crates/julie-extract-cli/src/store/executor.rs` and `tests/store_import_contract.rs`.

- Prefetched files carry the source mtime+size seen before the read (`SourceIdentity`); a mismatch at consume time drops the file to inline extraction, where the frozen-hash check fails it as `changed_between_waves`. New hook `JULIE_EXTRACT_STORE_TEST_PREFETCH_READY_FILE/RESUME_FILE` waits for the prefetch to finish, then pauses; new test `source_change_after_the_prefetch_finishes_is_still_detected`.
- Interactive updates extract on their own pool (`pool_for(FilePlanOperation::Update)`), so an import's prefetch cannot hold an update past the 250 ms interactive burst.
- Prefetched results record which progress stages they reached (`ExtractionStages`), so `files_extracted` matches inline accounting.
- The two hook/crash-dependent tests are gated behind `test-store-contract`, like the existing hook tests.
- The prefetch unit test canonicalizes its temp root (Windows verbatim path pitfall).

**WHY:** Codex (codex-cli 0.153.4, read-only, `--ignore-user-config` because ~/.codex/AGENTS.md demanded a `sol_worker` helper it could not spawn) reviewed b881fb1c..29bc16f0 and found these; all verified against the code before fixing. No critical findings; lifecycle, stale-key, crash-recovery, and Windows-handle checks passed.

**HOW:** `extract` now wraps `extract_with(on_stage)`; the prefetch closure records stages into a struct instead of touching `ScanProgress`.

**IMPACT:** Contract behaviour for source changes during the deep wave is now identical with and without prefetch. Suites: import contract 48 (feature) / 42 (no feature), operations 31, equivalence 7, executor unit 11.
