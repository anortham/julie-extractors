## Codex second review folded into the performance audit

### WHAT
- Codex (read-only) confirmed staging rollback, export statement reuse, and busy classification.
- Fixed from its findings: `temp_store=MEMORY` is now bulk-profile only (routine keeps SQLite defaults); busy message now says "could not acquire the database lock".
- Audit doc corrected: lease rationale for chunk=8 is outdated for imports (heartbeat thread renews the lease; import is renewable; 4 s limit excludes it); `MILLER_STORE_CHUNK_VERSIONS` sets both waves; bulk profile applies to every coordinator quantum; the deep wave may serve the second read from the snapshot cache.
- New verified defects recorded: rayon pool rebuilt per quantum (16 MiB stacks), store connection reopened per quantum (cold page cache), `validate_full` clones the whole extraction per file, `bulk_cache_size_kib` accepts i64 while SQLite reads i32.

### WHY
- User asked whether deep-chunk size should scale with cores (80-85%) and asked for a second set of eyes.

### IMPACT
- Tests pass (artifact crate, store import and maintenance contracts); clippy clean. Still uncommitted on main.
