## qmldir optional/default imports implemented

### WHAT
Added qmldir import extraction for ordinary `import`, `optional import`, and `default import` lines. All emit `qmldir.import.v1`; metadata now always includes boolean `optional` and `default` flags while preserving the leading directive (`import`, `optional`, or `default`). Added unit coverage for all forms, versionless imports, invalid versions, missing arguments, and malformed recovery. Expanded the registered qmldir golden fixture and regenerated its expected artifact plus the structural-fact contract JSON.

### WHY
Grok review confirmed that the parser accepts optional/default imports but the extractor silently dropped them. This closed the verified first-class qmldir import gap without changing the capability claim or inventing new pattern IDs.

### HOW
Kept `depends` on the existing module-reference helper. Routed imports through a dedicated helper that validates optional versions with the existing `is_version` rule, emits exact boolean metadata, and uses the actual leading directive as capture/metadata. Regenerated checked-in artifacts through the repository's existing `UPDATE_CONTRACT_JSON` and `UPDATE_GOLDEN` test paths.

### IMPACT
QML module manifests now retain tooling-relevant optional/default import semantics for downstream consumers. No capability row change was needed because `qmldir.import.v1` was already registered and claimed. Working tree remains intentionally uncommitted for the lead's parallel-lead-commit reconciliation.
