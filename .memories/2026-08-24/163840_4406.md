## Guard QML `.qmltypes` tree traversal

### WHAT
Added the crate traversal-budget guard to `crates/julie-extractors/src/qml/typeinfo.rs`. The typeinfo walker now carries a `u32` depth, checks `should_visit_tree_depth` before visiting each node, and uses `child_tree_depth` before recursing through `walk_children`.

### WHY
The default-gate convention test detected an unguarded `walk` ↔ `walk_children` recursion cycle. Deep `.qmltypes` trees could otherwise consume one Rust stack frame per CST node and overflow the extraction worker.

### HOW
Matched the established guarded-walker pattern used by the C++ and PHP extractors: start at depth zero, guard the current node in `walk`, compute one bounded child depth in `walk_children`, and pass it to recursive calls. Existing normal-depth extraction logic was left unchanged. The source-scan convention test was used as the red/green TDD check; the existing crate deep-traversal tests cover small-stack and over-budget behavior for guarded walkers.

### IMPACT
The traversal convention gate now passes for QML typeinfo while current QML type/member and structural-fact behavior remains green. No additional deep fixture was needed because the repository’s convention gate specifically detects the mutual-recursion cycle and the shared deep traversal suite passed.
