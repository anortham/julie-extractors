## Extensionless qmldir CLI discovery

### WHAT
Updated `crates/julie-extract-cli/src/discovery.rs` so discovery delegates complete path-aware language detection to producer-owned `detect_language_for_source`, while preserving size, ignore, and hard-exclusion handling. Added a focused test proving exact basename `qmldir` is selected as language `qmldir` and arbitrary extensionless `README` remains unsupported.

### WHY
CLI discovery previously extracted only a path extension, so extensionless `qmldir` manifests were rejected as `UnsupportedExtension` even though the extractor language contract recognizes the basename.

### HOW
TDD RED failed with `UnsupportedExtension` for `src/qmldir`; GREEN replaced the extension-only lookup with `detect_language_for_source(path, "")`. Empty content preserves discovery's extension-only behavior for normal files while allowing the producer's basename rule to handle `qmldir`; no `.qmldir` extension or CLI-specific hardcoding was introduced.

### IMPACT
The exact qmldir discovery test passes in CLI lib and bin targets. Existing `.qmltypes` source-limit and oversized-file discovery tests continue to pass, and the Julie language-spec/API contract test passes. Only `discovery.rs` was changed by this packet; no Task 2/4 files were touched or staged.
