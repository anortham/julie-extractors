## Path-aware QML language detection correction

### WHAT

Added a public producer-owned `detect_language_for_path(&Path, content)` API and routed the string compatibility wrapper, extractor pipeline helper, CLI discovery, and store import language paths through it. Added Unix invalid-UTF8-parent coverage for mixed-case QML, qmltypes, case-insensitive qmldir, C++ header sniffing, and ordinary extensionless rejection. Added a store contract proving a failed extensionless `qmldir` manifest row records language `qmldir`.

### WHY

CLI discovery previously converted the entire absolute path to UTF-8 before detecting language, and store paths only inspected extensions. Those paths rejected valid files beneath invalid-UTF8 parents or labeled extensionless qmldir failures as `unknown`.

### HOW

The Path API inspects only basename and extension components with `OsStr::to_str`; the existing `&str` API delegates to it. Discovery passes its `Path` directly. Store planned-file fallback and extraction use the same source-aware contract, preserving `.h` content sniffing and case-insensitive extension matching.

### IMPACT

Extensionless qmldir language identity is now consistent for discovery, successful extraction, and failure rows. The parent agent can review and commit only the owned detection/CLI/store files plus this checkpoint; concurrent QML extractor edits remain untouched.
