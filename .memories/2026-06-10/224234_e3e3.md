## Closed remaining unclassified applicability gaps

The larger Cursor-assisted slice closed the remaining unclassified scorecard gaps across `complexity_metrics`, `annotations`, and `doc_comments` without lowering the quality bar.

- **WHAT:** Added native SQL and regex complexity metric collectors, fixture/golden evidence, focused language tests, and applicability classifications for the remaining 20 non-native cells.
- **WHY:** The scorecard still had unclassified gaps after the raw-gap and native-debt passes. Those cells needed either real extraction or evidence-backed classification before the plan could move from coverage completion into depth auditing.
- **HOW:** Routed SQL/regex through language-specific complexity collectors, updated SQL fixture data to prove nonzero symbol-level complexity, added regex containment tests so symbol metrics do not inherit surrounding pattern complexity, updated `DOMAIN_APPLICABILITY`, refreshed capabilities, and documented Phase 19 decisions.
- **IMPACT:** `complexity_metrics`, `annotations`, and `doc_comments` now all report `unclassified_gaps: 0`; `complexity_metrics` is applicability-complete at 30/30, `annotations` at 23/23, and `doc_comments` at 35/35.

Lead review found and fixed issues before acceptance:

- SQL/regex capability claims initially did not match the feature-gated capability registry helper.
- SQL/regex symbol metrics needed callable body spans rather than declaration spans.
- Regex symbol metrics needed contained-node counting to avoid inheriting surrounding pattern complexity.
- SQL symbol-level evidence needed a nonzero callable metric, not only a zero-count trigger metric.
- QML language spec still advertised `types: false` even after QML TypeInfo rows were enabled.
- Elixir annotation coverage omitted existing `type` annotation evidence.
