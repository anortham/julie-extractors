## Added applicability-aware scorecard v2

- **WHAT:** Extended `scripts/language-data-quality-report.mjs` with an `Applicability-Aware Domain View` while preserving raw fixture-proven counts. Added script-local classification for `type_argument_usages` and documented Phase 16 in the findings doc.
- **WHY:** Raw `N/36` counts were mixing real extractor debt with true non-applicability and convention-only language idioms. The new view lets future Cursor batches target actual `native_debt` / `quality_debt` instead of chasing non-debt.
- **HOW:** Used Cursor Agent as implementor, then reviewed and sent fix loops for closure semantics and metadata validation. The report now shows `type_argument_usages` as raw `20/36` and applicability closure `20/20 complete`, with 13 `not_applicable`, 3 `convention_only`, and zero unclassified/debt rows.
- **IMPACT:** Future audits can classify raw gaps across domains directly in the scorecard. Metadata now fails fast for unknown languages, duplicate bucket assignments, and fixture conflicts for `not_applicable`, `convention_only`, or `native_debt`.
