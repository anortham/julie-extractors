## Added data, document, and regex structural facts

### WHAT

Implemented structural-facts coverage for Markdown, JSON, TOML, YAML, and Regex.

- Markdown emits frontmatter, heading, fenced-code-block, link-definition, and table facts.
- JSON emits object, array, and property facts with path/depth/value metadata.
- TOML emits table, array-table, key-value, and inline-table facts with key paths and value kinds.
- YAML emits document, mapping, sequence, anchor, and alias facts.
- Regex emits capture-group, named-capture, lookaround, character-class, quantifier, alternation, and anchor facts.
- Regex `source_regions` is closed as `not_applicable` for the current source-region contract instead of forcing pattern internals into comment/string/embedded regions.

### WHY

These data/config/document formats were still explicit structural-facts debts. Closing them reduces uneven language quality and gives downstream tools meaningful structure for documents, configs, and regex patterns.

### HOW

Added `base::data_structural_facts` and wired it into canonical extraction after generic/framework/web structural facts. Capability-matrix registry support now advertises the new pattern IDs. Goldens and `capabilities.json` were regenerated and the coverage-review doc was updated.

Review fixes applied before commit:

- TOML inline-table children now use nested key paths like `worker.profile.role`.
- Markdown/JSON/YAML count metadata now uses local/direct counts instead of recursive totals.
- The findings doc now matches strict scorecard output: `quality_bar_debts: 17`, `structural_facts: 19/36`, and `source_regions: 35/36 fixture-proven` with regex closed by exception.

### IMPACT

The strict scorecard now reports `quality_bar_debts: 17` with remaining debt only in structural facts for Zig, Java, VB.NET, PHP, Ruby, Swift, Kotlin, Scala, Dart, Elixir, Lua, QML, R, Bash, PowerShell, GDScript, and SQL.
