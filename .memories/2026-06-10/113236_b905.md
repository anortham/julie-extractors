## Corrected language-quality direction

### WHAT
- Revised `docs/findings/2026-06-09-language-coverage-review.md` and `docs/plans/2026-06-10-language-data-quality.md` after the user clarified the goal.
- Saved a new active Goldfish brief: `julie-extractors Best Tree-Sitter Implementation Focus`.

### WHY
- The prior plan framed the next work too much as honest capability accounting and cheap evidence closure.
- User clarified that the goal is not lowering the bar to current data quality; the goal is to make `julie-extractors` the best tree-sitter implementation available because downstream projects already depend on it.

### HOW
- Reframed the plan goal around deep, AST-backed, fixture-proven semantic data across the supported language set.
- Added a product quality bar for code languages and domain/data/markup languages.
- Made `not_applicable` valid only for constructs that genuinely do not exist in the language.
- Made `open_gaps` temporary implementation debt, not an acceptable end state.
- Added downstream dogfood/comparative quality validation as its own phase.

### IMPACT
- Future work should raise extractor quality broadly instead of merely documenting uneven coverage.
- Workers should treat missing code-language domains as bugs or debt until AST inspection proves otherwise.
