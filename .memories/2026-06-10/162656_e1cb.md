## Reviewed Cursor-driven annotation fixture slice

### WHAT
Used the new `razorback:cursor-agent` workflow to delegate a bounded annotation fixture-evidence slice to Cursor Composer 2.5 fast, then reviewed and corrected it through one fix loop.

### WHY
The project is raising tree-sitter extraction data quality across the language matrix. After complexity reached `28/36`, annotations were the next bounded domain with existing extractor support but missing fixture-backed capability evidence.

### HOW
- Initial Cursor pass added annotation evidence for `php`, `vbnet`, `powershell`, `scala`, `kotlin`, and `swift`, but closed gaps too shallowly.
- Codex sent a concrete fix prompt requiring all existing tested annotation target kinds to be fixture-proven or left as target-specific gaps.
- Cursor deepened fixtures and `capabilities.json` so supported annotation kinds match observed golden rows.
- Final proven kinds include PHP class/method/property, VB.NET method/property, PowerShell function, Scala class/function/method/property/type, Kotlin class/method/property/type, and Swift enum_member/function/module/property/struct/type.

### IMPACT
- `annotations` coverage is now `17/36`.
- Strict scorecard has `silent_cells: 0` and `quality_bar_debts: 45`.
- Cursor skill worked well operationally, but future capability prompts should explicitly require breadth across existing tested target kinds rather than count-only improvement.
