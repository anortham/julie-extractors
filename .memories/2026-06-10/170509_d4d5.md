## Completed doc-comment coverage slice

### WHAT

Reviewed and accepted the Cursor-driven doc-comment slice for the 11 remaining open languages.

- Added fixture-proven doc-comment support for Zig, TSX, VB.NET, Scala, Elixir, Lua, QML, R, GDScript, and YAML.
- Classified regex doc comments as not applicable for all emitted regex symbol kinds (`class`, `function`, `variable`).
- Added current doc-comment policy to both extracted-data v2 and v3 docs.
- Added YAML-specific key documentation handling so only a single same-indent comment immediately before a leaf mapping key becomes `doc_comment`; file headers and section/container comments remain ordinary comments.
- Included rustfmt-only cleanup for files that were already failing `cargo fmt --check` before this slice.

### WHY

The language data-quality goal requires every capability-domain claim to be either fixture-proven support, explicit true non-applicability, or concrete open debt. Doc comments were one of the remaining broad uneven domains and needed to be closed without treating plain comments as documentation.

### HOW

Codex reviewed the delegated diff, found issues around YAML comment overclassification, missing v3 contract docs, stale findings scorecard values, and incomplete regex `not_applicable` coverage. After fixes, Codex verified the generated golden rows, source-region behavior, capability rows, and focused test gates.

### IMPACT

- `doc_comments` is now 35/36 fixture-proven, with regex explicitly not applicable.
- Doc-comment open gaps are closed across the matrix.
- `quality_bar_debts` is reduced to 29 with `silent_cells` still 0.
- Remaining language-quality debt is now concentrated in annotations and structural facts.
