## Reviewed embedded/web complexity metrics slice

### WHAT
Reviewed and accepted the embedded/web complexity metrics slice for `tsx`, `jsx`, `vue`, and `razor` after the TSX/JSX test-routing fix.

### WHY
The language data-quality work is raising parser-backed complexity coverage across the advertised language matrix. This slice closes the remaining code-like embedded/web complexity gaps while leaving SQL and non-code formats design-gated.

### HOW
- TSX and JSX reuse the ECMAScript complexity config through variant-specific tests under `tsx_complexity` and `jsx_complexity`, so `cargo xtask test language tsx` and `cargo xtask test language jsx` now execute the new tests.
- Vue complexity is collected from `<script>` / `<script setup>` sections only and ignores template/style markup.
- Razor complexity reuses the C# config for code-bearing Razor AST nodes while avoiding HTML markup complexity.
- Fixture outputs and `capabilities.json` now claim `file` and `symbol` complexity only where golden evidence exists.
- Removed unrelated Unicode escape churn in `capabilities.json` before commit.

### IMPACT
- `complexity_metrics` coverage is now `28/36`.
- Strict language data-quality report has `silent_cells: 0` and `quality_bar_debts: 51`.
- The remaining complexity gaps are explicit for HTML, CSS, SQL, JSON, TOML, YAML, Markdown, and Regex.
