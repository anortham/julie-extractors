## Phase 1 language data quality slice

### WHAT
Completed the first real extractor-depth slice after the Phase 0 scorecard gate. C and C++ now have fixture-backed support for annotations, doc comments, literals, and doc-comment source regions. HTML/Bash capability cleanup was included because the richer doc-comment fixtures exposed bad inherited documentation rows.

### WHY
The project goal is to raise all language extraction to a high bar, not merely document uneven coverage. The C/C++ slice was chosen to turn the new quality plan into executable improvements while keeping capability claims backed by golden fixture evidence.

### HOW
- Added C annotation extraction for standard `[[...]]` and GNU `__attribute__((...))` syntax with normalized annotation markers.
- Added C/C++ annotation regression tests so attributes do not bleed onto following functions.
- Tightened base doc-comment ancestor lookup to walk through declaration wrappers, not owner containers, so class/struct comments do not attach to child methods or fields.
- Added C/C++ fixture evidence for doc comments, annotations, and string literals.
- Updated `fixtures/extraction/capabilities.json` for C/C++ and corrected exposed false claims for Bash variables and HTML DOCTYPE docs.
- Added real HTML element doc-comment fixture evidence and disabled DOCTYPE doc-comment inheritance.
- Updated `docs/findings/2026-06-09-language-coverage-review.md` with Phase 1 counts.

### IMPACT
- Strict scorecard remains fail-closed with `silent_cells: 0`.
- `quality_bar_debts` dropped from 98 to 92.
- Fixture-proven domains increased to annotations 11/36, doc_comments 25/36, literals 11/36.
- Capability matrix now reflects real evidence rather than fixture-header/shebang bleed.
