## Nested .julieignore support + ignore-rules contract + vendor-policy decision

Follow-up to the v2.3.0 openclaw benchmark: decided vendor/generated-file policy is consumer-side, promoted `.julieignore` to a first-class contract, and aligned scanner semantics with Miller's watcher.

### What changed
- **Nested ignore scoping fix** (`crates/julie-extract-cli/src/discovery.rs`): nested `.gitignore`/`.julieignore` files were merged into one root-scoped matcher, so nested patterns leaked root-relative (e.g. `ui/.gitignore: i18n/` wrongly ignored `docs/i18n/`). Now each directory with ignore files gets its own `Gitignore` matcher (`build_nested_matchers`), consulted deepest-first in `DiscoveryPolicy::is_ignored`; nested whitelists override shallower ignores, `.julieignore` beats `.gitignore` in the same directory. This was a latent pre-existing bug for nested `.gitignore` too.
- **`.julieignore` now honored nested** (previously root-only), matching Miller's `WorkspaceIgnorePolicy` per-directory loading.
- **Docs**: new "File Selection and Ignore Rules" contract section in `docs/contracts/cli.md` (4 layers: hard excludes → .gitignore → .julieignore → --ignore-file, with precedence rules); README pointer; clap doc comments for all CLI args (scan --help was blank).
- **Decision doc**: `docs/decisions/2026-06-11-vendor-policy-consumer-side.md` — extractor stays policy-free, consumers (Miller) detect vendor files and route via `--ignore-file` or write `.julieignore` as explicit user action.
