### Confirmed correctness/contract findings (discovery.rs unless noted)
1. **scan/update divergence**: nested `Match::Whitelist` short-circuits in `is_ignored` (lines 66-78) before parent-dir exclusion → `update --file` extracts files `scan` prunes; next scan deletes the rows (flip-flop). Also `matched_path_or_any_parents` lets a nested `!dir/` whitelist suppress a shallower `*.log` file rule. Both violate cli.md "exactly as git".
2. **Nested ignore outranks --ignore-file** — documented intent in cli.md:91-94, but contradicts the vendor-policy decision: a committed nested whitelist (`!de.tm.jsonl`) silently defeats the consumer's vendor exclusion in exactly its target scenario. Design/contract decision needed.
3. **Root-layer precedence inverted**: `build_ignore_matcher` adds --ignore-file lines after root .gitignore/.julieignore; last-match-wins → caller `!secrets/` overrides root `secrets/`, violating cli.md "in-tree outrank caller". No test covers the conflict.
4. **Ancestor .gitignore anchoring**: ancestor files fed into root-anchored builder; anchored patterns (`/docs`, `sub/cache/`) match wrongly. Pre-existing code, but the NEW contract section claims git semantics. Fix code (per-ancestor matchers) or amend contract.
5. **Dot-dir asymmetry**: `collect_nested_ignore_files` skips all dot-dirs but `discover_dir` walks them (e.g. `.devcontainer/`) → their ignore files silently inert.
6. **Depth off-by-one**: contract says 8 levels, recursion arithmetic delivers 7 (`if depth == 0 return` before read).
7. **Swallowed `builder.add` errors** (line 305 + pre-existing 231): unreadable nested ignore file → silently inert; --ignore-file path hard-fails by contrast.
8. **Symlink follow in collector**: `path.is_dir()` follows symlinks discover_dir skips → wasted IO into foreign trees, dead matchers.
9. **Sort-accident precedence**: `.julieignore` beats `.gitignore` only because `dir_files.sort()` + 'g'<'j'. Test-protected but should be explicit add order.
