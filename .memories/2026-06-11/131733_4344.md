## Fixed all confirmed pre-release ignore-rule findings via unified scope model

Rewrote `DiscoveryPolicy` in `crates/julie-extract-cli/src/discovery.rs` (TDD, red-then-green) to close the 9 findings from this morning's pre-release review.

### What changed
- **Unified scope model**: caller `--ignore-file` matcher consulted first and decisive (both directions — user decision: explicit caller rules win over in-tree files); in-tree per-directory scopes (ancestors anchored at their own dirs, root, nested at any depth) consulted deepest-first via one shared `decide_ignored`.
- **Git parent rule**: `is_ignored` walks path prefixes top-down, so a whitelist can no longer re-include a file under an excluded parent dir → `scan`/`update` can never disagree.
- **Ancestor `.gitignore` anchoring fixed**: each ancestor scope anchored at its own directory (anchored patterns like `/docs` now behave as git does).
- **Collection walk rewritten**: prunes ignored dirs (git never reads ignore files inside excluded dirs), skips symlinks (cycle-safe), no longer skips dot-dirs, no depth cap (contract's "8 levels" wording removed), explicit `.gitignore`-then-`.julieignore` add order (kills the lexicographic-sort accident).
- **Error surface**: unreadable in-tree ignore files → non-fatal warnings in `DiscoverySummary::errors`; `--ignore-file` problems stay hard CLI errors.
- **Dropped `HARD_EXCLUDE_PATTERNS`** — fully redundant with the string checks which run first; removes the dead/bypassable copy and the list-sync drift risk.
