## Prepared julie-extractors v2.5.2 release patch

### WHAT

Implemented and verified the local v2.5.2 patch for file-derived component/script symbols:

- Razor `.razor` files now emit a top-level public class-shaped component symbol named from the filename, with `component <qualifiedName>` signature and `razor-component` metadata.
- GDScript `extends "res://..."` resource-path scripts now emit the filename-derived implicit class and parent child symbols under it.
- Golden fixtures were refreshed for Razor and GDScript.
- Rust package versions were bumped from `2.5.1` to `2.5.2`.
- `EXTRACTION_CONTRACT_VERSION` was bumped with `file-derived-component-symbols-v1` because the canonical extraction shape changed.
- Added `docs/release-notes/v2.5.2.md`.

### WHY

Miller had to synthesize Razor component symbols because extractor artifacts did not emit top-level component/file identity rows. GDScript had the same file-derived identity gap for quoted resource-path `extends` scripts.

### HOW

- Razor derives component name from `.razor` file stem and optional qualified name from explicit `@namespace`.
- GDScript now falls back from typed `extends Node` parsing to quoted resource-path text parsing.
- The changed golden output triggered the repo guard requiring explicit extractor contract review, so the extraction contract marker was updated.

### IMPACT

Downstream consumers should be able to inspect Razor components and GDScript resource-path scripts by file-derived class/component name without compatibility fallbacks. Local release gates are passing; push/release/public evidence update remains an approval boundary.
