## Wave-2 scan-time regression found and fixed before the 3.4.0 release

**WHAT:** The real-repository comparison of wave 2 (`86f496f3`) showed scan-time regressions against the wave-1 build (`0ac8705c`): zod +25%, Newtonsoft.Json +27%, radzen-blazor +9%. The perf fix brings them below wave 1 (zod 2.90 -> 2.55 s, Newtonsoft.Json 5.21 -> 5.16 s, radzen-blazor 15.49 -> 14.29 s) with identical output.

**WHY:** Wave 2 added symbols and owner lookups to code whose cost grew with symbol count or tree depth. tree-sitter 0.26 `Node::parent` and `next/prev_named_sibling` search down from the root on every call (linear in child index at each level), so upward walks cost depth squared and are very slow in wide files (lockfiles, test files with many top-level statements).

**HOW (all output-neutral):**
- `tree_traversal::ancestors(root, node)`: one descent with `child_with_descendant`. Used by `OwnerIndex` (TS/JS/Dart/Swift) and C# `MemberScope` (now takes the root).
- C# relationships: `CallSites { owners: MemberScope, targets: ScopedSymbolIndex }` built once per pass instead of per call site (1.2 s -> 0.05 s on JsonSerializerTest.cs).
- `config_literals::ConfigKeyIndex`: id -> position index for JSON/TOML/YAML key-path carriers (replaced `build_config_key_carrier` linear scans; verifies id, falls back to scan).
- `containing_symbol::narrowest_byte_containers`: sweep by start byte for the first binder pass (data facts on pnpm-lock 329 -> 65 ms).
- YAML: `test_roles_possible` flag skips test-role parent walks; `body_span_rule = |_, _| None` avoids a thrown-away body hash; trailing-doc lookup pre-filtered by `LanguageSpec::may_hold_trailing_doc_comment` on the rest of the line.
- C# `is_csharp_type_usage_identifier` reuses the first parent.

**Evidence:** goldens unchanged; every extraction table identical on 13 repos (`86f496f3` vs final); fmt, workspace clippy, doc sync, quality 0/0 (backlog 25), xtask, default (42 s), contract, capability, reference_site_identity all pass. New tests: `sweep_binding_matches_a_scan_of_every_symbol`, `carrier_joins_the_parent_chain_names_and_the_key`, `carrier_reads_a_replaced_symbol_list_by_scanning`.

**Also:** the comparison showed wave-2 row changes the 3.4.0 ledger did not declare. Added: C# directive blanking (only the first `#if` branch extracts; Newtonsoft diagnostics 857 -> 5), F# auto-property rewrite, Lua call-argument table fields and setmetatable classes gone, QML declaration-site variable_ref gone, JS data object literal properties gone, YAML flow pairs/anchored items as symbols, Razor render-fragment tags, Kotlin null/true/false. Evidence doc: `docs/evidence/2026-09-23-language-gap-wave2-real-world.md`.

**IMPACT:** Alamofire stays ~10% slower than wave 1 because it writes ~190k more rows (HTML link pending rows, literals); no single file got slower. Remaining before release: Windows default tier on the final head, then user approval for push/tag/release and worktree cleanup.
