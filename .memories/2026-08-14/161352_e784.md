## Task 5B no-change import recovery passed

### WHAT

Julie ordinary full Import now reuses the prior manifest terminal record's durable `row_counts` when the manifest is reused. The executor validates family, view, generation, manifest hash, completion level, terminal uniqueness, and unsigned numeric count fields before reuse; every missing, corrupt, duplicate, or mismatched case falls back to the existing 17-table count query.

### WHY

Miller no-change startup spent about 24.8 seconds in Julie Import. Core dumps also proved repeated SIGBUS faults in SQLite `walFindFrame` while the terminal row-count query read the mapped `store.db-shm` during the writer transaction.

### HOW

Added a narrow optional result-count path and test-first contract coverage. A feature-enabled crash boundary proves a valid reused import never enters `terminal_row_counts`; fallback cases cover malformed/missing data, identity mismatches, completion mismatch, nonnumeric counts, and duplicate terminal rows. No schema, payload, WAL mode, or public API changed.

### IMPACT

Direct fresh-key no-change Import fell to a 308 ms measured median from 24,826 ms. The exact frozen-source Miller replay passed 8/8 runs: startup median 1,418 ms, workspace-open median 1,018 ms, import about 326–333 ms, resolution skipped, no crashes/cores/claims/leases, and exact generation/hash/counts preserved.
