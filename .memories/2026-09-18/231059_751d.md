## Task 4: Python, Swift, Dart, Lua, GDScript split compound call receivers

**WHAT:** every site in `python/relationships.rs`, `swift/relationships.rs`, `dart/pending_calls.rs` (4 sites), `lua/relationships.rs`, and `gdscript/relationships.rs` (4 sites, via a small `qualified_target` helper) that built a target from `"{receiver}.{terminal}"` text now tries `UnresolvedTarget::from_qualified_text` first and keeps the old target on `None`. One new test per language in `tests/<lang>/cross_file_pending.rs`; the pre-existing GDScript assertion in `tests/gdscript/cross_file_relationships.rs` now expects receiver `inventory`, namespace `["player"]`.

**WHY:** `Outer.Inner.chain()` recorded the compound receiver `Outer.Inner`, which no consumer can match. Plan `docs/plans/2026-09-18-qualified-call-chain-receivers.md` in code-kb, Task 4.

**HOW:** Python keeps `receiver_type` for `self`/`cls` untouched (`self.repo.save()` gives receiver `repo`, namespace `["self"]`). GDScript applies the split only to chains of three or more parts because its golden fixtures record two-part display names with a `()` suffix. `lua/core.rs` unchanged (that site is a `require` import).

**IMPACT:** nested-class and module-qualified calls in these five languages now carry a single-identifier receiver. Lead inline review clean; committed by the lead (parallel-lead-commit).
