## Task 1: shared chain helper and the C# qualified call chain fix

**WHAT**
- Added `UnresolvedTarget::from_chain(parts: Vec<String>)` and `UnresolvedTarget::from_qualified_text(text, separators) -> Option<Self>` in `crates/julie-extractors/src/base/relationship_resolution.rs`, with 11 unit tests in a `#[cfg(test)] mod tests` at the end of the file.
- Replaced the flat identifier scan in `unresolved_call_target_at_depth` (`crates/julie-extractors/src/csharp/relationships.rs`) with a recursive `collect_chain_parts` walk that descends into nested `member_access_expression` nodes, takes `identifier` children, and takes the identifier child of a `generic_name`. It calls `from_chain`.
- Added `test_csharp_qualified_call_chain_keeps_receiver_and_namespace` in `crates/julie-extractors/src/tests/csharp/cross_file_pending.rs`.

**WHY**
- `Outer.Inner.Method(...)` in C# produced a bare target with no receiver, so code-kb could not match the call to the nested method. Later julie tasks (Java, Kotlin, Go, and others) need the shared constructors.

**HOW**
- Target shape for `Q1 ... Qn.t`: terminal `t`, receiver `Qn`, namespace `[Q1 .. Qn-1]`, display joined with `.`. One or zero parts fall back to `simple`.
- `from_qualified_text` splits on every separator, trims, and returns `None` when any part is empty or is not a plain identifier (ASCII letters, digits, `_`, `$`, `@`).
- `this`/`base` receivers contribute no part, so those calls keep their old simple target and `self_receiver_type` handling.

**IMPACT**
- Verified: `cargo test -p julie-extractors base::relationship_resolution` (11 pass), `cargo test -p julie-extractors tests::csharp::cross_file_pending` (3 pass, new test was red before the fix), `cargo xtask test language csharp` unit tier 143 pass, clippy clean.
- Golden tier mismatch for the lead: `fixtures/extraction/csharp/http_client/expected.json` records the old wrong callee `client` for `client.GetFromJsonAsync<User>()`; the fix now yields `client.GetFromJsonAsync` with receiver `client`. The fixture is outside task ownership and the repo gates golden changes behind the extraction contract review (`EXTRACTION_CONTRACT_VERSION` in `lib.rs`).
