## Wrote the receiver-type-facts implementation plan

- **WHAT:** `docs/plans/2026-09-01-receiver-type-facts-implementation.md` — 10 tasks: base helpers + contract doc, C# correctness, C# parameters, then TS/JS, Python, Rust, Go, Java in a parallel batch, an evidence scan, and closeout with capability claims and open_gaps debt.
- **WHY:** Turns the receiver-typed call resolution spec into executable work. Miller policy v6's receiver tier already binds a receiver symbol through its `type_facts` rows; the extract just has to supply the facts.
- **HOW (key ground truth):** A real extract of `Miller.Core/Graph/{SymbolGraph,GraphTraversal}.cs` showed: 30/215 C# locals untyped (all `var x = new Foo()`), field facts truncated inside generics (`IReadOnlyDictionary<string,`), all rows wrongly `is_inferred=1`, and no parameter symbols in any language. The plan fixes these and adds parameter symbols (kind variable, metadata role=parameter) so Miller's scope walk finds them. `resolved_type` = base type name (generics/nullable/sigils stripped), full text in metadata `declared`.
- **CAVEAT:** The spec's reproduced example uses receiver `GraphTraversal`, an `internal` static class. Policy v6 refuses internal types cross-file, so that exact chain needs a Miller-side policy change; recorded in the plan and the decision doc.
- **IMPACT:** Wave 1 = 7 languages; wave 2 languages become open_gaps entries pointing at a named follow-up plan. Epoch stays 9 (unreleased). Work runs in worktree `.claude/worktrees/receiver-typed-call-resolution`.
