## WHAT

Fixed cursor advance/release accidentally hydrating a full GC plan before changing one coordinator row. Added bounded cursor binding validation and optional cursor_only report measurement scope; noncursor snapshots unchanged. Evidence: docs/findings/2026-09-06-cursor-command-cost.md.

## WHY

Miller M2 dogfood hit repeated 10-second CPU-bound cursor timeouts on a live family with 7.1M historical manifest entries. Import itself was progressing; reader exclusion was not the cursor bottleneck.

## HOW

Reused original transactional cursor methods and reader safety. Read-only validation checks schemas, identity, version floors and generation/maintenance eligibility. Deterministic manifest read-trap failed before and passes after for both cursor actions/modes. Plan mode deliberately refuses ineligible writers and writes no DB bytes.

## IMPACT

Same 1M-entry fixture, alternating release binaries, warmup+3 quiet runs: advance p95 2.272678s to 0.005595s; release 2.309953s to 0.005579s. 24 CLI maintenance, 4 reader/cursor and 28 connection tests pass; clippy and release build clean. No live DB mutations or resident-process kills. Local fix ready for lead integration; no merge, push, tag, version bump or release yet.
