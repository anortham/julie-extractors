## arg_count angle rule: tree-token straddle rule replaces the text scanner

**WHAT:** In julie 3.8.0 `call_arguments.rs`, the argument count of a call in TS, TSX, C#, C++, and Kotlin is dropped (no key) when a `<`-family leaf token comes before a top-level comma of the argument list and a `>`-family leaf comes after it. A second check drops the key when the top-level leaf comma count differs from the tree count.

**WHY:** Rounds 3 to 5 patched a hand-written text scanner (`scan_angles`, span content checks, `literal_end`, tail lists). Each oracle check (TypeScript API, Roslyn, clang AST, Kotlin PSI) found new wrong counts on valid code:
- stack pairing: C++ `q(a < b, u<A>(x))`;
- span content: C# `q(x < this.Max, y > (z))`, TS `q(a < b, c || d > (e))`;
- lexing blind spots: C++ raw strings, TS regex, JSX text, C# verbatim strings.

**HOW:** The only way a comma changes meaning in an error-free tree is that one reading puts it inside `<...>`. In both readings, a `<` token sits before it and a `>` token after it at the top level. Parens, brackets, and braces never cross an angle list. The tree's own leaves give correct lexing, so literals cannot hide a `<`.

**IMPACT:** The rule loses more keys (C# `out Dictionary<A, B> v`, `new T<A, B>[n]` in arguments), but a lost key means "unknown" and is safe for the code-kb arity rule. Real corpora showed 0 wrong keys in every round. The wrong counts only came from contrived oracle shapes.
