## julie 3.8.0: call argument counts (`arg_count`, `arg_spread`)

**What:** every `call` identifier in Python, JavaScript, TypeScript, TSX, Java, C#, Go, Rust, Kotlin, C, and C++ gets `metadata_json.arg_count`, plus `arg_spread: true` for a spread or splat argument. New post-pass `crates/julie-extractors/src/base/call_arguments.rs`, tests in `tests/call_argument_counts.rs` (76), ledger `## 3.8.0` in `docs/contracts/extraction-output-changes.md`, 146 goldens (only the two new keys). Version 3.8.0 in the three crates.

**Why:** code-kb phase 2 slice 3 uses the call-site count against the parameter range of the target as exclusion evidence. The feature rule: a key must be right or absent.

**How (after 8 rounds):**
- The angle ambiguity (`f(a < b, c > (d))`) uses a tree-leaf rule, not a text scanner: in TS, TSX, C#, C, C++, Kotlin there is no key when a top-level comma sits at angle depth above 0 and a `>`-family leaf follows it, plus a safety net that compares the leaf comma count with the tree count. `<=`/`<<=`/`>=` weigh 0; `<<` weighs 2 only in TS/TSX; the C# type after `new` is skipped.
- C#: no key when a directive line (as the blanker reads it, also inside a string or comment) lies between the call start and the end of the list.
- C/C++: counts written arguments before preprocessing (stated limit for comma macros).
- Rust macro-argument calls carry no key (lead decision).

**Evidence:** oracle checks (TypeScript API, Roslyn on 10 C# corpora, libclang on nlohmann, Kotlin PSI on moshi, grammar fuzzers, mutation fuzz on 11 languages) show 0 wrong keys; 770 of 2,039,175 keys lost against round 4 (0.038%). Gate: fmt, clippy, doc sync, language-data-quality, `xtask test default` 6914 passed, contract, compat-check against 3.7.2.

**Impact:** next is the code-kb dogfood round with this binary, then the julie 3.8.0 release (authorized by the owner).
