## TODO #16 diagnosed: identifier target-resolution gap is a kind-filter problem, not a missing tier

Investigated the C# identifier target-resolution entry added in `058b166a`. The measured numbers reproduce, but the entry's **diagnosis and proposed fix are both wrong**. Verified with 8 subagents plus direct SQL against `/Users/murphy/source/miller/.miller/symbols.db`.

### WHAT the entry gets wrong

- **"member_access 0.2% suggests the receiver path is not being walked at all"** — false. 43,545 of 44,959 C# `member_access` rows carry a receiver; only 1,414 come back `no_context`. The walk runs and dies downstream.
- **"Proposed fix: add a conservative unique-name fallback tier"** — that tier already exists: tier 4 `unique-language-global`, `CONFIDENCE_TIER4 = 0.55`, `METHOD_TIER4 = "tier4_global"` (`crates/julie-extract-cli/src/resolution.rs:52,59`).
- **"17,112 call rows unresolved despite a unique same-artifact name"** — inflated. Only **9,331** point at a `method`; **7,116** point at an `enum_member` (coincidental). The entry's own caveat was right; the answer is that tier 4's existing kind filter already rejects them, so no shadowing check is needed.

### ROOT CAUSE (ranked)

1. **`tier4_compatible_kinds(Call)` excludes `SymbolKind::Method`** (`resolution.rs:823`). C# has 9,412 methods vs 117 functions + 267 constructors, so ~97% of C# callables are structurally ineligible. Controlled comparison inside the same artifact: pending `instantiates` (Class/Struct/Constructor allowed) resolves 2,840/9,052 = **31%**; `uses` 555/1,295 = **43%**; `calls` 345/60,734 = **0.6%**. Only the kind filter differs.
   - Stated rationale (`docs/plans/2026-07-06-workspace-reference-resolution-design.md:177`, from accepted doubt-pass finding 6 at `:357-359`): "member names collide too heavily for global uniqueness to mean anything." **Asserted, never measured.** Measured: **7,343 of 7,960 (92%)** C# callable names are unique workspace-wide.
   - 4 unit tests pin the exclusion: `resolution.rs:2184, 2485, 2513, 2609`.
2. **Tier 2 is off for C#** — `TIER2_IMPORT_LANGUAGES = ["typescript","javascript"]` (`resolution.rs:77`). C# `call`/`type_usage` therefore have exactly one available tier, and that tier has no methods in its kind set.
3. **Tier 3 starves at receiver→symbol.** Funnel: 43,545 receivers → **1,544** resolve to a scope symbol (−96.5%) → 719 have a type fact → 466 name a unique type → **96** find the member. C# emits **zero** `SymbolKind::Variable` symbols (no `local_declaration_statement` arm in `csharp/mod.rs:220-252`) and `infer_variable_type` returns `None` unconditionally (`csharp/type_inference.rs:130-132`). All 12,438 C# type facts are `is_inferred: true` (`factory.rs:14-34`), capping tier 3 at 0.65.
4. **`tier123_compatible_kinds(MemberAccess)` = [Property, Field, Method]** excludes `Constant` and `EnumMember`. 3,853 of the 8,705 unique-name `member_access` residual point at constants/enum members — `SomeEnum.Value` can never resolve at any tier.
5. **Reporting leak:** `resolve_identifier_items` skips identifiers "covered" by a pending relationship (`resolution.rs:1351`). When the pending edge fails, the identifier gets **no `identifier_resolutions` row at all** — 61,655 C# call sites appear as neither `resolved` nor `missing`, so the resolution report understates the gap.

### HOW measured

`reference_resolution_status='partial'` means **tier-2 language gating**, not incomplete coverage (`resolution.rs:1028`: `if effective_full && gated.is_empty()`). The measurement is a fair full pass.

### IMPACT

The highest-leverage change is adding `SymbolKind::Method` to `tier4_compatible_kinds(Call)` — the exactly-one-candidate guard already provides the safety the design doc was worried about, and 92% name-uniqueness says it will rarely trip. That reverses an accepted design decision, so it needs a product call before implementing.
