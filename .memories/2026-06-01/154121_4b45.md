## Persisted capability snapshot rows for v0.1.0 audit

- **WHAT:** Added artifact-level capability snapshot persistence so `julie-extract scan` writes `parser_inventory`, `language_capabilities`, `language_capability_fixtures`, and `language_capability_gaps` rows. Aligned `julie-extractors` crate metadata to v0.1.0 and updated release notes with the refreshed binary SHA and performance baseline.
- **WHY:** The release-candidate audit found a contract mismatch: docs and JSONL/report contracts exposed capability rows, but real dogfood artifacts had zero rows.
- **HOW:** Added generic artifact capability snapshot model structs and an idempotent writer sync method, mapped the extractor crate capability snapshot into artifact rows in the CLI before mutations, and included capability rows in scan/update/delete row-count reports when they are written.
- **IMPACT:** SQLite and JSONL artifacts now expose capability evidence to non-Rust consumers, no-change rescans remain stable, and the release candidate no longer hides known capability gaps.
