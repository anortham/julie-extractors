## Incremental Scan Hash Skip

### WHAT
Implemented the first scan-performance slice for `julie-extract`: incremental scan now reads and hashes supported source files before parser extraction, loads existing SQLite `files(path, content_hash)` rows from a root/schema-validated artifact, and skips parser/extractor work for files whose current hash matches.

### WHY
`ArtifactWriter` already skipped row churn for unchanged content hashes, but the CLI still parsed every supported file before the writer could skip. This reduced SQLite churn but not parser cost.

### HOW
- Added `SourceSnapshot` in `crates/julie-extract-cli/src/extraction.rs` so source content, BLAKE3 hash, byte count, and line count are computed once.
- Refactored parsed extraction to map from the snapshot, preserving existing file metadata.
- Added `unchanged_artifact_file` to create file-level placeholder rows for unchanged files with empty child rows.
- Updated `scan` in `crates/julie-extract-cli/src/commands.rs` to load existing hashes after root/schema validation and to use the hash map only for non-force incremental scans.
- Added focused unit tests proving unchanged files do not invoke the extraction callback and force scans still extract all files.
- Documented the work in `docs/plans/2026-06-01-incremental-scan-hash-skip.md`.

### IMPACT
Incremental scans avoid parser/extractor work for unchanged files while preserving writer-owned revision handling, deletion detection, no-change reporting, and SQLite transaction behavior. No public CLI, SQLite, JSONL, or report contract changed.
