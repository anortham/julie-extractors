## Dogfood Incremental Rescan Baseline

### WHAT
Added the next product-bootstrap performance slice: `cargo xtask dogfood repo` now runs an immediate second `julie-extract scan` against the same SQLite artifact after the cold scan.

### WHY
The previous incremental scan optimization made unchanged files skip parser/extractor work, but dogfood only measured cold scan, info, and JSONL export. The release evidence did not exercise the no-change incremental path.

### HOW
- Added `rescan-report.json` to `DogfoodOutputPaths`.
- Added `rescan` duration to `CommandDurations` and serialized `rescan_duration_ms` plus rescan changed/unchanged/deleted/failed counts in `DogfoodMetrics`.
- Updated `run_repo` to execute cold scan, immediate rescan, info, and export through the public `julie-extract` CLI.
- Added `validate_rescan_report` so dogfood requires `status=no_change`, `operation=scan`, `mode=incremental`, nonempty unchanged count, zero changed/deleted/failed files, and empty errors.
- Added red/green contract coverage in `xtask/tests/dogfood_contract.rs`.
- Documented the implementation plan and updated release/testing docs for the new evidence shape.

### IMPACT
Dogfood now captures hard evidence that the just-built artifact supports a no-change incremental rescan, and report-only timing shows the optimized path. The first observed run on this branch had cold scan `18141ms`, immediate rescan `214ms`, and export `75135ms`.

No public `julie-extract` CLI, SQLite, JSONL, or report contract changed.
