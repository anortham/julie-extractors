## v2.0.0 And Test-Role Contract Alignment

### WHAT

Updated the active branch to target v2.0.0 and promoted test identification metadata into first-class artifact fields.

- Workspace crate versions and release workflow defaults now use `2.0.0`.
- Added `docs/release-notes/v2.0.0.md` and tracked the work in `docs/plans/2026-06-01-v2-0-0-version-and-test-role-contract.md`.
- SQLite `symbols` now includes indexed `is_test`, `test_container`, and `test_lifecycle` booleans.
- CLI extraction maps existing extractor metadata into those booleans.
- JSONL `symbol` records expose explicit test-role booleans while preserving metadata keys.

### WHY

The old Julie extractor crate was already at `1.22.0`, so publishing the standalone product as `0.1.0` would look like a downgrade. Also, preserving `is_test` only inside generic JSON metadata made downstream test filtering slower and weaker than the product contract should allow.

### HOW

- Kept artifact contract versions at v1 while changing package/release version to v2.0.0.
- Used the existing extractor metadata keys as source of truth instead of inventing a speculative `test_role` enum.
- Added schema/index contract checks, JSONL payload checks, and a CLI end-to-end test using a JavaScript test fixture.

### IMPACT

Downstream consumers can now query test cases, containers, and lifecycle hooks through indexed SQLite columns while metadata-oriented consumers still see the old keys. The active plan and brief now reflect the v2.0.0 release target.
