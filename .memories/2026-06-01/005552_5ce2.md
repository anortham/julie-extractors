## Split xtask command routing

- **WHAT:** Completed Task 1 from the post-bootstrap release-readiness plan by moving top-level `cargo xtask` dispatch into a new `xtask::commands` module.
- **WHY:** `test_tiers.rs` was starting to own unrelated release routing, which would get worse once dogfood and package commands are added. The split keeps test-tier planning separate from repo command dispatch.
- **HOW:** Added `xtask/src/commands.rs`, updated `xtask/src/main.rs` to call `xtask::commands::run_from_env_args`, exported the module from `xtask/src/lib.rs`, removed `run_from_env_args` from `test_tiers.rs`, and added `xtask/tests/commands_contract.rs` for route ownership and exact live-command output.
- **IMPACT:** `test_tiers.rs` no longer references release-package routing. Existing `cargo xtask test list` and `cargo xtask release package-list` behavior remains byte-compatible, giving Task 2 and Task 3 a clean route owner for dogfood and package commands.
