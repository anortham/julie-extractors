## Restore safe writer-open schema repair

- **WHAT:** Moved `idx_read_symbols_symbol` and `idx_read_symbols_parent_name` out of the monolithic store schema SQL into the crate-private idempotent `ensure_read_symbol_indexes` helper. `create_store_schema` still installs the additive indexes; `StoreConnectionFactory::open_writer` now calls only that helper plus `ensure_resolution_scope_feature`.
- **WHY:** The candidate release change made writer open run the entire schema batch. On a legacy store with duplicate terminal resolution rows, recreating a unique terminal index failed before Julie import could validate and apply its existing fallback.
- **HOW:** Kept all unique/domain-invariant indexes behind full schema creation and allowed writer open to repair only the two post-baseline non-unique query indexes. The exact regression was RED before the change and GREEN after it.
- **IMPACT:** Legacy stores with stale terminal data can reach import validation/fallback again without weakening unique invariants. Public APIs remain unchanged.
