## Reviewed accumulated-resolution rebase design

### WHAT

Created and adversarially reviewed `docs/plans/2026-08-16-accumulated-resolution-work-rebase-design.md`. This is a reviewed draft only; no implementation, commit, push, or release was performed.

### WHY

A Miller dogfood resolve processed 79 accumulated paths, reported 227,249 scoped rows, and took 100.3 seconds. The producer needs a bounded way to compact accumulated base-plus-delta state without changing Miller or public store contracts.

### HOW

- Preserved the existing store admission rule exactly: duplicated identifier-query reads with inclusive `>= 70%`, including its zero-identifier file/version fallback.
- Defined a separate rebase signal: scoped mode, more than one validated transition, nonzero corpus, and unique `(version_id, identifier_id)` coverage strictly greater than 25%.
- Kept the bit on crate-private `StoreResolutionDecisionTelemetry`; it must not enter durable execution telemetry, reports, SQLite, or public Rust types.
- Required the CLI to evaluate the artifact rebase check first, then OR the ephemeral bit, preserving validation and error ordering.
- Corrected the rationale: exact publication already clears scope batches; rebase additionally rotates to a new base with an empty delta and removes prior-overlay copy-forward.
- Added deterministic boundary, serialization-leak, error-order, scope-retirement, exact-equivalence, platform, and reproducible 79-transition performance criteria.

### IMPACT

The design now targets the real persistent state, separates incompatible measurement units, avoids repeated rebase after a single high-fanout edit, and requires no Miller or Store Contract change. It is ready for user review before implementation planning.
