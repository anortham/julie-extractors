## Task 8: identifier metadata transport (Qt lane A)

**WHAT.** The extractor `Identifier` now carries an optional metadata map, and those keys reach the artifact `identifiers.metadata_json` column.

**WHY.** The Qt lanes need to attach facts to a usage site (for example a QML binding target) and read them back from the artifact. Before this, an identifier could only carry `receiver_type`.

**HOW.**
- `crates/julie-extractors/src/base/types.rs`: new field `Identifier.metadata: Option<HashMap<String, serde_json::Value>>`, with `#[serde(default, skip_serializing_if = "Option::is_none")]` so every existing JSON shape stays byte-identical.
- `crates/julie-extractors/src/base/creation_methods.rs`: new `BaseExtractor::create_identifier_with_metadata`. The old struct literal moved into a private `push_identifier`, so `create_identifier` and `create_identifier_with_receiver_type` keep their signatures and delegate.
- `crates/julie-extract-cli/src/extraction.rs`: `map_identifiers` merges the extractor map last, so extractor keys beat the mapper's own receiver detection. `receiver_before_identifier` is untouched and still runs for `call` and `member_access` only.
- Three other `Identifier` struct literals (vue, css, tests/path_identity) got `metadata: None` so the crate compiles.

**Spool.** No change needed. `ArtifactIdentifier` and `SpoolIdentifier` already carry `metadata_json`.

**IMPACT.** Goldens for qml and rust are unchanged, and the default tier is green.
