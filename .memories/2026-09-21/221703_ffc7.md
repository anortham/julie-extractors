## Lane D: QML symbol arms (tasks 3-7 of the Qt 3.2.0 gap closure)

**WHAT** — `qml/mod.rs::traverse_node` gained two arms and three behavior changes:

- `ui_inline_component` emits a `Class` symbol, signature `component Name: Base`, metadata `base_types: [Base]`; its members parent to it because the arm sets `current_symbol`.
- `ui_signal` now sets the signature to the declaration text and records `parameters` (name, type) from `ui_signal_parameters`.
- `pragma Singleton` prefixes the root class signature with `singleton ` and sets `singleton: true`; every pragma also emits a new `qml.pragma.v1` structural fact with `name` and `value`.
- `ui_required` emits a `Property` symbol with `required: true`, `inherited: true`.
- A `ui_property` whose value spans lines keeps the declaration head only (`property var shellValues`).

**WHY** — A Qt developer's questions (which components extend X, who handles signal Z, is this a singleton) had no answer in the artifact. The audit is in code-kb `docs/plans/025-qt-qml-first-class-support.md`.

**HOW** — Three helpers in `qml/semantics.rs`: `property_signature`, `signal_parameters`, `file_declares_singleton`. The singleton check walks up to `program` and scans its `ui_pragma` children, so no pre-scan state is needed on the extractor.

**IMPACT** — 9 new tests, 151 qml lib tests green, `cargo xtask test language qml` green. New golden fixture `fixtures/extraction/qml/qt_symbols` covers all five items; its `expected.json` is generated but its capability-matrix row is NOT added (integration lane owns `capabilities.json`).

**HAND-OFF for the integration lane**

1. `capabilities.json`: add `qml.pragma.v1` to the qml `kind_coverage.structural_facts.supported` list (the `test-capability-matrix` test `capability_matrix_structural_fact_claims_match_registry` is red without it), and add the `qt_symbols` fixture row.
2. `structural_fact_registry/builtins/extra.rs`: add the `qml.pragma.v1` spec (languages `["qml"]`, family `pragmas`, keys `name` String/Always, `value` String/Optional), then regenerate `docs/contracts/structural-fact-patterns.json` with `UPDATE_CONTRACT_JSON=1`. Without it the registry conformance test fails once the fixture is registered.
3. Existing goldens changed only in signal rows (signature plus parameters metadata).
