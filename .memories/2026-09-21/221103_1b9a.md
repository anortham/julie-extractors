## qmldir type rows now carry the `export` kind (Qt lane B, task 13)

**WHAT** — `push_type_symbol` in `crates/julie-extractors/src/qmldir/mod.rs` emits `SymbolKind::Export` instead of `SymbolKind::Class`. This covers all three call sites: object types, singletons, and internal types. The `module` row is untouched and stays `SymbolKind::Module`.

**WHY** — A qmldir manifest declares what a module exports. It does not define a class. The class lives in the `.qml` file. Release 3.2.0 task 13 of `docs/plans/2026-09-21-qt-first-class-gap-closure.md` asks for the honest kind so a lookup list shows the export next to the class.

**HOW** — One enum variant changed at the single emission point. Metadata is unchanged: `qmldir_kind`, `type_name`, `file`, `version`, `singleton`, and `internal` all stay. Visibility stays. TDD: the two existing tests in `crates/julie-extractors/src/tests/qmldir/mod.rs` were changed to expect `Export` first and failed for the right reason, then the code change turned them green. The metadata test also gained kind and `internal` assertions for the `Internal` row.

**IMPACT**
- The golden `fixtures/extraction/qmldir/basic/expected.json` changed on exactly three lines: `Button`, `Private`, `Theme` go from `"kind": "class"` to `"kind": "export"`. Nothing else in the golden moved.
- `cargo xtask test language qmldir` passes on the final tree.
- **Open for the integration lane:** `fixtures/extraction/capabilities.json` still claims `class` for qmldir in `kind_coverage.symbols.supported` and `kind_coverage.body_spans.supported`. The test `capability_matrix_supported_kind_claims_have_fixture_evidence` will fail until both lists say `export`. That file is not owned by this lane, so it was left alone.
