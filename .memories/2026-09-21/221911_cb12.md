## Lane C: Qt JavaScript directives (`.pragma`, `.import`) in `.js` files

**WHAT.** A new pre-pass `crates/julie-extractors/src/javascript/qml_directives.rs`
recognizes Qt's QML JavaScript directives at the head of a `.js` file, blanks each
one to same-length spaces before the parse, and records it as extraction output.

**WHY.** `.pragma library` and `.import QtQuick 2.0 as QQ` are not JavaScript.
`tree-sitter-javascript` reported a parse error, so `julie-extract check` rejected
every real Qt JS file (for example `omarchy/shell/Commons/BorderGeometry.js`).

**HOW.**
- `blank_directives` returns `None` when a file carries no directive, so the common
  JavaScript path allocates nothing.
- `scan` walks the header region only. Blank lines, `//` comments, and `/* */`
  comments are allowed above the directives. The walk stops at the first line that
  is none of those, so `.pragma library` after real code stays untouched.
- Only the exact Qt shapes match: `.pragma <Identifier>`,
  `.import <ModuleUri> <version> as <Name>`, `.import "<path>" as <Name>`.
  `.5`, `.importantly()`, and `.pragma` alone are left alone.
- Blanking preserves every byte length, including the `\r` of a CRLF file, so byte
  spans of later symbols still point into the original text.
- Both parse paths call the same pre-pass: `pipeline::parse_for_language` and
  `syntax::parse_source_with_options` (the `check` path).
- `.import` becomes an `Import` symbol with the QML import metadata keys (`source`,
  `source_kind`, `version`, `alias`, `local_name`, `imported_name`, `import_kind`,
  `is_namespace`). `import_kind` reuses `crate::qml::import_kind`.
- `.pragma` becomes a `javascript.qml_directive.v1` structural fact. The shared
  registry macro drops extractor facts, so `registry.rs` now wraps the
  macro-generated `extract_javascript_program` with a small `extract_javascript`
  adapter that returns them.

**IMPACT.** `julie-extract check` accepts Qt JS files. A Qt developer can find which
QML module or JS file a helper imports, and which helper files are `.pragma library`
singletons.
