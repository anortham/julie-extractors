## QML reference contract: tasks 9-12 of the Qt first-class plan

Lane F of julie-extractors 3.2.0. One reference contract for QML type and handler references.

### WHAT
- **Task 9** — a qualified type name (`QQC2.Button`) now records the terminal segment as the identifier name and the dotted qualifier as `receiver` metadata. No dotted `type_usage` names remain.
- **Task 10** — the root `ui_object_definition` emits a `TypeUsage` identifier with `role: "base_type"`, contained by the root class itself, plus an `extends` relationship to the base type. A same-file inline component resolves concretely; everything else becomes a structured pending row with terminal name, receiver, and import context.
- **Task 11** — a `ui_binding` whose name has a capitalized head (`Layout.fillWidth`, `Kirigami.FormData.label`) emits a `TypeUsage` identifier with `role: "attached_type"`.
- **Task 12** — an `on<Signal>` binding and a `function on<Signal>()` inside a `Connections` object emit a `MemberAccess` identifier named after the signal with `role: "signal_handler"`. `on<X>Changed` points at property `X` with `change_handler: true`. The receiver is the `Connections.target` id when it is a plain id, else the enclosing object's type text. The function form now also carries `handled_signal` on its symbol.

### HOW
- New `qml/semantics.rs` helpers: `dotted_segments`, `attached_type_segment`, `handler_target_member`, `handler_receiver`, `enclosing_object_type`.
- `qml/identifiers.rs` gained `ui_binding` and `function_declaration` arms plus four private recorders; the root/nested split now reuses `semantics::enclosing_object` instead of its own ancestor walk.
- `qml/relationships.rs` reuses the instantiation walk: the root object picks `RelationshipKind::Extends` and the root class row as `from`.

### IMPACT
- Omarchy corpus (106 QML files): 106 `base_type` identifiers, 106 `extends` pending rows, 951 `signal_handler` identifiers across 85 files, 287 change handlers, attached types led by `Layout` (56) and `Keys` (55). Zero dotted `type_usage` names left.
- `cargo xtask test language qml` and `cargo xtask test default` are green. 16 new unit tests.
- The `qt_symbols` fixture gained qualified instantiations, an attached binding, both Connections handler forms and an `onXChanged` handler; every QML golden was regenerated.
- Known side effect: a `.qmltypes` root `Module {}` also gets a `base_type` identifier, because the identifier walk has no typeinfo guard. The relationship walk still skips typeinfo paths.
- Left for the integration lane: registering `fixtures/extraction/qml/qt_symbols` in `capabilities.json`, the `extends` pending kind, and the three identifier roles in the capability matrix.
