## Completed GLM remediation Task 3

### WHAT
Fixed frontend route and file precision issues from the GLM review remediation plan.

### WHY
The web structural fact collectors were over-emitting from nested route-object metadata, mishandling JS string escapes, classifying some Next/Nuxt file routes incorrectly, missing statically-known Nuxt links, and treating type-only imports as route evidence.

### HOW
- Added regression coverage for React/Vue nested `redirect` and `meta` paths, JS escape decoding/rejection, Next `pages/app/page.tsx`, JSX nested route parent metadata, Nuxt `:to` and relative links, CSS selector commas inside attributes, and type-only React Router imports.
- Tightened JS route-object scanning with owner-property context and stricter string parsing.
- Preserved pages-router evidence policy while preventing `pages/app` from being treated as the app-router root.
- Added JSX route stack handling for parent/effective route metadata.
- Expanded Nuxt route reference parsing for static bound `to` values and internal relative links.
- Updated the remediation plan checkboxes for Task 3.

### IMPACT
Frontend route/file precision acceptance criteria are complete and Task 4 backend framework remediation can start.
