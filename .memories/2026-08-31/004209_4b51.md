## WHAT

Implemented Rustdoc fence extraction as `rust.doc_test.v1` structural facts. Added the language-local collector, pipeline wiring, registry metadata including `mode`, API contract marker, Rust tests, fixture evidence, capability closure, and generated structural-fact contract.

## WHY

Rust `///` and `//!` executable examples were an open structural-fact gap. The packet requires exact source spans, deterministic IDs, explicit `run`/`ignore`/`no_run`/`compile_fail` modes, normal symbol attachment, and silence for ordinary/text/non-Rust/unterminated fences.

## HOW

The collector walks tree-sitter `line_comment` nodes, recognizes only `///` and `//!`, removes the comment prefix while retaining source byte offsets, pairs matching backtick fences within one comment block, classifies rustdoc attributes, creates `StructuralFact` rows with base metadata plus `mode`, applies shared containment and explicit outer-doc attachment, and sorts deterministically. The test-only structural pattern inventory and generated `docs/contracts/structural-fact-patterns.json` were updated because registry/capability gates require them.

## IMPACT

Rustdoc cases now publish through the canonical artifact without fabricated symbols or test roles. Rust capability structural facts are complete for this domain and strict data quality reports zero silent cells and zero quality-bar debts. Lead-owned BRE-16/BRE-43 plan edits remain unstaged and untouched. Broad clippy still reports an unrelated pre-existing warning in `crates/julie-extractors/src/go/test_calls.rs`.
