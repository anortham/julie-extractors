## BRE-43 review corrections ready to commit

### WHAT
Added TDD coverage and fixes for two review findings in the Go standard subtest collector. Callback function literals now require the exact testing.T.Run callback shape: one non-variadic parameter declaration with type `*testing.T`, at most one name, and no result. Receiver validation now scans preceding declarations in each enclosing block so `var` and short-variable bindings shadow outer testing parameters.

### WHY
The first implementation accepted arbitrary function-literal callbacks and incorrectly accepted `t.Run` after a nearer local `t` shadowed the active `*testing.T` parameter.

### HOW
Miller re-oriented the owned files and inspected the collector, receiver helper, declaration extraction helpers, and tests before edits; trace refs followed the existing collector call path. The locked tree-sitter-go grammar was checked directly: `parameter_declaration` exposes repeated `name` plus `type`, `var_spec` exposes repeated names, short declarations expose `left`, blocks contain `statement_list`, and function literals expose `parameters`/optional `result`. TDD tests were written first and each failed against the prior commit; minimal callback-shape and block-sibling binding checks then made them pass. Existing parent/child and Ginkgo behavior remained intact.

### IMPACT
The review findings are addressed without a general resolver, new public vocabulary, or fixture changes. Worker-scope focused Go detection and `cargo xtask test language go` pass. Lead-level broader gates remain.
