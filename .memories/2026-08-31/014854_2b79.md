## F# type provenance correction ready

### WHAT

Added explicit-vs-inferred provenance to the BRE-42 Task 2 F# type facts. Explicit annotations and record/union/member types are stored as `TypeInfo` with `is_inferred = false`; direct scalar-literal facts remain in the normal inferred map with `is_inferred = true`.

### WHY

The first Task 2 implementation returned only `HashMap<String, String>`, and the shared `convert_types_map` necessarily marked every row inferred. That violated the plan's honesty requirement for explicit F# type facts.

### HOW

- Miller `trace` proved `BaseExtractor.type_info` was initialized but otherwise unused by extractor code, while `TypeInfo` is consumed downstream through canonical results.
- F# `types::insert_type` now records explicit `TypeInfo` in the base-owned map and still returns the raw type text for compatibility with direct extractor inference.
- The existing `define_structured_full_language_extractors` macro converts raw types first, then extends with the extractor-owned map, making explicit entries override any same-symbol inferred entry without adding a F# dispatch function.
- Added assertions for `Name`, `Age`, `radius`, `makePerson`, and `convert` (`false`) and `inferredString`/`inferredInt` (`true`).

### IMPACT

The exact provenance regression test, all 12 F# tests, factory conversion tests, registry consistency test, crate check, package Clippy, formatting, and diff checks pass. The shared macro now has a generic override seam for any future extractor that needs richer `TypeInfo` provenance.
