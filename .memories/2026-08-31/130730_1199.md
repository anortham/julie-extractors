## Pre-release review of `codex/extractor-gap-closure-plans`

### WHAT
Reviewed the release candidate before approval. `main` holds no code change since
`v2.37.2` (docs, memories, TODO.md only). All product work sits on the unmerged
branch `codex/extractor-gap-closure-plans` (97 files, +12454/-106): a new F#
extractor, Go literal `t.Run` subtests, `rust.doc_test.v1` facts, and a C#
`internal` visibility fix.

### WHY
The user must know what the release contains and whether it meets the repo
quality bar before they tag.

### HOW
Ran every branch gate plus the certification tier, because `Cargo.lock`,
`language_spec/**`, and `registry.rs` all changed. Read the shared-base diffs
first (highest blast radius), then each language. Proved the rustdoc gap with
the built `julie-extract` binary instead of reading code alone.

### Gate results (all pass)
- `cargo fmt --check`, `cargo clippy --workspace --all-targets` (0 warnings)
- `cargo test -p xtask` (23), `xtask test default`, `xtask test contract`,
  `xtask test certification`
- `language-data-quality-report.mjs --strict`: silent_cells 0, quality_bar_debts 0
- `check-agent-doc-sync.sh`, `check-release-state.sh`: clean

### Findings
1. **`rustdoc_mode` drops real doc tests.** `base/rust_doc_test_facts.rs:177`
   accepts only `rust`, `ignore`, `no_run`, `compile_fail` as the first info-string
   token. Rustdoc also runs ```` ```should_panic ```` and ```` ```edition2021 ````.
   Proved with a scan: of three fences, only ```` ```rust,should_panic ```` produced
   a row. `rust.doc_test.v1` is claimed `supported` with no `open_gaps` entry, so
   this breaks the Data Quality Bar rule.
2. **Documented language count is stale.** `README.md:145` and
   `docs/site/index.html` (7 places) say 38; `julie-extract languages --json` now
   returns 40. `fsharp` (new) and `qmldir` (pre-existing) are missing from the list.
3. **C# `internal` value change.** `csharp/helpers.rs:56` now returns
   `Visibility::Internal`, not `Private`. Schema is safe — the variant already
   serialized as `"internal"` — but every consumer filtering C# visibility sees new
   values. Contract version records `csharp-visibility-v2`. No release notes yet.
4. No version bump and no release-notes file for the new version.

### Design notes
- `registry.rs:59` appends `ext.base.type_info` for all nine structured-full
  languages, not only F#. Only F# writes that map today, so no behavior change,
  but the widening is silent and untested elsewhere.
- `structural_facts.rs:156` hardcodes the rust doc-test pattern id outside the
  registry that already declares `languages: &["rust"]` — two sources of truth.
- `attach_fsharp_attribute_symbols` fallback drops the parent-scope filter, so an
  attribute can bind to a symbol in an unrelated scope.
- No Windows run for the new `tree-sitter-fsharp` native grammar dependency.

### IMPACT
The branch is technically sound and well tested (Go shadowing alone has ~17 cases;
nested `t.Run` parent identity is proven). Findings 1, 2, and 4 should close before
the tag. Nothing was changed — the branch and `main` are both clean.
