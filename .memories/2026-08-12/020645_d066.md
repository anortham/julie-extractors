## Fixed store-resolution scope explosion before phase execution

A one-file change could select almost every resolution row through common touched names while the crossover stayed scoped.

- **Root cause:** `versions_matching_names` widened `selected_versions`, and predecessor phases swept every prior row in those versions, but `scope_crosses_over` counted only `recheck_versions` plus direct name matches and exempted one changed path.
- **Fix:** Denominate the fixed 0.7 crossover in selected-version plus name/receiver identifier reads, including the duplicate work the scoped phases actually execute; apply it to one-file changes.
- **Exactness:** New one-file broad-name CLI regression selects full with `resolution_scope_crossover` and matches the forced-full canonical digest. Scope 7/7, equivalence 5/5, sequence/CAS 2/2, CLI contracts 24/24, mechanism 12/12.
- **Live evidence:** Requests `6a4c1fc...` and `49113677...` stayed scoped at 516,065 and 531,492 rows and spent 1,207,530 ms and 1,244,143 ms in resolution.
- **Impact:** Small faithful scope remains scoped at 98 files / 197 names / 784 rows; pathological 100/100 collision scope falls back before materialization.
- **Pending:** Clean three-run faithful timing replay requires restarting/pausing the current Miller MCP host, which continuously spawns released-v2.32.0 resolvers. Contaminated samples are not accepted as timing evidence.
