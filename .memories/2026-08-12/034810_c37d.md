## WHAT

Implemented a test-only fixed-field serializer and env-gated diagnostic worker for all fourteen `CandidateQueryFamily` counters. The one bounded Miller-scale fixture-preparation attempt timed out before the scoped replay could start.

## WHY

The existing performance worker launches the public CLI in a subprocess, but query counters live inside `StoreScratchResolutionSession` and the public report intentionally does not expose them. An integration-test-only worker preserves the public contract while enabling faithful diagnostics.

## HOW

- Added `CandidateQuerySample` with fourteen compile-time fields and `{executions, rows}` metrics.
- Added an exact serialization regression and an env-gated worker using the same `prepare_replay_view` setup and scoped session path.
- Ran one fixture setup under `timeout --signal=TERM --kill-after=5s 60s` at `/tmp/julie-store-query-replay-20260811`.
- The attempt exited 124. Read-only inspection found `query-diagnostic` at generation 1, zero ready bases, a 65,755,232-byte partial-base WAL, and a 91,488,256-byte work DB. The scratch tree is preserved.

## IMPACT

No scoped query-family ranking exists yet, so no optimization is selected. The next diagnostic must materially change setup by preparing/reusing a ready predecessor base outside the 60-second scoped measurement; repeating this setup unchanged is forbidden.
