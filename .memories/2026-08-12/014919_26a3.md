## Fixed writer-lease expiry during long artifact imports

Large `store import --from-artifact` quanta could outlive the writer lease because the coordinator renewed only before and after executor work.

- **Root cause:** `StoreCoordinator::execute_request_quantum` left a heartbeat gap around synchronous `CoordinatorExecutor::execute_quantum`; the expired fence then prevented publication and prevented fenced failure/requeue terminalization.
- **Fix:** Added one RAII heartbeat worker per acquired drain. It renews the existing holder/PID/fencing token at one-third of the unchanged TTL and stops before lease release. `FromArtifact` alone may exceed the ordinary quantum deadline because resolution-base materialization is indivisible; other request kinds retain the structural deadline.
- **Recovery:** Error returns become durable `failed` requests while panic/owner death drops the lease and leaves a stale claimed request recoverable by the existing takeover path.
- **Tests:** Added a deterministic blocked-quantum test crossing both the lease interval and quantum deadline, asserting one terminal commit. Strengthened failure/panic state assertions.
- **Impact:** Large legacy artifact imports can publish exactly once without weakening fencing, extending TTL, or changing public CLI/schema contracts.
