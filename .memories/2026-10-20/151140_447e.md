## julie 3.9.0: assigned JS properties owned references and split chained assignments

The code-kb release corpus check (express, radzen-blazor, miller) found two wrong answers in the new `javascript-assigned-properties-v1` rows:

- **Chained assignment:** `req.get = req.header = function header()` wrote a property `get` (the value is an assignment, not a function), and the method `header` became its child, so `header` dropped from outlines.
- **Owner:** the property span owned the calls and reads in its value. `opts.etag = this.app.enabled('etag')` inside `res.sendFile` made `etag` the caller of `enabled`; `blast_radius` stopped at the property and never reached `sendFile` or its tests. Radzen showed 5 gained / 4 lost call edges from the same cause.

### Fix
- `extract_assignment` (`javascript/assignments.rs`): a value that is an `assignment_expression` writes no property, like a bare name.
- `ecmascript_owner_index` (`javascript/mod.rs`): a symbol with `isAssignedProperty` never owns a reference, so owners are as in 3.8 (the enclosing function, or none at module level).
- Tests `a_chained_assignment_declares_no_property_and_keeps_the_method_top_level`, `the_function_around_an_assigned_property_owns_the_calls_in_its_value`; golden `javascript/language_gaps` updated (2 reads lose the owner `body`).

### Impact
Restores 3.8 caller attribution. The reach gate and the replays did not catch it, because they score site labels, not caller names; only the corpus call-edge diff did.
