## julie 3.9.0 prepared on feat/references-level (not tagged)

**What:** One release carries four items that code-kb accuracy phase 3 asked for:
- JavaScript: `obj.prop = <non-function>` on a plain identifier writes a `property` symbol (`className`, `isAssignedProperty`), first per file.
- C#: call identifiers get `arg_types` (one type or null per argument) at `references` and `full`.
- C#: symbols in a kept `#if` branch get `preprocessorIf` (nested conditions joined with ` && `); `using` rows count.
- Schema v8: `identifiers.reference_site_id` is nullable; the `references` level writes no `reference_sites` row for an identifier that no relationship shares.

**Why one release:** the smaller-rows change rewrites what the `references` level writes, so releasing the level alone would change its shape again next release.

**Decisions:**
- `extraction-output-changes.md` 3.9.0 classification is `incompatible` (compat-check accepts only `compatible`/`incompatible`; the first draft said "breaking for readers of …").
- The new JS property symbol contains identifiers in its value only outside functions (function priority 1 beats property priority 10 in `symbol_priority`), the same as a top-level `const`. Accepted; golden fixtures regenerated (13 C# files for `arg_types`, JS `language_gaps`, Razor code-behind).
- `cli_contract.rs` asserts `required_sqlite_schema_version` 8.

**Evidence:** fmt, clippy (`--all-features -D warnings`), doc sync, `cargo test -p xtask`, `cargo xtask test default` and `contract` (7111 tests), `cargo xtask compat-check --previous-binary` 3.8.1 (NOTICE, declared incompatible).

**Next:** build the release binary, copy it to code-kb `.tools/julie-extract`, pin 3.9.0 there, switch code-kb to the `references` level, run the code-kb dogfood round; tag julie only after that round has no `[open]` defect and the owner approves.
