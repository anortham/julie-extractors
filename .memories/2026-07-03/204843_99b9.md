## Designed + planned "finish the HTTP boundary lane" (v2.8.0)

Brainstorm → discovery → design → adversarial review → implementation plan for the next release. On branch `feat/finish-http-boundary-lane`.

### What
Complete the HTTP request↔handler boundary across the remaining mainstream backends so Miller can bridge client→handler everywhere.

**Scope (user-locked):**
- Server route facts: NestJS, Kotlin+Spring, Laravel, Phoenix, axum, actix (actix split into `attribute_route` + `scope_route`).
- Client-request facts for kotlin/php/elixir/rust — one primary client each (Ktor client, Guzzle+Http facade, Req, reqwest); other libs are `open_gaps`.
- Per-framework prefix-registration families: `axum.nest`, `actix.mount`, `laravel.route_prefix`, `phoenix.forward`. `nestjs.global_prefix` dropped (no Miller consumer).
- Ktor deferred for release scope with a documented safe gate as closure plan.

### How (process)
- Two discovery workflows (product coverage map; then per-framework feasibility against the v2.7.0 machinery).
- Adversarial Doubt Pass (5 skeptics) → 4 design changes + 2 rationale corrections.
- Codex read-only review → 4 more material fixes, all folded.

### Key decisions
- **Static-literal silence guard = tree-sitter AST whole-argument allowlist check** (reject concat/format!/const/interpolation), NOT a hand-rolled mask → ADR-0005. This was the biggest M2-safety fix (Codex caught that an interpolation-child check alone leaks `"/u/"+id`).
- Contract marker bumps to `.backend-http-boundary-v2`.
- `actix.scope_route.v1` is binary — fully shipped or fully absent (registry rejects dead specs).
- Prefix families are evidence-only in Miller until their `RouteFamilyForMount` mapping + anchor rule land (cross-repo follow-up).
