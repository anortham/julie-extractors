## Valid CLI scan cache benchmark

### WHAT
- Completed an isolated before/after benchmark for the scan snapshot-cache removal.

### WHY
- Earlier after-runs were invalid because `/tmp` SQLite artifacts exhausted scratch space. The performance claim required identical successful work and binaries differing only in this patch.

### HOW
- Archived commit `df927952` twice with `git archive`: one frozen fixture root and one baseline source tree.
- Created a second source tree from the same archive and applied only the CLI cache patch.
- Built each release binary with separate target directories under `/home/murphy/.cache/julie-cli-cache-review`; `/home` had 1.4 TiB free.
- Ran one warm-up per binary, then three alternating fresh `scan --level full --json` runs. Each output database used a new directory; all commands exited 0.

### IMPACT
- Baseline wall times: 17.29, 17.86, 17.95 seconds. Patched: 17.02, 17.33, 16.79 seconds. Median improved 17.86 to 17.02 seconds (4.7%); p95-of-three improved 17.95 to 17.33 seconds (3.5%).
- Median peak RSS fell 1,991,468 to 1,975,756 KiB (15,712 KiB). The writer/extractor's roughly 2 GiB peak masks the deterministic removal of the scan's up-to-64 MiB source cache retention.
- Reproducible command and raw runs sent to the lead and quality reviewer.
