## CLI scan cache removal

### WHAT
- Changed `commands::compute_file_outcome` to use `read_source_snapshot_uncached` during scan spooling.
- Added `scan_spooling_does_not_retain_source_snapshots` to guard against scans retaining source content in the global snapshot cache.

### WHY
- A normal one-shot `scan` consumes each `SourceSnapshot` immediately and never rereads it. The previous reader still cloned every stable source into the 64 MiB global cache, adding locking, cache bookkeeping, and retained copies without a possible cache hit. Store imports still use the cached reader to bridge their L1-to-deep reread.

### HOW
- Added a minimal uncached reader that preserves the existing read, decoding, content hash, and error path but omits cache lookup and insertion.
- Kept `read_source_snapshot` unchanged for store execution and identity paths.

### IMPACT
- Removes unnecessary source duplication from normal scans while retaining the store import single-read behavior.
- Focused red/green test passed; CLI lib tests and store import disk-read contract passed. Repository-scale after benchmark was invalid because `/tmp` SQLite artifacts exhausted available scratch space and scans failed during artifact write, so no timing claim is recorded.
