## Fixed two scan-aborting panic paths (review HIGH findings)

Both verified via TDD (reproduce -> fix -> green).

### Fix 1: R multibyte-UTF8 slice panic
`r/mod.rs` `format_parameter` truncated long parameter defaults with `&default_val[..30]`, guarded only by a byte-length check. When byte 30 landed inside a multibyte codepoint it panicked ("byte index 30 is not a char boundary; inside 'こ'"). Replaced with char-count truncation (`chars().take(30).collect()`), truncating only when characters were actually dropped. ASCII behavior unchanged.
- Test: `tests::r::functions::function_with_long_multibyte_default_does_not_panic` (RED reproduced the exact panic).

### Fix 2: no panic boundary on the per-file extraction path
Only ~6 of 34 extractors routed through the guarded `traverse_tree`; a panic anywhere else unwound through the single-threaded (now rayon) loop and aborted the whole scan. Added `catch_extraction_panic` in `extraction.rs` wrapping `extract_canonical` in `catch_unwind(AssertUnwindSafe(..))`, converting both returned errors AND panics into an `Extract`-kind `ExtractFileError` (-> `FailedPreserved` row + diagnostic). Boundary lives inside `extract_artifact_file_from_snapshot`, so it runs per-file on each rayon worker before a panic can propagate to `collect`. Kept narrow (not the loop) per the review recommendation. Also extracted `extract_error` helper + `panic_message` downcast.
- Tests: panic->error (RED unwound through the stub first), returned-error mapping, success passthrough.
