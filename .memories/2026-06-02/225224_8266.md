## Full project review of julie-extractors (focus: performance)

Ran a 24-agent multi-dimension review with adversarial verification (zero findings refuted; several severities corrected *down* against the repo's own profiling). Overall grade: **Strong B+**.

### Verified performance picture
- openclaw cold scan ~88s = **~52s parse/extract (58%) + ~37s SQLite write (42%)**, single-threaded, ~1.15x CPU on a 24-core box.
- **Top win: parallelize the parse phase.** It's embarrassingly parallel and the writer is already decoupled (spool written to disk *before* the SQLite connection opens, `commands.rs:177` vs `:209`). Expect total ~88s → ~45-50s (write phase becomes the floor). **In progress now.**
- Allocation churn in `map_results`/`dedupe_by_id` is real but LOW (parsing dominates) — do not oversell.
- `[profile.release]` tuning missing (no LTO, codegen-units=16) — low, single-digit % on parse half only.
- SQLite: spool deserialized 4× (safe win 4→3 passes); `load_existing_file` N+1; index/FK during bulk load (careful: a contract test pins `idx_symbols_is_test`).

### Correctness blockers (HIGH)
- **R multibyte-UTF8 panic** `r/mod.rs:280` `&default_val[..30]` (byte slice, not char boundary) + **no `catch_unwind` boundary** on the per-file path → one bad file aborts the whole scan. Only ~6 of 34 extractors route through the guarded `traverse_tree`. Fix: char-safe truncate + wrap `extract_canonical` at `extraction.rs:88`.

### Contract bugs
- **HIGH, resolved by later review patch** `export --out - --json` failure branches hardcoded stdout → corrupted the JSONL stream (`commands.rs:775-805`).
- MEDIUM: `info` never emits documented `metadata_missing` warning (doc drift); `languages --json` emits `parser_crate` vs `parser_package`; discovery silently drops unreadable dirs.

### Tooling/supply chain (MEDIUM)
- clippy CI **skips `julie-extractors`** (204K core crate unlinted).
- `md5 0.7` appears in production per-symbol ID/hash paths; verify advisories with a supply-chain gate before citing a RustSec ID, and only migrate to `md-5` if byte-identical ID stability is proven.
- No `cargo-deny`/audit gate; 4 git-pinned forks; manifest references non-existent `docs/TREE_SITTER_UPGRADES.md`.

### Architecture cleanups (MEDIUM)
- `registry.rs` duplicates ~14 identical extract fns instead of its own macros.
- `language.rs` 4 dead `pub` node-kind fns (Julie editing-tool leftover, boundary smell).
- No `LanguageExtractor` trait; signatures drift (vue).

### Strengths
Decoupled extract→spool→write; single-tx writer with prepare_cached + WITHOUT ROWID; JSONL export buffering fixed (20.8s→2.4s); robust per-file failure + data-loss guard; real enforced test tiering (~2,359 tests ~9s); `unsafe_code=forbid`; AGENTS/CLAUDE byte-synced.
