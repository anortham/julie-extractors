## Write-path optimization: baseline + bottleneck localization (cold force scan, parallel branch)

The parallelization (committed 005b337/8a63834 on perf/parallel-extraction) compressed extraction; the SERIAL SQLite write is now the dominant cost.

### Measured baselines (release, cold force scan, fresh DB)
- **hermes-agent**: total 14,820ms; `artifact_write` **11,889ms = 80%**; extraction_spool 2,841ms. (was 30.35s pre-parallel)
- **openclaw**: total 40,919ms (41.0s real); `artifact_write` **34,816ms = 85%**; extraction_spool 5,925ms. ~2.31M rows -> ~66K rows/sec serial.

### Row distribution (openclaw) — where the write cost lives
identifiers **1,102,973 (48%)**, symbols **640,317 (28%)** = 76% of rows. Then type_facts 176,396; pending_relationships 119,945; relationships 90,714; type_arguments 22,191; type_argument_usages 18,759; files 12,781.

### Structural findings in write_scan_spooled_snapshot (writer.rs 713-858)
1. **4 passes over the JSONL spool**, each a full serde_json deserialization of the entire artifact (plan / insert files+symbols / collect symbol-ids / insert children).
2. **Two-step insert-then-UPDATE on the two biggest tables**: insert_identifiers inserts containing/target = NULL then UPDATEs them (1.1M extra UPDATEs) even though symbol_lookup is fully built before child insertion; insert_symbol_rows + update_symbol_parent_rows inserts NULL parent then UPDATEs (640K UPDATEs).
3. **load_existing_file called twice per file** (passes A and B) — redundant indexed SELECT.
4. **PRAGMA foreign_keys = ON** globally -> per-child-row FK validation during bulk load; delete_file_rows uses EXPLICIT ordered deletes (not ON DELETE CASCADE), so FK-OFF during the write txn is safe.
5. Schema: 20 indexes (most consumer-only, not queried during write); journal_mode=WAL, synchronous=NORMAL, temp_store=MEMORY, cache_size=-131072 (128MiB), stmt cache 64.

### Negative results to RESPECT (memory checkpoint_f1e24c1c, 2026-06-02)
Bulk index drop/rebuild AND an existing-row cache were tried and BACKED OUT — slower on real openclaw dogfood. Any index/cache proposal must explain why it differs.

### Contracts
Byte-identical artifact + identical row counts required; no schema/CLI/JSONL/report contract change without a tracked plan.
