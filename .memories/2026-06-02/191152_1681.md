## Replaced large symbol lookup IN clauses with temp-table lookup

### WHAT

Changed the artifact writer's symbol lookup path so large requested-symbol sets no longer build dynamic `IN (...)` SQL. The writer now:

- seeds lookup results from symbols emitted by the current write batch or spool pass
- inserts only unresolved requested IDs into a temp table
- joins `symbols` against that temp table to resolve existing artifact symbols
- drops the temp table after the lookup

### WHY

The v2.0.0 binary could fail on real repos when dynamic `IN` placeholders exceeded SQLite's host-parameter cap. Even when chunked below the cap, 32k-placeholder SQL is an expensive and brittle write-path shape.

### HOW

Kept the change private to `crates/julie-extract-artifact/src/writer.rs`. Added unit coverage for same-batch lookup without SQLite probing and large unresolved ID requests. Verified through artifact crate tests, changed-test gate, release builds, and live scans of Eros and julie-extractors.

### IMPACT

Fresh scans avoid SQLite lookups for same-batch symbol references, incremental scans resolve cross-file references with stable temp-table joins, and the reported Eros failure is fixed without relying on SQLite variable-limit clamps.
