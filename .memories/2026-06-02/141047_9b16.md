## Implemented spooled two-phase scan writing

- **WHAT:** Added an `ArtifactFileSpool` JSONL temp-spool API, a new `ArtifactWriter::write_scan_spooled` path, and routed CLI `scan` extraction through the spool instead of retaining all extracted `ArtifactFile` rows in memory.
- **WHY:** Large repositories like `openclaw` and `hermes-agent` were exposing the next real bottleneck after the SQLite variable batching fix: scan held all extracted rows in memory before writing.
- **HOW:** The spooled writer now plans from disk, writes file/symbol rows first, builds symbol lookup after all symbols are present, and replays child rows from the spool. It preserves single-revision semantics, deletion handling via snapshot paths, cross-file relationships to later symbols, no-change rescan behavior, and rejects spooled files missing from the snapshot path set before DB mutation.
- **IMPACT:** Peak memory on release dogfood dropped to about 395 MB RSS for Openclaw and about 424 MB RSS for Hermes while preserving row counts and report contracts. Openclaw scan now trades some wall time for bounded memory: about 99.28s versus the prior post-PRAGMA 92.52s baseline, with RSS reduced from about 2.10 GiB.
