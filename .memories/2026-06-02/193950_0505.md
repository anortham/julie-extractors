## Prepared v2.0.1 release candidate after perf and Eros blocker work

### WHAT

Prepared the local v2.0.1 release candidate. The work includes:

- version bumps for all three crates to `2.0.1`
- Release Binaries and Specialist Gates workflow defaults updated to `2.0.1`
- v2.0.1 release notes and release-candidate evidence docs
- artifact writer prepared-statement cache tuning on hot write paths
- writer performance tripwire for repeated child-row writes
- stale JSX/TSX golden fixture updates for pending-noise pruning behavior
- active brief updated with v2.0.1 candidate state

### WHY

The v2.0.0 binary had a real Eros blocker from SQLite symbol lookup SQL shape, and large-repo scans needed enough measured evidence to ship a stable patch release without pretending deeper cold-scan optimization is complete.

### HOW

Used the existing report profiling to rerun a multi-repo matrix with the `julie-extract 2.0.1` release binary. Kept contracts unchanged except additive optional report profiling already documented in the release line. Added a small writer tune where it was low-risk and verified with a red/green writer performance tripwire.

### IMPACT

The Eros blocker is fixed, no-change rescans are cheap, and v2.0.1 is locally ready for commit/push/publish. Openclaw cold scan remains expensive but measured and documented as follow-up, not a patch-release blocker.
