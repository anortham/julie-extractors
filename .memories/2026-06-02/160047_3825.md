## Pruned noisy TS/JS member pending calls

### WHAT

Added a second performance slice that narrows TypeScript and JavaScript pending-call emission to useful cross-file targets.

- Imported namespace/default receiver member calls now carry an import context, e.g. `path.join()` records `import_context=path`.
- Member calls with no imported receiver context are no longer emitted as pending cross-file calls.
- Added red-green tests for imported receiver member calls and unimported member-call pruning in both TS and JS.

### WHY

Openclaw profiling showed the remaining cost concentrated in recursive pending-call traversal and unresolved-target construction. Artifact analysis showed very high pending-call row volume from unimported member chains such as test matchers and built-in/prototype methods, which are not useful cross-file resolution candidates.

### HOW

The walker now builds the unresolved target, then emits member pending calls only when the target has an import context. Member target construction now resolves import context from direct imported receiver bindings before falling back to cached `new ImportedType()` receiver inference; non-identifier receivers skip the expensive receiver scan.

### IMPACT

Openclaw fresh scan dropped pending rows from 517,566 to 316,272 and wall time from the prior verified 103.13s to 88.59s. Hermes source checkout dropped from 31.50s to 29.55s with pending rows from 192,505 to 186,075. No-change rescans stayed cheap.
