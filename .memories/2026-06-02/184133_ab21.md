## Added scan report profiling

### WHAT

Added optional `profile` data to JSON reports and wired `scan` to emit phase and per-language timing data.

Changed surfaces:
- `Report.profile` with typed `ReportProfile` and `ReportLanguageProfile`
- Scan phase timings for existing artifact handling, discovery, extraction/spool, writer open, capability sync, and artifact write
- Per-language counts for files, changed/unchanged/failed files, bytes, read time, extract time, and spool write time
- Failure-path profile attachment for DB-open and write failures after extraction
- Report contract docs and release-evidence dogfood note

### WHY

Large-repo scan performance needed machine-readable evidence instead of report-only wall-clock timing. The original blocker class involved SQLite artifact writing, so reports need to separate extraction/spool time from artifact write time and preserve partial profile data on late scan failures.

### HOW

The CLI accumulates profile data at the existing scan spool boundary without changing extractor APIs. The artifact crate exposes the profile shape as an additive optional report field. Contract tests lock serialization and CLI report behavior, including a post-extraction DB-open failure path.

### IMPACT

Consumers can now inspect scan JSON to tell whether time is in discovery, extraction/spooling, SQLite artifact write, or a specific language. Dogfood showed clean forced scans on `julie-extractors`, `openclaw`, `Newtonsoft.Json`, and `hermes-agent`; `hermes-agent` did not reproduce the prior SQLite variable failure with this binary.
