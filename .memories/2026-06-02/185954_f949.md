## Fixed oversized SQLite symbol lookup chunks

### WHAT

Capped the artifact writer's dynamic symbol lookup `IN (...)` chunk size at a conservative prepare-safe limit of 32,000 variables.

Changed file:
- `crates/julie-extract-artifact/src/writer.rs`

Added tests:
- `symbol_lookup_chunk_size_clamps_reported_limit_to_prepare_safe_bound`
- `symbol_lookup_chunks_above_sqlite_prepare_variable_limit`

### WHY

Eros migration testing reported a pinned `julie-extract v2.0.0` failure where scan hit `db_write_failed` from a single `IN (...)` query with 36,241 placeholders, above SQLite's prepare-time host-parameter cap. The old writer trusted `tx.limit(SQLITE_LIMIT_VARIABLE_NUMBER)` directly, which can report a value higher than what prepare accepts in some binary/runtime combinations.

### HOW

Kept runtime chunking but routed it through `symbol_lookup_chunk_size()`, which preserves small configured limits and clamps high reported limits to 32,000. This addresses the root cause in the writer instead of requiring Eros or other callers to work around scan.

### IMPACT

Large symbol lookup sets are split into prepare-safe chunks even when SQLite reports a higher host-variable limit. Current local Eros scan writes successfully with 80,494 symbols, 4,521 relationships, and 20,595 pending relationships.
