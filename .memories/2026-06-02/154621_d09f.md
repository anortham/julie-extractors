## Tuned pending call traversal after spooled artifact writing

### WHAT

Kept the two-phase spooled scan writer fix and added measured extractor traversal speedups for pending call extraction.

- Added lazy unresolved-target construction for TypeScript and JavaScript pending-call traversal.
- Added receiver import-context caching keyed by containing scope and receiver name.
- Added regression tests proving local calls avoid import-binding cache initialization and repeated receiver calls reuse cached import context.

### WHY

Large-repo scans were no longer failing on SQLite variable limits, but openclaw still spent a lot of CPU in pending call traversal. Profiling showed TypeScript pending-call relationship extraction, unresolved-target construction, import binding lookup, and tree-sitter cursor walking as dominant costs.

### HOW

The pending-call walker now checks whether a call resolves locally from the terminal callee name before building unresolved import targets. Receiver import context lookup now caches repeated receiver resolution inside the same function scope, avoiding repeated scans for patterns such as `service.one()`, `service.two()`, and `service.three()`.

### IMPACT

The blocker remains fixed and openclaw gets a small measured speed improvement without changing artifact row counts. The next larger perf target is reducing traversal and pending relationship volume rather than more SQLite writer tuning.
