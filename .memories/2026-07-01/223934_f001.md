## Project review after v2.5.10 (three-agent deep review)

Full-project review of julie-extractors covering tree-sitter data quality, web route facts, contracts, and engineering health. All quality gates verified clean at HEAD (36 languages, 0 silent cells, 0 quality-bar debts, 0 open_gaps in capabilities.json — only 16 evidence-backed domain exceptions).

### Key findings

**Web route facts (v2.5.10, web-route-facts-v3):** All planned frameworks shipped and hardened (htmx/Alpine/ASP.NET minimal API/Vue/React Router/Next/Nuxt). Biggest cross-boundary tracing gap: **no client HTTP call facts (fetch/axios) and no API route-handler definitions** (Next.js route.ts, Nuxt server routes, ASP.NET controller attribute routes `[Route]`/`[HttpGet]`) — both sides of the fetch↔API-route join are missing. Also: htmx attributes not scanned in JSX/TSX/Vue templates (dispatch is html/razor only). Client URL literals do exist in the `literals` table (kind=url, carrier=axios.get) but not as normalized structural facts.

**Contracts:** Dual-axis versioning (integer contract v3 + EXTRACTION_CONTRACT_VERSION marker string) is solid; Miller pins v2.5.10 in lockstep and gates on integers. Main weak spot: `metadata_json` is a free-form bag with no per-`pattern_id` payload schema — consumers need out-of-band knowledge of which keys each pattern carries. Miller does not yet consume `revision_file_changes` for true delta indexing (Miller-side latent capability, not an extractor gap).

**Engineering health (top risks):**
1. `base/web_structural_facts.rs` god module — 3,676 lines, plus helper duplication with `framework_structural_facts.rs`
2. ~159 production unwraps; sharpest in `julie-extract-artifact/src/writer.rs` (SQLite write path) and `sql/schemas.rs`
3. `registry.rs` — 20 near-identical ~34-line `extract_<lang>` wrappers (macro candidate)
4. Slow/certification tiers run only on manual workflow_dispatch — no nightly schedule
5. 4 git-pinned grammars (razor/vbnet/qmljs/powershell) + tree-sitter ABI spread 0.23–0.26

**Performance snapshot (v2.5.10 dogfood):** 1,257 files → 289 MiB SQLite artifact, 5.1s full scan, 165ms no-change rescan. Artifact size is source-region/structural-fact heavy — worth watching on large repos.

### Recommended next work (ranked)
1. HTTP boundary facts: client request facts + API route-handler definition facts (serves cross-boundary tracing/impact goal directly)
2. htmx-in-JSX/Vue scanning
3. Per-pattern metadata schema in contracts (possibly machine-readable pattern registry)
4. Engineering-health cleanup: split web_structural_facts.rs, writer unwrap audit, nightly specialist gates
