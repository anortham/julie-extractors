## Preserved dirty checkout and reconciled main after release-source-control failure

- **WHAT:** Created a recoverable snapshot of the dirty primary checkout before cleanup, fast-forwarded local `main` to `origin/main`, restored rescue-only plan/checkpoint files into `main`, and added a release closeout rule requiring a clean current primary checkout and tag/main parity before a release is called complete.
- **WHY:** The v2.5.7 release flow left local `main` stale and dirty, and `origin/main` had commits after the release tag. The cleanup had to preserve all user-paid work before reconciling state.
- **HOW:** Wrote external recovery artifacts under `/Users/murphy/source/julie-extractors-recovery-20260701T020504Z`, committed the exact dirty state to `rescue/pre-release-cleanup-20260701T020504Z` at `cbf78b4`, fast-forwarded primary `main` to `eafddb2`, restored only rescue-only docs/memory files to current `main`, and kept stale source-code differences preserved on the rescue branch instead of merging regressions.
- **IMPACT:** No dirty work was discarded. Current `main` is now aligned with `origin/main` plus a pending cleanup commit, and future release closeout should fail if the primary checkout, remote main, and release tag are out of sync.
