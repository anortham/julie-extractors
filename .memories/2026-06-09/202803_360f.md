## Implemented ASP.NET, htmx, and Alpine structural facts

### WHAT

Added framework structural facts for the ASP.NET/htmx/Alpine slice in `julie-extractors`:

- `aspnet.minimal_api.route.v1` for static C# minimal API `MapGet`/`MapPost`/`MapPut`/`MapPatch`/`MapDelete` calls.
- `htmx.attribute.v1` for HTML/Razor `hx-*` attributes, including request verb and static target path metadata when applicable.
- `alpine.directive.v1` for HTML/Razor `x-*`, `@...`, and `:...` directives with normalized directive metadata.

### WHY

C#, HTML, Razor, and JS syntax support already existed, but downstream tools needed durable, versioned framework facts before Miller can reliably index and later bridge htmx calls to ASP.NET minimal API routes.

### HOW

- Added `crates/julie-extractors/src/base/framework_structural_facts.rs` and appended its rows from `registry::extract_for_language` into the existing `structural_facts` row family.
- Kept SQLite/JSONL schema unchanged; only pattern IDs and metadata expanded.
- Added fixture-backed capability metadata for C#, HTML, and Razor.
- Added unit coverage for route extraction, htmx/Alpine metadata, Razor markup, and a raw-script-text false-positive guard.
- Updated structural-facts design docs, SQLite/JSONL v3 contracts, and marked TODO #10 done.

### IMPACT

The extractor now emits the facts Miller needs for this web-stack workflow without owning downstream route linking. Capability surfaces and `languages --json` now advertise exact fixture-backed pattern IDs.
