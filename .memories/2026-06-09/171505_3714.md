## Pre-release review fixes and verification

### WHAT
Fixed the remaining deep-review findings before release:

- Bumped JSON report schema to `report_schema_version: 3` after adding SQLite v3-only row count domains.
- Updated report docs, README, dogfood validation, CLI/report contract tests, and package-list coverage for v3 docs.
- Changed `cargo xtask performance writer-current-schema` to generate one symbol-scoped complexity metric per generated symbol plus one file-scoped metric per file.
- Fixed VB.NET body hash comment normalization for case-insensitive `REM`, bare `REM`, and inline `: REM` comments while preserving `Remote` as code.

### WHY
External review found the prior fixes were incomplete for public report versioning, synthetic performance evidence, and VB.NET comment edge cases. These were release blockers because they affected machine-readable contracts, performance evidence fidelity, and clone/body-hash correctness.

### HOW
Used red/green regression tests for all three findings, then reran focused and release-scope verification:

- Report schema red/green: `cargo test -p julie-extract-artifact --test report_contract report_serializes_schema_version_and_success_shape`
- Performance workload red/green: `cargo test -p xtask --test performance_baseline_contract writer_current_schema_execution_writes_every_current_child_domain`
- VB.NET red/green: `cargo test -p julie-extractors body_hash_normalizer_ignores_vbnet`
- Broader verification: `cargo xtask test default`, `cargo xtask test contract`, `cargo xtask release package-list`, `scripts/check-agent-doc-sync.sh`, `git diff --check`
- Live dogfood: `cargo xtask dogfood repo --root . --out-dir target/dogfood/pre-release-review-v3`
- Synthetic writer evidence: `cargo xtask performance writer-current-schema --out-dir target/performance/pre-release-review-current-schema`

### IMPACT
The branch is materially closer to release-ready: public artifact/report/JSONL schema versions now align at v3, release packaging includes v3 docs, report consumers see a proper schema bump, current-schema writer evidence now covers 90,000 complexity metric rows in the default 10k-file workload, and VB.NET body hashes ignore supported comment-only changes.
