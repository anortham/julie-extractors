## Implemented structural facts starter slice

### WHAT

Added the first `structural_facts` contract slice for `julie-extractors` TODO #7.

- Added extractor `StructuralFact` rows and `collect_structural_facts()`.
- Wired Rust `unsafe { ... }` blocks as `rust.unsafe_block.v1` with `unsafe_block` capture, node kind, span, confidence, optional containing symbol, and metadata.
- Added SQLite `structural_facts`, JSONL `structural_fact`, report row counts, writer insert/delete/count support, CLI mapping, dogfood lists, and current-schema performance workload coverage.
- Updated README, v2 contract docs, testing strategy, design doc, and TODO #7 status.

### WHY

Miller and Eros need parser-backed structural facts without owning tree-sitter extraction policy or building parser logic downstream. This keeps the repo boundary at `source tree -> versioned extraction artifact`.

### HOW

The implementation mirrors the existing `source_regions` row-family pattern:

- The registry invokes `collect_structural_facts()` after language extraction.
- The CLI maps extractor facts into `ArtifactStructuralFact` rows.
- The artifact writer persists rows transactionally with the rest of a file.
- JSONL export emits deterministic `structural_fact` records after `source_region`.
- Reports and synthetic writer-current-schema output count the new row domain.

### IMPACT

The artifact contract now has a stable structural-fact row shape and one fixture-backed Rust safety pattern. TODO #7 remains partial: broader pattern/language coverage and capability-matrix metadata are intentionally deferred until the matrix is meaningful.
