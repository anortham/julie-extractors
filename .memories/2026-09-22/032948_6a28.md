## Wave 9: the certification gate failed, and why

`cargo xtask test certification` failed on
`tests::parser_upgrade::parser_upgrade_gate_covers_full_language_inventory`:

```
assertion `left == right` failed: cpp fixture must exercise its own parser entry
  left: "c"
 right: "cpp"
```

- **Cause:** the same defect wave 7 fixed in `tests/golden.rs`. The test called
  `detect_language_for_path`, which detects a `.h` file from the path with **empty content**,
  and the `.h` branch of `detect_with_probe` answers `c` whenever the probe gets no content.
  `fixtures/extraction/cpp/qt_header/source.h` is the only `.h` fixture in the matrix, so the
  gate was green until wave 7 added it. Waves 7 and 8 never ran the certification tier.
- **Fix:** the test reads the fixture source and calls `detect_language_for_source`, the same
  content-aware detection the pipeline uses. With the source in hand the probe answers `cpp`.
- **Not a weakening:** the assertion still requires every one of the 270 fixtures to route to
  its own registry language; it now tests the routing that actually happens at scan time.

`cargo test -p julie-extractors --features test-certification --lib parser_upgrade`: 2 passed.
