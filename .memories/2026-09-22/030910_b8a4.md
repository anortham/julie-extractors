## wave 8 C1, C2, C6, C7: the macro scanner reads literals, trivia and continued comments right

Four Codex findings, all in `cpp/qt_macros.rs`.

- **C1 (high).** `end_of_raw_string` was called with `end + 1` although `end` already pointed at the opening quote, so the delimiter was read one byte late: `R"tag(text)tag"` searched for the wrong terminator and every macro after it was lost, and an unfinished `R"` at the end of the input sliced past the end and panicked. The call now passes the quote offset, and the delimiter search is bounded to the 16 characters the standard allows, so a malformed literal falls back to the ordinary-literal scan instead of running to the end of the file.
- **C2.** `matching_paren` skipped ordinary literals only, so `QML_UNCREATABLE(R"msg(Use ")" carefully)msg")` closed at the first parenthesis inside the raw string. One helper, `end_of_literal_token`, now handles ordinary, character and raw strings with their encoding prefixes (`u8R`, `LR`), and both the outer scan and the argument balancing call it.
- **C6.** `argument_list_start` skipped spaces and tabs only. `skip_trivia` now skips newlines and comments too, so `Q_PROPERTY` with its argument list on the next line is blanked whole. Every newline byte is still preserved.
- **C7.** A `//` comment that ends in a backslash continues onto the next line in C++, so `// note \` followed by `Q_PROPERTY(int ghost READ ghost)` manufactured a ghost property. `end_of_preprocessor` already honoured the continuation, so it is renamed `end_of_logical_line` and now serves the `//` skipping in the scan, in `matching_paren` and in `skip_trivia`.

**Impact:** no macro is lost after a raw string, no panic on a truncated one, no ghost property behind a continued comment, and a Qt macro whose arguments start on the next line is handled.
