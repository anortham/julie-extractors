## wave 8 C3, C4, C5: stacked macros, own-line member prefixes, comments in `Q_PROPERTY`

- **C3.** Every identifier tested its prefix against the original line text, so in `Q_REQUIRED_RESULT Q_INVOKABLE int count();` the second macro saw the first one and was rejected, and a leading `/* comment */` blocked a declaration macro the same way. `scan` now tracks a `consumed` offset that advances past each recognized site and each comment, and `line_prefix` starts the prefix there. A run of specifiers, macros and comments is a valid declaration prefix.
- **C4.** `apply_member_sections` attached a prefix site to every method on the site's line, so `Q_SIGNAL void changed(); void helper();` marked both as events, and a member-prefix macro on its own line was classified `Statement` and never applied. Two changes: `MEMBER_PREFIX_MACROS` (`Q_INVOKABLE`, `Q_NOREPLY`, `Q_REQUIRED_RESULT`, `Q_SCRIPTABLE`, `Q_SIGNAL`, `Q_SLOT`) are `Prefix` sites whatever follows them, and the new `apply_member_prefixes` gives a site exactly one member: the first callable that starts after it with no `;`, `{` or `}` in between.
- **C5.** `parse_property` split the arguments on whitespace only, so `Q_PROPERTY(int value /* units */ READ value)` yielded no property and `READ /* getter */ value` recorded `/*` as the accessor. `without_comments` strips both comment forms before the split; the site's span still covers the original bytes.

**Impact:** stacked Qt declaration macros all get blanked, a prefix macro marks the member it stands in front of and no other, and a commented `Q_PROPERTY` still yields its property symbol and fact.
