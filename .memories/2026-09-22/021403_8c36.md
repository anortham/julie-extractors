## Header language detection flipped two Qt namespace headers to c

The `.h` probe parses the file with the C grammar and the C++ grammar and takes
the one with fewer error nodes. Task 19 blanks Qt macros before both probes, so
a header whose only C++ evidence was the macros now parses cleanly under both
grammars. The tie then went to the spelling scan, which looked only for `::`,
`template <` and the three access labels, and picked `c`.

tree-sitter-c accepts `namespace X { ... }` without an error node, so the
namespace was no evidence at all.

- **Fix:** the tie-break now also accepts a line-leading `namespace <name>`
  definition, in `language_spec/source_detection.rs`. Both probe paths share
  `CPP_ONLY_SPELLINGS` and `is_namespace_definition_at`.
- **Why line-leading:** C code may name a struct or a parameter `namespace`
  (`typedef struct namespace { int template; }`), and two pipeline tests cover
  exactly that. A bare `contains("namespace ")` broke both.
- **Net effect on the corpora:** 5 plasma headers moved from c to cpp, and the
  two regressions are gone.

Regression test: `a_qt_namespace_enum_header_is_still_detected_as_cpp` in
`tests/cpp/qt_macros.rs`.
