## Shared Qt release review milestone

### WHAT
- Found and fixed JavaScript QML directive spans that included trailing `//` comments in import-symbol and pragma-fact rows.
- Added `directive_spans_exclude_trailing_comments` and an indented C++ namespace header case to the public syntax API contract.
- Clarified 3.2.0 and 3.3.0 release notes/evidence: `compat-check` accepts a compatible ledger entry; it does not prove every observed output diff maps to an entry.

### WHY
- The QML directive parser blanks trailing comments but had stored the span through the full line, making source spans and stable IDs cover non-directive text.
- Release documentation overstated the compatibility gate's current evidence.

### HOW
- Reproduced the span bug with `.pragma library // shared` and `.import "Helpers.js" as Helpers // helpers`; the test initially failed with a pragma end byte of 25 instead of 15.
- Changed `qml_directives::scan` to use `directive_text.len()` for the stored end byte.
- Focused directive tests passed before concurrent QML work temporarily made the workspace fail to compile.

### IMPACT
- JavaScript QML directive artifact rows now identify only the directive text.
- Release evidence now accurately states what the compatibility check proves.
- Re-run focused syntax API and formatting checks once the QML worker restores a buildable shared tree.
