## Wave 7 review fixes R1 to R4 for the Qt C++ macro pre-pass

The lead's review of wave 6 found four defects with `julie-extract check`. All four are fixed at the shared point in `cpp/qt_macros.rs` and `cpp/qt.rs`.

- **R1 (regression).** The `Export` rule blanked any `[A-Z][A-Z0-9_]*_EXPORT` identifier anywhere, so `enum Mode { MODE_EXPORT }` and `flags | MODE_EXPORT` broke a clean 3.2.0 parse. An export macro now needs a declaration prefix position (`is_declaration_prefix`: a run of declaration specifiers, optionally ending in `class`, `struct`, `union` or `enum`) and must be followed by an identifier.
- **R2.** `Prefix` and `Statement` macros required an empty line prefix, so `virtual Q_INVOKABLE ...`, `static Q_INVOKABLE ...` and `inline Q_NOREPLY ...` still failed. `is_specifier_prefix` now admits a run of `virtual`, `static`, `inline`, `explicit`, `constexpr`, `extern`, `friend`, `const`, `volatile`, `mutable`, `template`.
- **R3.** Vendor macros outside the `Q_`/`QML_` vocabulary failed. `is_qt_macro_name` also accepts the `QT_` prefix; `VENDOR_STATEMENT_MACROS` is a fixed list (`K_PLUGIN_*`, `QTEST_*`, `QUICK_TEST_MAIN*`, `DBUS_QML_TYPE`) rewritten only in statement position; any all-caps name containing `_DEPRECATED` is a prefix macro when a declaration follows. `TEST(Suite, Name)` and `TEST_CASE("...")` stay untouched.
- **R4.** `cpp/qt.rs::section_at` took the last access label before the member, including a label inside a nested class body, so a method after a nested class left the outer `Q_SIGNALS:` section. A boundary now counts only when its innermost class range is the member's own class.

**Verification.** 13 new tests in `tests/cpp/qt_macros.rs` (blank_macros/scan plus one check-path assertion per rule) and one in `tests/cpp/qt_symbols.rs`; all 9 red first, all green after. `cargo xtask test language cpp` 166 passed. `cargo fmt` and `cargo clippy -D warnings` clean. No golden fixture changed.

**Impact.** Unblocks task 21 (the remaining C++ header defects) and removes the one wave-6 regression against 3.2.0.
