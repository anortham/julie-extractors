## Task 20: Qt properties, signals, slots and QML metadata

New `crates/julie-extractors/src/cpp/qt.rs` turns the macro sites from task 19
into symbols, metadata and one structural fact.

- `qt::apply` runs at the end of `CppExtractor::extract_symbols`. It sets class
  metadata (`qt_object`, `qt_gadget`, `qml_element`, `qml_singleton`,
  `qml_anonymous`, `qml_uncreatable`, `qml_attached`), promotes a method in a
  `signals` section to `SymbolKind::Event`, marks a method in a `slots` section
  `qt_slot: true`, marks a `Q_INVOKABLE` line `qt_invokable: true`, and adds a
  `SymbolKind::Property` symbol per `Q_PROPERTY` under its class.
- A member's section comes from the last section site or `access_specifier`
  node before it inside the same class body; a section site wins over an access
  label at the same byte, so a rewritten bare `Q_SIGNALS:` beats the `public:`
  the pre-pass wrote there.
- `cpp/visibility.rs` now reads the leading word of an `access_specifier` node
  and treats anything else as public. That covers both rewritten forms:
  `public Q_SLOTS:` keeps `public`, and a bare `Q_SIGNALS:` label whose original
  bytes read `Q_SIGNA` becomes public, as in Qt.
- `cpp.qt_property.v1` facts come from `extract_cpp` in `registry.rs`, which now
  wraps the macro-generated `extract_cpp_tree`, so `ExtractionLevel::Symbols`
  emits none. The spec lives in `structural_fact_registry/builtins/core.rs`
  (extra.rs would have crossed the 700-line family ceiling) and
  `docs/contracts/structural-fact-patterns.json` was regenerated.
