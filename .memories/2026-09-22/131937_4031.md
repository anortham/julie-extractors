## Qt release performance investigation

### WHAT

Prepared pinned, repeatable release benchmarks under `target/qt-release-review` for v3.1.3, v3.2.0, and v3.3.0. The corpus includes KDE Kirigami commit `b5ff40fa6ada29bfc4e95f1c80be28e469fa83d5`, Quickshell commit `fae96f1a5b7f53de9b7e40e5b53c0b7a2e97b1d7`, ordinary C++, Rust, JavaScript, and QML-directive workloads. Each release workload uses one warm scan plus five single-worker full-level samples and records wall time.

### WHY

The v3.2.0/v3.3.0 review needs regression evidence from pinned inputs and a check that the new Qt macro support does not damage unrelated language throughput.

### HOW

An adversarial one-line Qt C++ class exposed a released v3.3.0 quadratic macro prepass: p95 wall time was 0.13s at 1,000 members, 1.04s at 5,000, and 4.02s at 10,000 (169KB). `qt_macros::line_prefix` scanned the entire source prefix for every identifier. The local correction reuses the already-built `line_starts` index, preserving the no-allocation ordinary C++ path. The focused macro test group passed; current release-build exploratory p95 at 10,000 members fell to 2.40s.

### IMPACT

The concrete source of the superlinear C++ regression is fixed locally pending review. Quiet-machine historical release samples remain to run before making cross-version throughput claims. QML's new enclosing-symbol implementation was flagged separately because its whole-symbol scan per ancestor would introduce another quadratic risk; use the existing interval index instead.
