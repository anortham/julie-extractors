## Task 19: Qt C++ macro pre-pass

New `crates/julie-extractors/src/cpp/qt_macros.rs` blanks Qt macros to
same-length spaces before the C++ grammar parses, mirroring the QML JavaScript
directive pre-pass.

- **Scanner** (`scan`) is token-level, never uses a tree. It skips string,
  character and raw-string literals, `//` and `/* */` comments, and
  preprocessor lines (including `\`-continued ones).
- **Four rules**: `Statement` (a line-leading `Q_`/`QML_` macro that owns its
  line), `Prefix` (same macro with code after it, plus line-leading `emit`),
  `Section` (`Q_SIGNALS:`/`signals:` become a padded `public:`;
  `Q_SLOTS:`/`slots:` become spaces; `public Q_SLOTS:` keeps its access word),
  and `Export` (`*_EXPORT`, `*_NO_EXPORT`, `Q_DECL_EXPORT`, `Q_DECL_IMPORT`).
- **New `src/preprocess.rs`** holds `blanked_source(language, content)` and
  replaces `qml_directives::blanked_source`. `pipeline.rs::parse_for_language`
  and `syntax/mod.rs` now call it.
- **`language_spec/source_detection.rs`**: a `.h` file is pre-parsed by the
  header probe, so the blanking had to be applied there too, otherwise Qt
  headers never reached the blanked text. This was the load-bearing discovery.

### Findings to report, not fixed here

The cpp method-signature builder has two pre-existing defects that the brief
assumed the pre-pass would cure:

1. `extract_basic_return_type` returns nothing for a class member, so a method
   signature is `setIndex(int index)`, not `void setIndex(int index)`.
2. `extract_method_modifiers` walks up to the grandparent node, so one member's
   `override` leaks into every method signature in the class.

Both are macro-independent and a fix would rewrite every cpp golden fixture,
which the brief lists as a stop rule.
