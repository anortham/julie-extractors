## Codex review round: 5 more receiver-proof holes fixed, 3 design tradeoffs documented, 2 items declined with evidence

Ran `codex exec` (read-only, full source diff) as a third independent review pass per user request. Codex reported 10 findings; triaged against the code and fixtures.

### Fixed (TDD, 8 new tests, all watched RED first)
- **rust.rs**: qualified `X::Client::new()` / `x: &X::Client` now require the qualifier to be the `reqwest` crate (`path_terminal_is`); bare `Client` proof tightened from "any reqwest use" to `has_rust_use_reqwest_client` (a `use reqwest::...Client` declaration).
- **kotlin.rs**: Spring receivers gained same-file local proof (`val web = WebClient.create(...)`, `val rest = RestTemplate()`) via `spring_local_is_client` reusing the anchored ctor-chain check — closes the recall gap Codex flagged at kotlin.rs:579.
- **php.rs**: `walk_assignments` is now ordered (assignment must complete before the call being proven) and closure-scoped (skips nested function-likes); `new \Aws\Client()` no longer proves Guzzle (qualified FQN must be exactly `GuzzleHttp\Client`); dynamic/unrecognized `CURLOPT_CUSTOMREQUEST` silences the handle instead of emitting a wrong default-GET verb.
- **capabilities.json**: added `elixir.http_client.alias_resolution` open_gaps entry (literal alias matching, both FP and FN direction).

### Declined, with evidence
- **"cURL should require curl_exec"**: the golden fixture (php/http_client_deferred/source.php) never calls curl_exec and its expected.json contains those facts — configuration-based emission is the shipped, fixture-backed contract. Changing it is a product decision, not a bug fix; left for the user.
- **Kotlin `content.contains` gates / file-wide unordered local proofs (kotlin+rust)**: mitigated by receiver proofs and conflict rules (any non-client same-name assignment disproves); residuals documented in the instance_receiver open_gaps entries. Parser-backed Kotlin import gates would be a further hardening, not shipped-broken behavior.
