## Vanished-file store updates now commit as deletions

### WHAT
`store update` no longer fails the whole request when the target file is gone at the planning read. On `io::ErrorKind::NotFound` it enqueues a single-file delete request under the update's request id and idempotency key, drains it, and reports a committed `update`. `store import` planning now skips a file that vanished between discovery and the identity read. All other read errors (permission, I/O, decode) keep failing the request.

Files:
- `crates/julie-extract-cli/src/store/update.rs` — fallback enqueue, delete-row idempotency adoption, kind-aware report tail (operation stays `update`).
- `crates/julie-extract-cli/src/store/import.rs` — `read_source_identity_or_missing` helper + `planned_import_files` that skips NotFound targets.
- `crates/julie-extract-cli/src/extraction.rs` — shared `read_error` helper, `content_hash_bytes` made pub(crate).
- New harness `tests/store_update_vanished_file.rs`; revised cross-kind idempotency tests in `tests/store_operations_contract.rs`.
- Decision doc `docs/decisions/2026-08-27-vanished-file-delta-semantics.md`.

### WHY
Miller's telemetry audit (2026-08-27, Priority 3): three incremental deltas in the Tycho workspace died with "source file could not be read: No such file or directory" at `StoreWorkspaceCoordinator.RequireCommitted` during branch-switch churn, forcing scan-failure backoff over files that were legitimately deleted after delta enumeration.

### HOW
- Miller rejects a report whose `operation` field differs from the invoked command (`JulieStoreClient.ParseReport`), so the fallback keeps `operation: update` while the underlying coordinator row is `RequestKind::Delete`.
- The idempotency replay branch must adopt a delete row that names exactly the update's file — a retry after a crash mid-fallback would otherwise conflict forever (poison key). Mismatched rows still conflict; the old blanket update-over-delete conflict test was revised deliberately.
- Executor drain semantics untouched: a file vanishing after enqueue still becomes a per-file failed manifest entry in a committed request; the next delta deletes it.
- Helper lives in `store/import.rs`, not `extraction.rs`, because the bin target compiles `extraction.rs` without the store module and would flag it dead.

### IMPACT
Routine branch switches no longer turn Miller deltas into failed scans plus backoff. NOT released: Miller needs a julie-extract release + pin bump afterwards, which needs user approval on the Miller side.
