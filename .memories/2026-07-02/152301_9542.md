## Updated backend HTTP boundary plan after review

- **WHAT:** Patched `docs/plans/2026-07-02-backend-http-boundary-coverage.md` and the linked decision note `docs/decisions/0004-http-boundary-join-contract.md` after plan review findings.
- **WHY:** The original plan left three contract edges ambiguous: whether normalized route templates preserve trailing slashes, whether same-file mounts emit both resolved handler facts and mount facts, and whether workers could own strategy-tier contract/capability interpretation.
- **HOW:** Made trailing slash preservation explicit in the naming rule, Cross-Family Doctrine, Task 1 normalizer acceptance, and Django acceptance example; clarified mount behavior so traceable same-file mounts emit resolved handler facts plus mount facts while untraceable mounts emit only mount facts; documented the JS/web vs backend/framework collector split for `http.client_request.v1`; added lead-owned review boundaries for registry/docs/capability/version marker semantics. Kept ADR 0004 synchronized with the updated doctrine.
- **IMPACT:** Future implementation workers have explicit acceptance criteria for slash-sensitive joins, mount-fact emission, Django include routing, shared client metadata, and strategy-tier lead review.
