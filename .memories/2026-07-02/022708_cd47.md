## Reviewed local HTTP boundary facts commits

**WHAT**
Reviewed the unpushed `origin/main..HEAD` series adding HTTP boundary structural facts and v2.6.0 release prep in `/Users/murphy/source/julie-extractors`.

**WHY**
The user asked for a thorough code review before pushing. The changes expand public extraction contracts for `http.client_request.v1`, `nextjs.route_handler.v1`, `nuxt.server_route.v1`, and `aspnet.attribute_route.v1`.

**HOW**
Inspected the changed collectors and contract tests with Miller, verified official ASP.NET Core attribute-routing semantics for absolute action templates, ran focused and full test gates, and scanned temp edge-case inputs through `julie-extract` into SQLite.

**IMPACT**
Found four actionable review issues:
- ASP.NET absolute action templates beginning with `/` or `~/` are incorrectly combined with controller route templates in `join_effective_route`, producing wrong `effective_route_template` join keys.
- `[HttpGet(Name = "...")]`/named-only ASP.NET HTTP attributes are dropped because `attribute_route_argument` treats the first named argument as `NonLiteral` instead of `Absent`.
- `fetch("/x", { headers: { method: "POST" } })` emits `verb=POST` because verb resolution searches for `method:` anywhere after the first argument instead of only top-level options.
- A comment-only `// import axios from "axios"` gates a real `axios.get(...)` fact because `collect_js_imports` is text-scanned without syntax/comment filtering.

Verification that still passed: `cargo test -p julie-extractors`, `cargo fmt --all -- --check`, focused HTTP/ASP.NET/Next/Nuxt tests, and `node scripts/language-data-quality-report.mjs --strict` with 0 silent cells and 0 quality-bar debts.
