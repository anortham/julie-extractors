## Prepared julie-extractors v2.6.1 local release candidate

### WHAT

Fixed the release-review follow-up for structural-fact `containing_symbol_id` binding and prepared local `2.6.1` release surfaces.

- `line_containing_symbol` now rejects candidate symbols whose byte span is contained by the fact span.
- Added regression coverage for same-line React route object facts so they cannot bind child property symbols such as `id`, `index`, or `path`.
- Regenerated JavaScript/JSX structural-fact goldens where module-level route objects now have `containing_key: null` instead of bad property bindings.
- Bumped the three Rust packages and `Cargo.lock` from `2.6.0` to `2.6.1`.
- Added `docs/release-notes/v2.6.1.md` and updated contract docs to describe the finalized fallback semantics.

### WHY

Route-object facts can span an entire one-line object while property symbols live inside that same byte range. The previous line fallback only checked line containment, so it could choose a child property as the containing symbol. That produced misleading ownership for bridge consumers.

### HOW

Kept the existing two-pass containing-symbol selection, but tightened the line fallback to exclude candidates whose byte range is fully inside the fact. This preserves the exported const arrow handler case, where the handler symbol line-spans the fact but is not byte-contained by it, while preventing child object properties from becoming owners.

### IMPACT

The local `2.6.1` release candidate is prepared and verified. No tag, push, publish, or package asset verification has been performed yet because that requires explicit release approval.
