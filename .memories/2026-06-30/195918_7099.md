## Implemented React and Next.js route facts

### WHAT
- Added React Router structural facts: `react.route_reference.v1` and `react.route_definition.v1`.
- Added Next.js structural facts: `nextjs.route_reference.v1` and `nextjs.file_route.v1`.
- Added focused React/Next tests under `crates/julie-extractors/src/tests/react/`.
- Added fixture-backed capability evidence for JavaScript, JSX, TypeScript, and TSX, including dedicated Next.js file-route fixtures.
- Updated public contract docs and the React/Next implementation plan ledger.

### WHY
The approved plan was to broaden framework coverage before a patch release so downstream consumers can query source-backed React Router and Next.js route definitions/references from existing structural fact surfaces.

### HOW
- Kept implementation extraction-only and deterministic from local source text plus file path.
- Import scanning gates React Router and Next.js link facts so arbitrary local `Link` components are ignored.
- JSX tag scanning now skips nameless fragments and handles `>` inside JSX brace expressions, fixing React `<RouterLink>` and `<Route element={<Reports />}>` extraction.
- Capability pattern claims were narrowed to fixture-backed surfaces: TypeScript advertises route definitions and Next file routes, not JSX link-reference facts.

### IMPACT
- Consumers can now identify static React Router links/routes and Next.js links/page routes through versioned `structural_facts` rows without schema changes.
- Capability matrix and strict language quality gates prove the new pattern claims have fixture output.
- `EXTRACTION_CONTRACT_VERSION` now includes `react-nextjs-route-facts-v1`.
