## Fixed UTF-16 source read failures in julie-extract

A user report showed Miller marking a UTF-16LE SQL file as `read_failed` because Miller delegates extraction to `julie-extract` and `julie-extract` required strict UTF-8 at the file-read boundary.

- **WHAT:** Added BOM-aware UTF-16 decoding in `crates/julie-extract-cli/src/extraction.rs` before SQL parsing.
- **WHY:** BOM-marked UTF-16LE `.sql` files should not produce partial artifacts before extraction starts.
- **HOW:** Kept UTF-8 as the default path, decoded UTF-16LE/UTF-16BE only when a BOM is present, preserved original byte hash and byte count for incremental tracking, and kept malformed UTF-16 as a read error.
- **IMPACT:** Miller should stop inheriting `julie-extract` `read_failed` artifacts for BOM-marked UTF-16 SQL files once it consumes this fixed CLI version.
