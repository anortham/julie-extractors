## Fixed review findings from committed performance branch

### WHAT
- Reverted the spooled SQLite write-path FK-off optimization by removing `ForeignKeysOff` and leaving SQLite foreign-key enforcement active during spooled scans.
- Added writer regression coverage for deleting a cross-file target symbol while a surviving file still has identifier/relationship references.
- Fixed `export --out - --json` failure routing so JSONL stays on stdout and failed reports go to stderr.
- Fixed scan profile byte accounting for read failures with known byte counts.
- Serialized the panic-hook unit test with a mutex to avoid global hook races.
- Updated `docs/contracts/cli.md`, `TODO.md`, and committed memory notes to remove stale/false claims.

### WHY
Review found correctness regressions and contract drift in the committed-but-unpushed performance work: disabling FK enforcement skipped SQLite `ON DELETE` actions, export failure could corrupt stdout JSONL, malformed-read bytes disappeared from reports, and TODO/checkpoint text misrepresented production `md5` and clippy state.

### HOW
- Let SQLite enforce cascade/null actions instead of trying to mirror all FK semantics in Rust.
- Added end-to-end tests that failed before the fixes and pass now.
- Kept docs aligned with the actual `failed_preserved`/`partial` scan behavior and current TODO scope.

### IMPACT
- Restores SQLite artifact integrity for spooled incremental scans.
- Preserves machine-readable stdout discipline for JSONL export failures.
- Keeps scan profile reports accurate for recoverable read failures.
- Leaves remaining TODO scope focused on supply-chain policy, production MD5 identity handling, and legacy clippy cleanup.
