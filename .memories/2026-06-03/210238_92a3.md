## Implemented source regions as artifact contract v2

Added `source_regions` as a first-class extraction row domain across the extractor, artifact, CLI, JSONL, reports, and docs.

- **WHAT:** Introduced `SourceRegion` / `SourceRegionKind`, shared AST-based source-region collection, SQLite `source_regions`, JSONL `source_region`, report row counts, and CLI scan/export wiring.
- **WHY:** Downstream products need AST-bounded spans for comments, doc comments, string literals, and embedded regions without julie-extractors owning search indexes, vectors, raw AST dumps, or full source text storage.
- **HOW:** Bumped artifact/schema/report/JSONL contract versions to v2, added source-region mapping from extractor results into artifacts, added writer/export/report support, and documented v2 contract files plus release note.
- **IMPACT:** Julie-extractors is now a stronger foundation for upstream tools that want scope-aware lexical filtering or AST-bounded chunking while preserving this repo's product boundary as extraction only.
