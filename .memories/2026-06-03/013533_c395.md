## Validated current large-repo performance after review fixes

### WHAT
- Live-measured current release binary against `/Users/murphy/source/hermes-agent` and `/Users/murphy/source/openclaw` with three cold `scan --force --json` runs each.
- Discovered the initial FK-on review fix made hermes scans fail with `FOREIGN KEY constraint failed` because the spooled writer inserted `parent_symbol_id` inline before later parent symbols existed.
- Fixed the writer by enabling `PRAGMA defer_foreign_keys=ON` inside the spooled transaction while keeping connection-level `foreign_keys=ON`.
- Added `spooled_scan_allows_child_symbols_before_parent_symbols` regression coverage.

### WHY
Performance numbers were invalid while the real large-repo scan failed. The unsafe FK-off shortcut had hidden a symbol self-FK ordering issue; re-enabling immediate FK checks exposed it.

### HOW
- Verified SQLite deferred FK behavior still runs `ON DELETE SET NULL` with a minimal sqlite3 experiment.
- Kept FK enforcement enabled and only deferred validation until transaction commit.
- Rebuilt `target/release/julie-extract` and reran three cold force scans per repo.

### IMPACT
- Current fixed medians: hermes-agent total 10,860ms, extraction/spool 2,885ms, artifact_write 7,914ms; openclaw total 28,889ms, extraction/spool 6,040ms, artifact_write 22,663ms.
- Compared to 2026-06-02 pre-enhancement profiling: hermes total -65.5%, artifact_write -38.5%; openclaw total -68.1%, artifact_write -40.3%.
- Compared to the earlier unsafe FK-off note, current fixed scans are roughly 17-18% slower end-to-end and 19-21% slower in artifact_write, but valid.
