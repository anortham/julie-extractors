## Continuous-testing evidence gap review

Reviewed `julie-extractors` v2.34.2 test-role output against the local Miller continuous-testing consumer.

- **WHAT:** The extractor emits `is_test`, `test_container`, `test_lifecycle`, plus evidence currency. Miller preserves these in its normal index, but the local CT seam `CtSymbolFact` carries only `IsTest`; `CtFactAdapter.ToSymbolFact` drops role and currency fields, and `ContinuousTestImpactSelector.SymbolFact.FromMiller` converts every positive into `testcase`/`test`.
- **WHY:** Adding more extractor role flags has limited CT value until the consumer preserves the shipped evidence. Exact roles are needed to distinguish runnable cases from containers/lifecycle hooks and to handle uncertain evidence conservatively.
- **HOW:** Recommend verifying this seam against the user's newer Windows Miller session, then extending the existing typed adapter rather than adding a new extractor contract. In parallel, prioritize extractor precision: Scala and Elixir currently classify every callable in conventional test paths; Python accepts any annotation key prefixed `pytest` or `unittest`. Existing golden fixture paths do not exercise those conventional-path/helper negatives.
- **IMPACT:** Best next slice is evidence-preserving CT integration plus negative-control hardening, before burning down low-value schema/markup gaps. Current local Miller is known to lag an active Windows bug-fix session, so its branch state is structural evidence only.
