## WHAT

Updated `decode_utf16_content` in `crates/julie-extract-cli/src/extraction.rs` to use `bytes.as_chunks::<2>()` instead of `chunks_exact(2)`.

## WHY

Closeout CI run 32397840877 installed Rust 1.98 and failed strict Clippy on the newly enforced `chunks_exact_to_as_chunks` lint. The tagged release candidate had already passed its CI; this is a post-release toolchain-compatibility correction on `main`.

## HOW

The slice is split into fixed two-byte arrays plus a remainder. A non-empty remainder still produces the existing odd-byte UTF-16 error, while valid arrays are copied and passed directly to the endian decoder. No runtime contract changes.

## IMPACT

Strict workspace Clippy is compatible with Rust 1.98 without changing UTF-16 decoding behavior. Formatting, CLI all-target/all-feature check, exact strict workspace Clippy, and the UTF-16 source snapshot test pass.
