## Razor comment grammar fix pinned for julie-extract 3.12.1

Branch `fix/razor-comment-grammar` in the primary checkout (uncommitted while the changed-path gate runs).

- **WHAT:** `tree-sitter-razor` pin moves from `fba8571` to `81a0aae` (anortham fork `main`). The grammar reads `@* … *@` as one token and keeps it an extra only, no longer a `_node` choice. Three product crates and the release workflow default are `3.12.1`; `EXTRACTION_CONTRACT_VERSION` adds `razor-comment-extras-v1`; ledger, release notes `v3.12.1.md`, and `docs/languages/razor.md` written.
- **WHY:** a comment first in an `@if`/`else`/`@foreach` block, element, or `@code` block made a whole Razor file one parse error (julie #29), so code-kb's Stop hook reported every `@code` member as removed. The first fork commit (`bd30dc3`, one-token comment) regressed `fixtures/extraction/razor/cross_file`: a comment above the directives counted as the first node and ended the directive section. Dropping `razor_comment` from `_node` fixed that with no corpus expectation change.
- **HOW:** the `razor/error_recovery` fixture, which recorded the old defect, is renamed `razor/comment_placement` with a component that holds a comment in every position and six `@code` members; its golden has no diagnostic and 7 symbols. `current_syntax.rs` gains seven valid comment cases and a members regression test.
- **Rejected:** making `_blended_content` optional for empty or comment-only blocks (`@if (x) { }`): 13 block forms use it and tree-sitter refuses an empty-matching rule, so that pre-existing gap stays and is recorded in the notes.
- **IMPACT:** ceres `ThemeDesigner.razor` parses with 2 local errors (a `@<span>` template) instead of one whole-file error.
