### WHAT
Confirmed the occurrence-loss reproduction on the release 3.6.3 binary: two identical same-line unresolved and resolved calls collapse to one artifact row in Rust; same-line unresolved calls also collapse in Go. Python keeps both.

### WHY
The artifact mapper derives pending and resolved IDs after filtering out spans marked non-exact, so broad call-expression spans cannot separate occurrences. Upstream canonical extraction does not run the all-symbol location rekey pass, leaving some raw Rust relationship IDs identical.

### HOW
Used generated Rust, Go, and Python source files, scanned at both facts and full levels, and queried SQLite rows. The task will test this through the real CLI before changing the shared mapping boundary. No source edits yet.

### IMPACT
Fix should use any emitted span as occurrence identity, while only exact spans supply published reference-site coordinates; pending IDs must include the full span. True spanless rows retain existing identity/dedup behavior.
