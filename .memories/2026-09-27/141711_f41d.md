## WHAT

Architecture review confirmed reference occurrence loss and missing producer-freshness enforcement; no production fix was made.

## WHY

The user wants issues assessed from current correctness and total system complexity, without treating historical decisions as constraints, and with deep support across every language.

## HOW

Used target/release/julie-extract 3.6.3 with disposable fixtures and `scan --level facts --json`. Rust `pub fn f() { external(); external(); }` emits one pending row for external. The same two calls on separate lines emit two. All three rows have null byte spans. CLI map_structured_pending drops non-exact spans; pending_id falls back to caller/name/kind/line; map_results deduplicates that ID. Fix occurrence identity across applicable language emitters, not only Rust. HTML script imports also have null spans, but two same-line tags retain two rows because their caller IDs differ; do not claim that HTML reproduction loses rows.

A separate two-file fixture simulated older producer metadata by changing binary/parser/capability metadata only. Editing one source then scanning succeeded: changed file revision advanced 1->2, untouched file stayed revision 1, global metadata became current. A wholly unchanged scan leaves old metadata intact. This proves mismatch is accepted during partial refresh; it is not a two-release output comparison.

## IMPACT

Priorities: reference occurrence correctness; extraction-identity guard for partial writes; remove global report aggregates from incremental commands; consolidate CLI receiver fallback into canonical extraction. table_totals runs 22 counts; JSON scan attribution runs 14 grouped counts then sorts all files. Read-performance/schema and resolution ownership still need actual workload evidence. code-kb was not inspected or changed.
