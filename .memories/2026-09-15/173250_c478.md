## Add the `facts` extraction level for code-kb (2.43.0, branch feat/facts-level)

**WHAT:** `ExtractionLevel::Facts` between `symbols` and `full`: symbol core plus `structural_facts`, with identifiers, literals, type-argument usages, and source regions empty. `includes_structural_facts()` gates the facts collectors in `registry.rs`; `ExtractionResults::strip_to_level(level)` replaces `strip_to_symbols_level`. CLI `--level facts` (`LevelArg::Facts`). Version 2.43.0 in all three crates. Docs: `docs/contracts/cli.md` level section, release notes `docs/release-notes/v2.43.0.md`, release-notes README list.

**WHY:** code-kb reads only the symbol core, structural facts, literals, and type facts. `full` wrote ~60% data code-kb never read (hermes-agent: 3.9 GB, 85 s, 5.3 GB RSS). `symbols` dropped structural facts code-kb needs. See code-kb docs/plans/017.

**HOW:** TDD: lib test `facts_level_keeps_structural_facts_and_drops_reference_families_for_every_fixture_language` and CLI test `scan_level_facts_keeps_structural_facts_and_drops_reference_domains` written red first. Literals are dropped at `facts` for cross-language uniformity because most languages record them in the identifier walk. Rejected: changing the meaning of `symbols` (would silently change existing artifacts and the store's `l1`).

**IMPACT:** New `index_level` value `facts`. Older binaries report it as an unknown index level per the existing contract. code-kb 1.0.2 pins 2.43.0 and requests this level. Release not yet published.
