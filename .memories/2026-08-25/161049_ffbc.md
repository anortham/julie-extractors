## CT language readiness audit (workflow, 12 Opus agents)

### WHAT
Ran a full audit of julie-extractors test-detection readiness for Miller continuous testing (CT). Two contract scouts derived (a) what Miller CT consumes from the artifact and (b) the QML-derived 15-item extractor checklist. Ten language audits graded: go, ruby, java, php, kotlin, swift (candidates) and rust, python, javascript+typescript, csharp (existing CT languages). Full results: session task output `w25yjyrp1` (scratchpad) and tool-results/b91rctihr.txt in the session dir.

### WHY
User wants to prep more languages for Miller CT after QML, and to find gaps in languages CT already runs.

### KEY FINDINGS
- Miller CT providers today: Dotnet, Node, Python, Rust, QML. Test *discovery* is provider-side (real test tool); *staleness* is artifact-side (change journal + symbols + is_test/test_container/test_lifecycle).
- Highest-leverage cross-language item: Miller's `ContinuousTestClassifier` reads a `test_role` string from `symbols.metadata_json` first (confidence 1.0) but NO extractor writes it. Also `test_linkage`/`test_coverage` readers exist in Miller with no writer.
- Verdicts: java=minor_gaps (1 session), csharp=minor_gaps (2 sessions), everything else major_gaps. JS/TS worst (3 sessions).
- Blockers found: Go testify suite lifecycle/containers unhandled + go/functions.rs never emits test_lifecycle; Ruby Rails `test "..." do` macro emits NO symbol (Rails suites invisible) + bare RSpec DSL false positives in production code; Swift Testing @Test/@Suite emits no role flags + XCTestCase never test_container (ledger over-claims).
- Existing-CT correctness bugs: jsx/tsx language-string mismatch between artifact and Miller extension map breaks selector matching; Playwright test.describe misclassified; parameterized tests (test.each) emit nothing; pytest fixtures and xunit-style hooks invisible; `*_test.py`/`conftest.py` not test paths; xUnit ctor/Dispose lifecycle invisible; detect_rust accepts only test/tokio::test/rstest keys.
- Ledger honesty problem is systemic: `supported` claims rest on thin single-idiom goldens (e.g. ruby 9-line fixture, rust plain #[test] only).

### DECISION (proposed order, pending user)
1. Fix existing-CT gaps first (JS/TS 3 sessions, Python 2) since they degrade CT today.
2. New languages: Go first (popular, clean `go test` provider story, 2 sessions), then Java (1 session, cheapest), then Ruby (2 sessions, blockers).
3. One shared task: emit `test_role` string + decide test_linkage contract.

### IMPACT
Ranked, evidence-backed prep plan for CT language expansion. All four worktrees verified clean; fix/test-detection-precision fully merged into main.
