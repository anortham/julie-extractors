## Fixed both confirmed defects on `delta-resolution-soundness`; gate now 9 cases

Follow-up to the codex cross-model review. Both confirmed defects fixed, four cases added. Uncommitted on branch (base 241c842).

### Fix 1 — module-path invalidation (the blocker)
Module selection turns on which candidate PATH exists, so add/delete re-points a specifier while changing no symbol name. Name-keyed unions are structurally blind to it.

- Split `resolve_import_module_file` into `import_module_candidates` (paths a specifier COULD bind to, existence-independent) + `select_module_file`. Dead `#[cfg(test)]` wrapper removed.
- `load_import_records` now returns `(Vec<ImportRecord>, HashMap<file_id, BTreeSet<candidate path>>)` — built in the SAME loop that already computes candidates, so zero extra SQL. New index field `module_candidates_by_file`, empty from `build()`, populated by `load_index`. **ImportRecord untouched** — deliberately, to avoid churning 10 unit-test constructors.
- New accessor `files_importing_module_candidates(&changed_paths)`.
- New `structurally_changed_paths(conn, revision, ids)` reads `revision_file_changes` for THIS revision, filtered to `('inserted','deleted','unsupported')`.

**Key refinement found while measuring:** first version keyed on ALL changed paths, which over-fired on every pure rewrite (a rewrite cannot move a `module_file_id` — `file_id = stable_id("file",[&path])`). Narrowing to structural kinds made the rewrite case cost-neutral. `updated` excluded on purpose; `unsupported` included because it also drops the `files` row.

### Fix 2 — SQLite bind-limit regression
`unresolved_pending_in_files` chunked by `FILE_QUERY_CHUNK`; results re-sorted after merge since per-chunk ORDER BY doesn't order the whole.
