## Added JSON Report Contract Model

### WHAT
Implemented Task 7 report model support in `crates/julie-extract-artifact`.

- Added serializable report structs for the JSON report envelope, input, artifact metadata, tool identity, revision, counts, diagnostics, and optional languages payload.
- Added stable `ReportStatus`, `ReportOperation`, `ReportMode`, and `ReportCode` enums using snake_case JSON serialization.
- Added `REPORT_SCHEMA_VERSION = 1` and custom `Report` serialization so callers cannot drift the schema version field.
- Added exhaustive `RowDomainCounts` for SQLite v1 row domains plus conversion from writer `RowCounts`.
- Added `tests/report_contract.rs` covering schema version, every status value, every v1 error code spelling, single-file paths, and exhaustive row-count keys.
- Added `serde` and `serde_json` dependencies to `julie-extract-artifact`.

### WHY
Task 7 requires a stable product-owned JSON report/error API before the CLI can emit machine-readable reports. The model must avoid old Julie flat analysis/status fields and match `docs/contracts/reports.md`.

### HOW
Tests were written first against the public report API and failed with missing imports. Implementation then added the public report structs/enums and serde serialization. Export mode was modeled as `jsonl`, matching the command-specific contract despite the general field-doc ambiguity.

### IMPACT
Unblocks CLI contract and operations work that needs typed status/error/report serialization while preserving SQLite v1 exhaustive row count domains.
