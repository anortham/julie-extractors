## Added CLI Contract Skeleton

### WHAT
Created `crates/julie-extract-cli` with the `julie-extract` binary, v1 command parsing, JSON report plumbing, language capability reporting, initial info/export behavior, and contract tests.

### WHY
Task 9 requires the standalone process interface to become the primary integration surface for non-Rust callers while keeping SQLite/JSONL artifact contracts central and excluding old Julie server/search/tool behavior.

### HOW
- Added clap-based parsing for `scan`, `update`, `delete`, `info`, `export`, and `languages` with the documented flags.
- Reused `julie-extract-artifact::reports` types for stable JSON reports and mapped exit codes `0`, `1`, `2`, and `3` in CLI contract tests.
- Added `languages --json`, artifact `info`, and `export --format jsonl` plumbing over existing artifact APIs.
- Added negative contract tests for absent `analyze` and forbidden old Julie behavior terms.
- Wired the CLI crate into workspace, default tier, and contract tier.

### IMPACT
The CLI process surface now exists and is protected by both default and contract tiers. Task 10 can focus on path policy/source discovery; Task 11 can replace the scan/update/delete failure paths with full extraction operations.
