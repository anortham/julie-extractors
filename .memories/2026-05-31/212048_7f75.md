## Task 10 path policy implementation ready to commit

### WHAT
Implemented the `julie-extract` Task 10 source discovery and path-policy layer.

- Added CLI path canonicalization in `crates/julie-extract-cli/src/paths.rs`
- Added source/ignore classification in `crates/julie-extract-cli/src/discovery.rs`
- Wired `scan`, `update`, and `delete` through canonical root/db/file paths, root mismatch checks, and stale-row cleanup for ignored/unsupported update targets
- Added `tests/path_policy.rs` and added it to xtask contract tier
- Expanded CLI forbidden-boundary test to scan new production modules

### WHY
Task 10 requires strict CLI boundary path handling before end-to-end extraction is wired in Task 11. The product contract needs root-relative Unix paths in artifacts, typed outside-root/missing-file/root-mismatch errors, and safe behavior for missing delete targets.

### HOW
Used the old Julie external extraction code only as evidence, then rewrote product-local path/discovery modules around the standalone CLI and artifact writer. `ignore` provides gitignore-style matching; `time` provides RFC3339 metadata timestamps. Unsupported/ignored update targets call artifact delete cleanup instead of preserving stale rows.

### IMPACT
Task 10 path policy is covered by a public CLI contract test and included in default and contract tiers. `scan --force` can rebuild root-bound metadata and clear old rows when no supported extraction rows need to be produced yet; full supported-file extraction remains Task 11 by plan.
