## Added Batched SQLite Artifact Writer

### WHAT
Implemented the Task 6 SQLite writer path in `crates/julie-extract-artifact`:

- Added an artifact-owned normalized write model in `src/model.rs`.
- Extended `ArtifactWriter` with scan, update, and delete operations.
- Persisted all SQLite v1 row families through one transaction per operation.
- Added writer contract tests for scan/update/delete replacement, rollback, cross-file relationships, unchanged-hash skipping, force-scan rewriting, child-row cleanup, and data-loss guarding.
- Added a tiny-fixture writer performance tripwire that asserts one commit and a small wall-clock budget.

### WHY
Task 6 needs the product-owned artifact writer to optimize SQLite extraction throughput without inheriting old Julie database/schema coupling.

### HOW
The writer uses explicit transactions, prepared inserts, exact file-row cleanup, content-hash skip logic for incremental/single-file writes, force-scan rewrite behavior, and a pre-delete data-loss guard for parser/read failures or zero-symbol parser output over known-good rows.

### IMPACT
This creates the core durable SQLite artifact write path needed before report, JSONL, CLI, and end-to-end operation tasks can be wired safely.
