## Made SQLite Performance A Contract Priority

- **WHAT:** Updated schema docs and testing strategy to put performance on equal footing with correctness for the SQLite artifact.
- **WHY:** The product is optimized around `source tree -> versioned extraction artifact`; slow writes or missing indexes would make the standalone product poor even if the schema is logically complete.
- **HOW:** Added performance requirements to `docs/architecture/schema-principles.md`, required writer behavior and required indexes to `docs/contracts/sqlite-schema-v1.md`, and performance guardrails to `docs/testing-strategy.md`.
- **IMPACT:** Future implementation must use explicit transactions, prepared statements, batched inserts, indexed file replacement, WAL-friendly operation, required schema indexes, tiny-fixture writer budgets, query-plan checks, and per-row commit detection.
