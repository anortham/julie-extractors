## WHAT

Independent semantic, rebase, and SQL-scale reviews evaluated the first direct scoped-delta draft. Semantic parity and Windows handle closure passed, but the draft was rejected because it still streamed the full base/effective corpus and reported overlapping phase timings.

## WHY

Avoiding scratch materialization is insufficient if a one-file update still hashes and traverses hundreds of thousands of unchanged rows. The recovery target requires work proportional to changed state, not repository size.

## HOW

The accepted boundary is: carry the prior base-relative delta for untouched sources, recompute only touched/removed source rows against keyed base reads, and validate only the changed closure. Existing frozen-overlay validation remains authoritative; ordinary scoped finalization must not reopen/hash the complete base. Resolution, diff, and publish timers must remain exclusive.

## IMPACT

The current dirty implementation is not commit-ready. A bounded correction packet is active. Future work must reject any design that reintroduces full-corpus scans or overlapping telemetry even if correctness tests pass.
