## Diagnosed abandoned v2.12.1 release + added release-state tripwire

User flagged that Miller/Eros were updated to a new julie-extract version while fixes sat unpushed locally.

- **Finding:** v2.12.0 released correctly on 2026-07-10 (tag, assets, Miller pin all good). The push CI then went red (Rust 1.97 Clippy on 7 files). A v2.12.1 closeout patch (`03cab8f`) was prepared 16 minutes later, locally verified, then never pushed/tagged/released — it sat local-only for a day. The stranded fixes are Clippy-only; no functional changes were missing downstream.
- **Root cause:** the closeout checks in docs/release.md only run when someone remembers; nothing fails loudly when a release-prep commit exists without its pushed tag.
- **Fix:** added `scripts/check-release-state.sh` — fails on (a) source version without origin tag, (b) local main ahead of origin/main, (c) local tags missing from origin, (d) version tag not ancestor of origin/main. Verified it detects the exact current failure state. Wired into docs/release.md as session-start + first closeout check; noted in v2.12.1 release notes.
- **Next:** push main, wait for CI green, tag v2.12.1, push tag (triggers release-binaries workflow), verify assets, re-run tripwire.
