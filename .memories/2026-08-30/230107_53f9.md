## Wrote the approved extractor gap closure design

### WHAT

Created `docs/plans/2026-08-30-extractor-gap-closure-design.md` with architecture, acceptance criteria, verification rules, non-goals, and plan boundaries for BRE-16, BRE-43, BRE-53, and BRE-42.

### WHY

The remaining issues touch four independent language subsystems. A shared implementation plan would couple their completion and let the F# parser integration delay smaller fixes.

### HOW

The design keeps existing artifact interfaces stable, adds only language-local extraction behavior, and requires one implementation plan per Linear issue. F# uses the grammar's separate implementation and signature parsers while publishing one `fsharp` artifact language.
