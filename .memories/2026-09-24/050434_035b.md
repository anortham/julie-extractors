## PowerShell: fixed the review findings for call-initializer type inference

- **What:** Five review findings are fixed in `powershell/type_facts.rs`. Inference now records nothing for these forms:
  - an operator or a leading comma around the value (`-not (Get-Foo)`, `,(Get-Foo)`, `-not [Foo]$y`);
  - a compound assignment (`+=`, `??=`);
  - a script path call (`& ./lib/Get-Foo`);
  - `$this.M()` inside a script block;
  - a command with a redirection.
- **How:**
  - `unwrap_value` looks through a wrapper only when the wrapper has exactly one child, counting anonymous tokens. A bare cast is still a one-child `expression_with_unary_operator`, and `-not x` has two children.
  - `is_plain_assignment` requires the operator text to be `=` and no direct ERROR child. `??=` parses as ERROR plus `=`.
  - A `command` target whose text has `/` or `\` records nothing.
  - `in_script_block_within_class` stops `$this` inference inside a script block.
  - `has_redirection` checks `command_elements` for a `redirection` node.
- **Finding correction:** the review suggested rejecting `path_command_name` targets. This is wrong, because `& Get-Foo` also parses as `path_command_name`. The code checks for path separators instead.
- **Evidence:**
  - Added 10 tests. Each mutation of a guard makes its test fail.
  - The corpus rerun removed one fact: the `+=` pscustomobject fact in PSScriptAnalyzer. The 155 new facts did not change.
- **Open:** the identifier and relationship receiver type for `$this` inside an Add-Member script block still uses the enclosing class. This code was already on the base branch before this slice.
