## Fixed the C review findings for call-initializer type inference

The C `ReturnTypeIndex` dropped every name from a declaration with a parse error. So a local that shadowed the callee did not block the fact, and `w` got the wrong type `widget`. The three cases were a C23 `auto make = pick();` local, `long (*make)(void) = container_of(...)`, and a malformed prototype that disagreed with another prototype.

- **Fix:** `malformed_declaration_names` in `c/type_facts.rs` now records each declarator name as unknown. It also records a name that tree-sitter-c misread as the type (a `type_identifier`, or the name of a `macro_type_specifier`, as in `auto make = (factory)pick();`). It leaves out the misread callee of a C23 `auto` declaration.
- **Tests:** added 4 tests: the C23 auto shadow (5 shapes), the malformed-local shadow (2), the malformed disagreeing prototype, and the attr_pure macro gap. Mutation checks showed that each case gives `widget` without the fix.
- **Docs:** `docs/languages/c.md` now states that malformed declarations block the fact, and lists the gap for a macro between the return type and the name.
- **Corpus:** picom has the same 51 inferred facts after the fix. drgn and jq still have 0.
