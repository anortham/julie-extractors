## C call-initializer inference: second review fix

- **What:** In `c/type_facts.rs`, a function name that tree-sitter-c misreads as a call now makes the name unknown. This happens when a macro with arguments stands before the real name, as in `__attribute__((malloc)) make(void)`, `NONNULL(1) make(void *p)`, or `__declspec(dllexport) make(void)`. The new `misread_function_names` function does this for well-formed and malformed declarations and definitions.
- **Why:** The reviewer found a high finding. If the misread declaration sat in one `#ifdef` branch and `struct widget *make(void);` sat in the other, the scan recorded `widget`, which is wrong.
- **Test:** `parenthesized_attribute_prototype_that_disagrees_records_no_fact` checks 4 shapes. With the fix removed, all 4 shapes gave `widget`.
- **Docs:** `docs/languages/c.md` now says two things. A local that tree-sitter-c reads as a call (`fp_t (make);`, `LIST_HEAD(make);`) does not block the fact. A macro with arguments before the function name blocks the fact.
- **Corpus:** The inferred facts did not change: picom 51, drgn 0, jq 0.
