## PowerShell: infer local types from same-file call initializers

- **What:** Untyped `$x = ...` assignments now get an inferred type fact from a same-file function with exactly one `[OutputType([T])]` type, from `$this.M()` on an instance method of the enclosing class, or from `[Foo]::M()` on a static method of a same-file class. Parentheses are looked through.
- **How:** `ReturnTypeIndex` in `powershell/type_facts.rs` is built once per file in `extract_symbols`. It also holds the class names, so the old per-assignment whole-file class search is gone. Names match case-insensitively. Same-named candidates must agree. `$this.` looks only at instance methods and `::` only at static methods.
- **Records nothing for:** pipelines, longer chains, inherited methods, string OutputType, two different output types, and callees in other files. A written type still wins.
- **Evidence:** 25 new unit tests. Removing each key guard makes its negative test fail. The corpus scan (Pester, DscResource.Base, ImportExcel, PSScriptAnalyzer, SqlServerDsc) added 155 inferred facts, 0 wrong, and changed no declared facts. Unresolved receiver calls went from 2234 to 2227 in SqlServerDsc. Most new types are hashtable, string, or bool, so few receiver calls resolve.
- **Docs:** added `docs/languages/powershell.md`.
