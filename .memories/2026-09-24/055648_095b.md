## C# call-initializer inference: second review fixes

**What:** I fixed two high review findings in `crates/julie-extractors/src/csharp/initializer_types.rs` (C# and Razor share this file).

- **Static receiver visibility:** `Type.Method()` now binds its receiver the way C# name lookup does. The order is: types nested directly in an enclosing type (innermost first), then top-level types of the call's namespace, then each outer namespace, then the global namespace. The receiver's type argument count must match. The first scope with a matching type decides. A receiver named like a type parameter records nothing. A new `types` index with `TypeDecl` holds each type's container (a type or a namespace), its type parameter count, and its open flag.
- **Open-type overloads:** a type is open when it has a base list or `partial`. Its methods count only for a call with no arguments to candidates with no parameters (see `safe_in_open_type`). This holds for simple-name calls, `this.` calls, and static calls. The Razor file class is always open.
- **Generic filter:** with explicit type arguments, only methods with the same type parameter count match. With no arguments and no type arguments, generic methods are skipped.
- **Removed:** the file-scoped namespace handling. It never tells two same-file types apart.

**Why:** a wrong type is worse than no type. The reviewer showed that same-file base overloads, partial types, and invisible nested or namespaced types produced wrong facts.

**Evidence:** 13 new tests (12 C#, 1 Razor). Ten of them failed before the fix. I made 8 mutation checks and each one made a test fail; two first survived, so I added a test and deleted dead code. On the corpus, the fix lost 252 correct but unprovable facts and gained 1 correct fact (ParseLambda<T>). Every base fact is kept. All tiers, clippy, fmt, and the strict quality report pass.

**Docs:** csharp.md has new bullets for the receiver lookup and the open-type rule. I renamed the open gap to "bindings in another file" and gave it a concrete closure.
