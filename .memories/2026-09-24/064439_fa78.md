## Scala call-initializer inference: second review round fixed

Fixed 5 review findings (4 high, 1 medium) in `crates/julie-extractors/src/scala/type_facts.rs`.

- **.get unwrap:** unwraps only the Scala `Option`/`Some`/`Try`/`Success`. A qualified name must be `scala.Option`, `scala.Some`, `scala.util.Try`, or `scala.util.Success`, and `_root_.` is allowed. An unqualified name is blocked by a same-file type, by a foreign import of the name (including a rename), or by a wildcard import from outside a safe package list. Unqualified `Try`/`Success` also need an import from `scala.util`. Import parsing is in `imported_names`.
- **Case class shadowing:** `lookup_term` stops at a nearer case class (`Term::CaseClass`, which gives Name) or enum (no fact). A plain class passed on the way out turns an outer def or object into no fact.
- **Export:** an `export` in a template body or at top level counts as inheritance.
- **Synthetic companions:** a case class companion (`apply`, `unapply`, `fromProduct`, `tupled`, `curried`) and an enum companion (`values`, `valueOf`, `fromOrdinal`) block their members. `Obj.apply` and `this.m` in an object route through the new `object_member`, which keeps the case-class result guard.
- **Inherited abstract types:** `names_concrete_type` gives no name for an unqualified type inside a template that can inherit, unless the file declares it as a concrete type and never as an abstract member. The index build is now two passes, so def shapes can see the file's types.
