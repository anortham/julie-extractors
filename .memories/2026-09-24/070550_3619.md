## PowerShell call-initializer inference: second review round fixed

- **Unrolled output:** a function whose OutputType is an array, a generic type, a collection name (suffix List/Collection/Array/Queue/Stack/Enumerable/Enumerator/DataTable), or a same-file class that derives from one now records nothing. PowerShell unrolls function output. Method calls still record arrays.
- **Generic owner:** `[Foo[int]]::M()` and `[Foo[int]]::new()` record nothing (ReducedType.is_generic).
- **Aliases:** Set-Alias/New-Alias/sal/nal (-Name or first positional) and function `[Alias()]` names hide same-named functions. A non-literal alias name stops function inference in the whole file.
- **Nested functions:** a function nested in a function or class method is visible only inside it. Script blocks count as top level (Pester BeforeAll). An enclosing node with a parse error is not trusted (SqlServerDsc DSC_SqlSetup misparse nests 7 top-level functions).
- **Mutation:** comparison-around-call test now kills the `child_count() >= 1` mutant.
- **Corpus:** 6 wrong facts removed (the 5 named plus sqlSystemAdminAccounts Object[]); 149 new facts vs base. One source OutputType lie found (Compare-TargetResourceState declares Boolean, returns hashtable array): documented as a limit.
