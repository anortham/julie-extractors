## VB.NET call-initializer inference: review fixes

- **What:** Fixed 8 review findings in `vbnet/type_facts.rs`.
  - Arity check: a call records no fact when no candidate takes its argument count (VB indexes the result of a parameterless function). `Optional` and `ParamArray` count.
  - `ConfigureAwait(...)` keeps the task type only as the direct operand of `Await`.
  - Lambda parameters shadow a called name or qualifier.
  - An open type (Inherits, Partial, or more than one part in the file) stops the unqualified search. `Overloads`/`Overrides` in an open type records no fact.
  - Modules and qualifier types must be in scope: same or enclosing namespace, unaliased `Imports`, or a nested type inside its declaring type.
  - Unqualified `Object` member names (ToString, Equals, ...) never fall back to module functions.
- **Why:** Each finding produced a wrong type. A wrong type is worse than no type.
- **Evidence:** 10 new tests fail on the old code and pass now. The language, default, and contract tiers pass. Clippy and fmt are clean. The strict quality report shows 0 silent cells and 0 debts.
- **Corpus:** The fix removed 1 of 56 new facts (an `Overrides` call in an inheriting class, a correct fact lost on purpose). It added 0 facts.
- **Docs:** `docs/languages/vbnet.md` lists the new no-fact cases and the partial-type limits.
- **Note:** The scratchpad file `type_facts.new.rs` is a symlink into a shared cache. A `cp` over it wrote through to the shared file of another agent for about 1 minute.
