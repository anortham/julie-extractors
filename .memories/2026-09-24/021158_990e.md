## C: infer `auto` / `__auto_type` local types from same-file call initializers

Resumed after an out-of-memory crash killed the previous agent. I kept its uncommitted work and fixed the defects below.

- **Contract:** A GNU `__auto_type` or C23 `auto` variable gets an inferred fact equal to the declared return type of a same-file function it calls by name. Same-named declarations must agree. A same-named macro, variable, or parameter anywhere in the file blocks the fact.
- **Fixes to the earlier work:**
  - A parameter or typedef function-pointer variable that shadowed the callee produced a wrong type. The index now records every declared name, so the shadowed name becomes unknown.
  - The old signature path matched substrings. `auto t` gave the type `au` and `float a` gave `flo`. It now matches whole words and skips unnamed variables.
- **C23 misparse cleanup:**
  - The misread variable name and `__auto_type` no longer emit type usages or `uses` edges.
  - `auto w = f();` now emits the call edge and the call identifier.
  - A bare-name argument is now a variable reference.
- **Corpus:** picom gained 51 facts, and all 51 are correct. It lost 96 wrong `auto` facts and 856 wrong pending `uses` rows. jq and drgn gained no facts.
- **Docs:** added `docs/languages/c.md`.
