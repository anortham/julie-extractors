## Elixir: infer local types from same-file call initializers

- **What:** `x = load()`, `x = Store.load()`, `x = __MODULE__.load()`, and `x = a |> load()` take the callee's `@spec` base type. `{:ok, x} = open()` binds `x` as a new local and gives it `T` when the spec is `{:ok, T}` and every other alternative is a literal.
- **How:** Spec matching now runs at the end of `extract_symbols`, so a spec after its def still applies. Two specs for one head that disagree record nothing, which also fixes the existing function fact. `record_initializer_type` in `relationships.rs` uses `CallScope` for alias expansion and requires a strict arity match. Every reachable definition must have a spec and agree. Macro calls record nothing.
- **Evidence:** 18 unit tests, and each key guard was removed once to confirm a test fails. There is a new golden fixture `elixir/call_initializers`. The ecto corpus gained 5 facts and plug gained 1, and all 6 match the callee spec. The receiver query stays at 0, because Elixir emits no `method` symbols.
- **Docs:** new `docs/languages/elixir.md`.
