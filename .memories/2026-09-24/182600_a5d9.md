## Prepare julie-extract 3.6.1: Python instance-attribute signatures keep `self.`

**WHAT:** `python/assignments.rs` now writes `self.x = v` (also annotated and tuple targets) as the signature of a `self.x` property row. Before, it wrote `x = v`, so code-kb skeletons showed method assignments as class attributes (flask `Flask.cli`, `debug`, `_got_first_request`). Contract marker `python-instance-attribute-signature-v1`, ledger entry 3.6.1, release notes v3.6.1, Python language page, 4 golden fixtures (7 signature lines), versions 3.6.1. Release-notes README pointer moved to v3.6.0 (3.6.0 missed it); site still says v3.5.0 and must move to v3.6.1 in the publish commit.

**WHY:** Found by the code-kb v2.2.0 dogfood; user asked for the julie patch release plus any defect found on the way.

**HOW:** Kept kind `property` (tested design); only signature text changes. JS/Lua/Ruby already keep the receiver; other languages emit no such rows.
