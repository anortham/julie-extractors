## JS and QML: fixed the review findings for call-initializer type inference

- **WHAT:** This commit fixes five review findings on feat/type-infer-javascript.
  - QML: a bare call resolves in the scope object and then the component root. An object in between that declares the name stops resolution, so the call gets no fact.
  - JS: the own name of a named function expression now shadows the callee.
  - JS: a generator callee must declare Generator, Iterator, IterableIterator, or Iterable (or the Async forms).
  - JS: a doc before a multi-declarator const, let, or var now documents only the first declarator. `helpers::is_later_declarator` clears the doc in `extract_node_symbol` and in destructuring.
  - JS: `visible()` now scopes candidates by the syntax tree, not by parent_id. `var` is scoped to the function. `let`, `const`, `class`, and imports are scoped to the block. A function declaration is scoped to its block. A call elsewhere in the same function records nothing, because sloppy code hoists the declaration.
- **WHY:** Each finding recorded a wrong type. A wrong type is worse than no type.
- **HOW:** The class-expression part of finding 2 was already handled. The extractor names a class expression by its inner name, so `class_named` sees two classes and records nothing. The test for it stays as a regression test.
- **IMPACT:** The corpus facts did not change: eslint 1878, kirigami 14, express 76 inferred. The kirigami QML call graph did not change. eslint lost 5 wrong docs on later declarators. 10 new tests. A mutation check on each guard makes a named test fail.
