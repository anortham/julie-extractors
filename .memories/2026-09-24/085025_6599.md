## C call-initializer inference: switch from blocklist to expected-use rule

- **What:** `ReturnTypeIndex::build` in `crates/julie-extractors/src/c/type_facts.rs` now marks a name unknown when any identifier or type_identifier with that text shows up in an unexpected place. Expected places: the name of a well-formed declaration or definition, the callee of a call, the callee of the C23 `auto w = f();` misread, and a struct/union/enum tag. Misparsed contexts (ERROR nodes, malformed declarations, expression statements with errors, file-scope expression statements) never count as expected.
- **Why:** The final review found more tree-sitter-c misparse shapes that let a wrong fact through: `gadget_fn *const __attribute__((unused)) make = pick;`, `struct gadget *(* __attribute__((unused)) make)(void)`, `_Atomic(gadget_fn *) make;`, and a macro with a parenthesized name, `struct gadget *API (make)(void);` and `(API make)`. Adding a guard per shape was whack-a-mole.
- **How:** Removed the separate rules for assignment targets, parameters, preproc names, and malformed-declaration names, because the expected-use rule covers them. Kept `misread_function_names`.
- **Impact:** `fp_t (make);` and `LIST_HEAD(make);` now also block the fact. The earlier c.md note said they did not. Docs updated. New tests: attribute_or_atomic_local..., local_read_as_a_call..., parenthesized_name_after_a_macro....
