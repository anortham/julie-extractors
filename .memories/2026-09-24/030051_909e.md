## Erlang: infer local types from same-file call initializers

The worktree held no work from the agent that ran out of memory, so this slice started fresh.

- **What:** `X = Value` body matches now record an inferred type fact when `Value` is a call to a same-file function whose `-spec` clauses all agree on one base return type. The call can be `load()`, `?MODULE:load()`, or `own_module:load()`. Record updates (`Old#rec{..}`) of same-file records now count as record values too.
- **Guards:** The function must be defined in the file. Spec clauses and duplicate specs must agree. A variable bound by several matches in one function keeps a fact only when every match agrees. Other modules, fun variables, macros, `catch`, and type-variable, union, tuple, or list returns record nothing. In a `.hrl` file, `?MODULE` calls record nothing.
- **How:** `InitializerScope` in `erlang/type_facts.rs` is built once per file. `DeclaredTypes::agreed_spec_returns` is in `erlang/types.rs`.
- **Evidence:** 25 Erlang type_facts tests, and each key guard was checked by removing it. The golden `return_types` fixture was extended. Corpus: cowboy +28 facts, rebar3 +50, 0 facts lost, 78/78 spot-checked correct. Unresolved receiver calls stay at 0 because Erlang has no receiver calls.
- **Open:** `{ok, S} = load()` tuple patterns are out of scope, because tuple-pattern variables are not emitted as symbols.
