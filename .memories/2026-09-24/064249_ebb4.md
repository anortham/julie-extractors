## Elixir call-initializer review round 2: quote calls and same-module alias check

- **What:** `initializer_type` (elixir/relationships.rs) now returns None for a call inside a `quote` block, and for a same-module call whose dotted spec return name expands differently at the call than at the spec.
- **Why:** Quoted code runs in the module that injects it, so `load()` and `__MODULE__` do not mean the module that holds the quote. A module-level alias after the spec, or a function-body alias, changes what `Ws.t` means at the call site.
- **Tests:** `call_inside_a_quote_records_nothing` and `same_module_spec_name_that_an_alias_reads_differently_records_nothing`. Both failed before the fix.
- **Docs:** docs/languages/elixir.md records both rules.
- **Corpus:** the type facts, relationships, and pending rows in ecto, plug, phoenix, and phoenix_live_view did not change. The earlier report counted inferred facts for all languages and labeled them as Elixir-only. The Elixir-only counts are 97, 30, 84, and 17.
