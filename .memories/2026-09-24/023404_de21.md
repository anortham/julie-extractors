## Scala: infer local types from same-file call initializers

Resumed after an out-of-memory crash. The previous agent left only the test file (`tests/scala/initializer_types.rs`). This session wrote the implementation.

- **What:** An untyped `val`/`var` now gets an inferred type fact when its initializer calls or references a same-file `def` with a declared return type. The def can be local, top-level, a member of an enclosing template, reached through `this.`, or an object member. Companion `Name(..)` uses the object's `apply` defs.
- **How:** `ReturnTypeIndex` (in `scala/type_facts.rs`) is built once per file and stores defs by the node that declares them. The lookup walks outward from the call site. It stops with no fact when a value binding shadows the name, or when an enclosing template can inherit the name (extends, self type, case, anonymous, enum/given, or an Any member). The call's argument lists must match the def's explicit lists or all of its lists. `.get` unwraps Option/Some/Try/Success.
- **Discovery:** tree-sitter-scala puts a def's `[T]` list under the `parameters` field. Parameter lists are therefore counted by the `parameters` kind, and type parameters by the `type_parameters` kind.
- **Impact:** Corpus of scopt, fastparse, and cats-effect (753 files): 178 new inferred facts, 0 wrong. Unresolved receiver calls dropped from 5184 to 5158. The old rule gave `Worker[F](..)` the wrong type `Worker`; it now gives the apply's return type, `Resource`.
