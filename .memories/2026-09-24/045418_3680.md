## Erlang: fixed the review findings for call-initializer type inference

- **What:** `{ok, X} = load()` now binds `X` as a body local. `X` gets `T` when every `{ok, T}` alternative of the same-file `-spec` agrees on `T`, and every other alternative is an atom or a tuple with another tag or size. The open gap from the first pass is closed, so capabilities.json needs no open_gaps entry.
- **Atom and no_return fixes:** A spec that returns a bare atom (`-> ok`), `no_return()`, or `none()` now gives locals no fact. The atom must not join to a user type named `ok()`.
- **How:** `SpecReturn { value, ok_payload }` in `erlang/types.rs` replaces `Option<DeclaredType>`. `InitializerScope::ok_payload_type` in `erlang/type_facts.rs` does the lookup.
- **Docs:** New `docs/languages/erlang.md` with a Types section that lists the inferred cases and the no-fact cases.
- **Corpus:** cowboy 825 -> 827 facts, rebar3 1630 -> 1631, in-repo 77 -> 77. One fact went away: cowboy_handler.erl `Result => ok`, which was the atom bug. Four new facts, all checked correct. About 1.1k new untyped tuple locals. The certifi_pt.erl baseline in erlang_corpus.rs went from 14 to 15 symbols.
- **Evidence:** 5 new tests, and each new guard was mutated to prove a test fails. The erlang language tier, default tier (20s), contract tier, clippy, fmt, and the DQ report with --strict all pass.
