## C# and Razor: infer var types from same-file call initializers

Resumed the killed agent's uncommitted work on `feat/type-infer-csharp` and finished it.

- **What:** `csharp/initializer_types.rs` builds a `ReturnTypeIndex` once per file. `var x = Load()`, `this.Load()`, static `Type.Create()`, and local functions now get an inferred fact. `await` unwraps one `Task<T>`/`ValueTask<T>` layer, also through `ConfigureAwait`.
- **Fixes over the prior draft:** callable owners are keyed by declaration position, so same-named nested types no longer lend members. Only in-scope local functions count. Razor `@{ }` markup `var` locals now get facts too (`expressions.rs`).
- **Guards:** overloads with an accepted arg count must agree. Type-parameter returns record nothing, and so does `@typeparam` in Razor. The simple-name search stops at a type with a base list or `partial`. Explicit interface impls are skipped.
- **Evidence:** 10 guard mutations each failed a negative test. radzen-blazor: +1398 C# and +46 Razor facts. Newtonsoft.Json: +14. 60 of the new facts spot-checked, 0 wrong.
- **Known limit:** a derived class overload with the same arg count and a different return than a base-class overload cannot be seen, because the base class is in another file.
