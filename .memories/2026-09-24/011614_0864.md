## JS and QML: infer local types from same-file call initializers

- **WHAT:** A JS `const/let/var` with no `@type` now gets an inferred type fact from `new T()` or from a same-file callee's JSDoc `@returns {T}`. This works for bare calls, `Class.static()`, `this.m()` in a class body, and chained methods of a same-file class. `await` unwraps one `Promise<T>`. A QML function local gets its type from a same-file function's return annotation, called bare in the enclosing objects or through a same-file id. QML typed locals (`let x: T`) now record their written type.
- **WHY:** code-kb resolves receiver calls only through type_facts.
- **HOW:** JS `record_initializer_facts` is a post-pass in `javascript/type_facts.rs`, and constructor inference moved into it, so a written `@type` now wins (16 eslint rows changed from inferred to written). Guards: same-named candidates must agree, `@template`/`this` return types are skipped, and `exports.x = fn` or the inner name of a class expression are not treated as bindings. A parameter, loop, or catch binding that shadows the name is detected by `pattern_binding_encloses`, which QML shares. QML uses the new `resolve_scoped_callee`, which is the existing resolver without its loose bare-name fallback.
- **IMPACT:** eslint gained 750 inferred facts and all of them match the callee's `@returns` (0 wrong). kirigami QML gained 14 facts (all correct) and express gained 3.
