## C# and Razor: fix review findings on call-initializer type inference

- **What:** `csharp/initializer_types.rs` now indexes every non-method binding (locals, parameters, lambda, foreach, pattern, catch, query variables, fields, properties, events, primary-ctor parameters, Razor `@inject`/`@foreach`/case names) by scope: owner type plus enclosing member start byte.
- **Why:** a same-named binding hid the method, but the rule still recorded the method's return type (review finding, high).
- **How:**
  - A simple-name call records nothing when a binding with the callee name is visible in the member body or in any type layer the outward search passes.
  - A static `Type.Method()` records nothing when a binding has the receiver's name (Color Color included).
  - Calls to names inherited from `object`/`ValueType` or synthesized by records (Equals, ToString, PrintMembers, ...) record nothing.
  - Partial/base overloads in another file stay an open gap, now written in `docs/languages/csharp.md` with reason and closure.
  - Declared text keeping type parameters (`List<T>`) is documented; it matches the Rust reference, so a change needs a cross-language decision.
- **Impact:** every reviewer repro now records nothing; controls keep their facts. Corpus: only 1 correct fact lost (radzen ColumnRef.cs:30 `ToString(Column)`), no base fact lost.
