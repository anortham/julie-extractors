## C call-initializer inference: closed final review findings

- **What:** `ReturnTypeIndex::build` in `crates/julie-extractors/src/c/type_facts.rs` now marks more names as unknown, so fewer wrong inferred type facts get through.
- **Why:** Two high findings. (1) Some valid local declarations that shadow the callee, such as `gadget_fn *__attribute__((unused)) make = pick;` and `_Atomic(gadget_fn *) make = pick;`, parse as expression statements or ERROR nodes, so the local did not block the fact. (2) A file-scope prototype or definition with an object-like macro before the name (`LIBAPI struct gadget *API make(void);`, `struct gadget *restrict_ptr make(void) {}`) splits into a declaration plus a file-scope expression statement or a misread function_definition.
- **How:** These names are now unknown: every identifier or type_identifier inside an ERROR node, inside an expression_statement with errors, or inside a file-scope expression_statement; the left identifier of an assignment_expression; and the names of a function_definition that has no function declarator (its misread type is the real name).
- **Tests:** `object_like_macro_prototype_that_disagrees_records_no_fact`, `misparsed_local_shadowing_the_callee_records_no_fact`, and a positive control `unshadowed_callee_next_to_the_misparse_shapes_records_a_fact`. Updated docs/languages/c.md.
- **Trade-off:** a file-scope macro call such as `EXPORT_SYMBOL(make);` now blocks the fact for `make`. This is conservative, and docs/languages/c.md records it.
