## Erlang call-initializer type inference: second review round fixed

**What:** Fixed four review findings on feat/type-infer-erlang (erlang/type_facts.rs, types.rs docs, docs/languages/erlang.md).

- **High:** Erlang emits one symbol per variable name per function. Before, the agreement guard saw only `Var =` and `{ok, Var} =` matches. Now `walk_body` marks every variable that any other pattern binds as untracked: a match of another shape, a `cond_match_expr` lhs, a `cr_clause` pat (case/receive/try/maybe-else), a `catch_clause` class/pat/stack, a generator lhs, or a fun_clause name/args. `BodyBindings::into_bindings` clears the type of those names. There is one exception: a typed nested match inside the pattern (`S = #state{}` in a case clause, `{ok, #state{} = W} = f()`) keeps its variable. No new symbols are emitted.
- **Medium:** `?=` in `maybe` is now handled like `=`: `X ?= load()` and `{ok, X} ?= open()`. It uses the same ok-payload rule, because both `=` and `?=` bind X only when the match succeeds. So the reviewer's "drop the unmatchable-alternatives rule" would be wrong: a named-type alternative could match `{ok, Y}`.
- **Low:** `(load())` and `begin .., load() end` now pass through to the value (`result_expr`).
- **Low:** the docs now say that `list()`, `nonempty_list()` and `map()` record a base name, and that only `[t()]` and `#{..}` literal syntax record nothing.

**Corpus:** cowboy 827 -> 813 facts. 14 removed, all checked: each name is also bound by a generator, a fun head, a case pattern, or a map/tuple match. rebar3 1631 and in-repo 77 are unchanged. Symbol counts are unchanged. There are 72 new facts compared with the pre-slice baseline, and they are a subset of the 82 checked earlier.

**Note:** the rebar_state.erl:525 inferred flag on a head-pattern parameter is a parse-recovery quirk from before this work (a `?WITH_STACKTRACE` macro breaks the parse). It is not in scope.
