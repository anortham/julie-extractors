## VB.NET call-initializer inference: closed the final review findings

- **What:** I closed 4 findings in `crates/julie-extractors/src/vbnet/type_facts.rs`.
- **Namespace qualifier:** `shared_call` now records nothing when a namespace segment in the file has the qualifier name. Before, `Loader.Create()` got the wrong type when `App.Loader` was a namespace.
- **Imports alias:** `shared_call` now records nothing when an `Imports` alias has the qualifier name. VB binds an alias before a type that an import brings into scope.
- **Set accessor:** `enclosing_bound_names` adds the implicit `value` name inside a `set_accessor`, so `Value()` records nothing there.
- **Test strength:** In the shadow test, each callee now accepts the argument count of its call, so the test fails when the shadow check is removed. I confirmed this with a mutation run.
- **Docs:** `docs/languages/vbnet.md` now lists the new rules. It also names a limit: the extractor cannot see a namespace or project-level alias in another file.
- **Checks:** The vbnet language tier, the default tier (48s), the contract tier, clippy, fmt, and the strict data-quality report all passed.
