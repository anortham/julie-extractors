## Implemented Cross-Language Parity Fixes & Updated Contracts

### WHAT
Implemented all 5 cross-language parity fixes identified in the parity audit across JS, TS, and C++, declared the 5 contract markers in `EXTRACTION_CONTRACT_VERSION`, documented the contract changes in `docs/contracts/extraction-output-changes.md`, and validated all tests and quality gates.

- **`ECMA-INSTANCEOF-TYPE` (JS & TS):** Emits `instanceof` RHS as `IdentifierKind::TypeUsage` instead of `VariableRef`, excluding it from value read expressions.
- **`TS-DECORATOR-ARGS` (TS):** Retains decorator arguments in method, class, and property signatures, normalized to single-line and truncated at 100 characters with `…`, matching Python decorator behavior.
- **`CPP-UNION-1BASED` (C++):** Changed anonymous union naming from `<anonymous_union_{row}>` (0-based) to `anonymous_union_{row + 1}` (1-based, no angle brackets).
- **`JS-PROPERTY-INIT` (JS):** Excluded `SymbolKind::Method` from duplicate declaration suppression so constructor assignments (`this.x = value`) coexist with class getters and setters.
- **`TS-CTOR-PROPERTIES` (TS):** Extracted constructor-assigned properties (`this.x = value`) with visibility and preceding JSDoc comments.

### WHY
Python received these improvements in v3.6.1 and v3.6.2; analogous constructs in TypeScript, JavaScript, and C++ were missing equivalent extraction behavior, violating cross-language consistency and data quality expectations.

### HOW
- Added contract markers: `.ecmascript-instanceof-type-usage-v1`, `.typescript-decorator-signature-arguments-v1`, `.cpp-anonymous-union-naming-v1`, `.javascript-property-init-coexistence-v1`, and `.typescript-constructor-assigned-properties-v1` to `EXTRACTION_CONTRACT_VERSION`.
- Updated contract assertion in `crates/julie-extractors/src/tests/api_surface.rs`.
- Updated test assertions in `crates/julie-extractors/src/tests/typescript/symbols.rs` and `wave2_gaps.rs` to reflect decorator argument retention.
- Added reproduction and regression tests in `crates/julie-extractors/src/tests/repro_parity_gaps.rs`.
- Documented changes in `docs/contracts/extraction-output-changes.md`.
