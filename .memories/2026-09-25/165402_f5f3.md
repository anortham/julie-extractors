## Resolved Codex Review Findings: Class Field Duplicate Suppression & Qualified Instanceof Deduplication

### WHAT
Addressed both P2 findings raised during Codex CLI code review:
1. **TS & JS Constructor Properties vs Later Field Declarations:** `class_body_declares_property` now inspects `class_body` for `public_field_definition`, `property_definition`, and `field_definition` regardless of AST position, preventing duplicate property extraction when fields are declared after the constructor.
2. **Qualified `instanceof` RHS Member Access Suppression:** `is_instanceof_rhs_terminal` identifies when a `member_expression` is the terminal type target of an `instanceof` binary expression, suppressing duplicate `IdentifierKind::MemberAccess` rows so only `IdentifierKind::TypeUsage` is emitted for the target class.

### WHY
1. If a class declared `constructor() { this.x = 1 }` before `x: number`, the depth-first AST walk had not yet visited `x: number`, causing both an assigned property and a declared field to be emitted.
2. For `value instanceof ns.Validator`, `Validator` was emitted as `TypeUsage` by the `binary_expression` arm and then as `MemberAccess` by the subsequent `member_expression` arm, creating conflicting duplicate identifiers with the same ID.

### HOW
- Added `class_body_declares_property` in `typescript/symbols.rs` and `javascript/assignments.rs`.
- Added `is_instanceof_rhs_terminal` in `javascript/identifiers.rs` and applied it in both JS and TS `member_expression` identifier extractors.
- Added reproduction unit tests `repro_ts_constructor_property_does_not_duplicate_later_field_declaration` and `repro_qualified_instanceof_does_not_emit_duplicate_member_access_identifier` in `crates/julie-extractors/src/tests/repro_parity_gaps.rs`.

### IMPACT
- Fully passes `cargo test --lib` and `cargo test -p julie-extractors` (6,304 passed).
- Fully passes `node scripts/language-data-quality-report.mjs --strict` (0 silent cells, 0 debts).
