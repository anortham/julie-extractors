## Completed TODO 11: per-file extraction cost attribution

### WHAT
Implemented stable per-file row attribution in JSON reports for `julie-extract`.

- Added `ReportFileRows` and new `ReportCounts` fields: `file_rows_truncated` and `file_rows`.
- Added SQL-backed read-side attribution in `crates/julie-extract-cli/src/artifact_access.rs`.
- Wired successful scan reports to include a bounded largest-file summary and `info --json` to include the full persisted breakdown.
- Updated report/CLI contract docs and marked TODO 11 complete.

### WHY
Consumers need a stable way to see which source files dominate artifact row counts so vendor/large-file ignore policies can be based on measured impact instead of ad-hoc SQL or name-pattern guesses.

### HOW
The implementation avoids SQLite schema and writer changes. It reads existing artifact tables, groups row counts by `file_id`, attributes symbol-owned rows through `symbols`, attributes type arguments through `type_argument_usages`, and keeps artifact/revision-level domains at zero for individual files.

### IMPACT
This closes the remaining architecture-quality TODO item. Scan reports now surface top offenders, while `info --json` provides the full persisted per-file breakdown for downstream automation.
