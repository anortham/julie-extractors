## Workspace reference resolution design — doubt pass complete (rev 4)

Design doc `docs/plans/2026-07-06-workspace-reference-resolution-design.md` went through a 3-round Codex doubt pass and is ready for user review.

### What survived vs what changed
- **Survived:** tiered resolution with confidence stamps, exactly-one rule, no best-guess, per-language honesty, additive rollout, `pending_resolutions` overlay concept, tier 3 implementability.
- **Round 1 killed:** delete-pending-and-resurrect lifecycle (relationships.to_symbol_id CASCADE + delete_file_rows-at-transaction-start destroys provenance), artifact-crate policy placement, name-only invalidation.
- **Rev 2+ state model:** pending rows durable, resolution = FK-governed overlay tables (`pending_resolutions`, `identifier_resolutions`), FK-first invalidation, name-worklist only for candidate-set growth.
- **Rounds 2–3 hardening:** ResolutionHook transaction seam (non-escaping HRTB closure, before update_revision_counts in every path incl. spooled), non-fatal resolver failure + `reference_resolution_status` metadata so Miller never gates on schema version alone, atomic storage primitives for denormalized identifiers.target_symbol_id, tier 2 language-gated by fixture-tested import contracts, tier 4 same-language + kind-restricted, deleted names collected before delete_file_rows.

### Impact
Unblocks the implementation plan for julie-extract 2.9.0, then Miller pin bump → P3 dead-code → P4 trends.
