## WHAT

Replaced shell-based filesystem capacity acquisition with native cross-platform `fs4::available_space` and added a source-built Windows PR job.

- Added exact dependency `fs4 = "1.1.0"`.
- Removed Unix `df` and Windows PowerShell/Get-Volume subprocess logic.
- Added real temporary-directory and deeper nonexistent-store ancestor coverage.
- Added a Windows CI job for the capacity tests and a real local-path store import.

## WHY

The Windows PowerShell command expected `$args[0]` under `-Command`, but the appended path was not reliably bound as an argument. Store bootstrap failed with `capacity_probe_failed` for ordinary local workspaces.

## HOW

`fs4` delegates to native platform APIs, including caller-scoped `GetDiskFreeSpaceExW` semantics on Windows, while leaving ancestor selection, required-byte arithmetic, injected `CapacityProvider`, and failure classification untouched.

## IMPACT

Current-source builds no longer depend on PowerShell, Storage/CIM modules, `df` parsing, locale, or shell argument semantics for capacity checks. Pull requests will exercise the source fix on Windows before publication.
