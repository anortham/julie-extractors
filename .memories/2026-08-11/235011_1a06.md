## Fixed Windows CURRENT publication

### WHAT

Closed the `CURRENT.partial` file handle after `sync_all()` and before atomic rename in both initial `StoreLayout::create` and generation promotion.

### WHY

Linux permits renaming an open file, but Windows rejects it with `Access is denied (os error 5)`. This prevented every new family-store import from publishing `CURRENT` on Windows.

### HOW

Added an explicit `drop(current)` at both duplicated publication sites. The existing Windows public store-import CI probe is the cross-platform RED regression; local connection, generation, public-import, format, diff, and strict Clippy gates are green.

### IMPACT

New store creation and later generation rotation now preserve the intended sync-then-atomic-rename protocol on Windows. This unblocks the v2.32.0 release once Windows CI confirms the fix.
