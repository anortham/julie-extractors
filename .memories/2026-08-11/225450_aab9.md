## Fixed current gated-Partial family-store bootstrap

### WHAT

Updated the from-artifact producer boundary so current Complete or Partial legacy resolution may seed an exact family store, while stale or incomplete artifacts still fail before store creation.

### WHY

Legacy `partial` is overloaded. A successful full resolution pass reports Partial whenever any language is tier-2 gated, even though the revision is current, every identifier has an outcome, and the pending-resolution subset is exactly what a fresh store full resolve produces. The preflight rejected that safe state categorically, so missing-store RootRebind could never converge.

### HOW

- Requires resolver version compatibility, positive last-full, `last_full_revision == MAX(extraction_revisions.revision_id)`, and one resolution outcome per identifier for both Complete and Partial.
- Keeps existing canonical root, artifact hash, extraction/capability epoch, target visibility, and base materializer integrity checks.
- Continues rejecting Failed/Absent metadata, zero revisions, stale Complete/Partial, and missing identifier outcomes.
- A real Rust tier-gated Partial fixture proves unresolved pending rows exist and the imported exact store's normalized identifier/pending rows equal a separate fresh store full resolve.
- A Miller Scale regression exercises the real replaced-root path and opens the recovered exact store.

### IMPACT

Fresh-store recovery now accepts semantically current gated resolution and restores Miller readability without weakening stale/incomplete input rejection or changing Miller production code.
