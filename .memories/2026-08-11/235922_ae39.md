## Made store durability syncs Windows-correct

### WHAT

- `sync_file` now opens owned files with write access before `sync_all`.
- Resolution base/file syncs reuse the corrected store durability helpers.
- CLI export uses a writable handle for the partial artifact file.
- Directory fsync remains active on Unix and is skipped on Windows for resolution-base publication, from-artifact publication, and export publication.

### WHY

Windows requires write access for `FlushFileBuffers` and does not support the Unix pattern of opening a directory as a regular file. The previous durability code returned `Access is denied (os error 5)` before a new store could finish initialization.

### HOW

Applied the platform-specific contract consistently across every store file/directory sync found in the artifact and CLI paths, while preserving Unix directory durability behavior.

### IMPACT

Initial imports, resolution base publication, from-artifact imports, and exports no longer use unsupported Windows sync handles. This should clear the remaining Windows release gate without weakening durability on Unix.
